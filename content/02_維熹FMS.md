# 維熹FMS｜欄位帶值與查詢報表

整理日期：2026-10-13。

## 1. 專案定位

本專案有兩類內容：在 SAP 表單欄位執行的 FMS，以及較大型的採購、庫存、庫齡 SQL 報表。它們的執行位置、輸入方式與驗收方法不同，不能把 SSMS 可執行的查詢直接當成已通過 FMS 測試。

## 2. 共用取值原則

- 要讀取尚未儲存的畫面輸入，使用實際表單可解析的 FMS 欄位語法；只查 OITM 等資料表可能找不到新品項。
- FMS 以 SELECT 回傳目標值，不寫成 `OITM.U_ItemSpec = ...` 的賦值式。
- 表頭、明細 Matrix、側邊 UDF 面板的取值位置不同；UID 必須在實際表單確認。
- 找不到值時，先單獨回傳來源值，再加入 WHERE、型別轉換、計算，不一次猜全部原因。
- NULL、空字串與數字 0 要分清楚；不得把所有轉換失敗都當成真正的零。

## 3. 品項主檔組合欄位

| 目標欄位 | 來源／組合 | 狀態 |
|---|---|---|
| OITM.ItemName | U_Seg1Desc 等描述欄位組合 | 歷史問題是新品項未存檔，FROM OITM 查不到；改由畫面取值 |
| OITM.U_ItemSpec | 線種、線規、芯數、耐溫、顏色、長度；長度有值才加 MM | 已提供群組 101 版本，但使用者回報找不到值，仍待釐清 |
| OITM.U_ProductForm | U_HeadType＋空格＋U_TailType | 最後需求明確要空格；保留群組 101 條件，尚無成功回覆 |

U_ItemSpec 的來源欄位：U_WireType、U_WireSpec、U_CoreCount、U_TempRating、U_Color、U_Length。使用文字 CAST 避免數字相加或轉型問題；LTRIM/RTRIM 只清除頭尾空白，不會消除缺欄造成的中間連續空格。

### U_ItemSpec「找不到值」排查紀錄

最後提供的測試方式是先回傳目前畫面的 ItmsGrpCod 與 U_WireType，確認是否真的為群組 101。若群組不符，WHERE 會使查詢沒有資料；若來源值也讀不到，再查 FMS 綁定及取值方式。尚未取得使用者的測試結果。

### 保留的 U_ProductForm 範例（待表單驗證）

```sql
SELECT LTRIM(RTRIM(
    ISNULL(CAST($[OITM.U_HeadType] AS NVARCHAR(254)), N'')
    + N' ' +
    ISNULL(CAST($[OITM.U_TailType] AS NVARCHAR(254)), N'')
))
WHERE $[OITM.ItmsGrpCod] = 101
```

空字串 `''` 不會加入空格；`N' '` 才是一個空格。來源：聊天「檢查 OITM.U_ItemSpec FMS」。

OIGE 歷史錯誤涉及取值符號未被替換；同時已更正來源欄位為 U_ChangeType。不能把前面的 $[$30.0.0] 版本當成成功方案。

## 5. 數字、日期與多 SELECT

### 數字格式

- 越南格式 `1.234,56` 的小數及千分位與 `1,234.56` 相反；轉換前應先確認來源，不可通用替換。
- 查詢需要後續加總時，保留 DECIMAL 數值。歷史 FORMAT(...,'N2','en-US') 會得到顯示文字，不適合直接視為數值欄位。
- SQL 的 ROUND／CAST 與 Excel 顯示小數位數不同：資料是 180，也可以顯示 180.00；匯出後仍需設定欄位格式。
- 日期轉年月採 yyyyMM，避免將日期與月份文字直接比較。

### 多段 SELECT

歷史討論使用 UNION ALL 合併欄位數與型別相容的查詢。前提是各分支的條件及回傳筆數符合需求；若多個分支都命中，仍會有多筆，不會自動變成唯一帶入值。

## 6. 採購與庫存報表

### 未結採購單

固定只查 `CANCELED='N'`、`DocStatus='O'`。討論中的 `_CmSp_OPOR_Search` 接收 CardCode 與 ItemCode，空白參數轉 NULL。內容包含採購量、已交量、已退量、實收量、未交量、單價及未交金額。

來源單據與明細關聯需避免一對多 JOIN 導致數量重複；數量與幣別／單位一致性仍需用實際採購單核對。歷史格式建議為數量兩位、單價四位、金額兩位小數，但不代表各公司的精度需求已定案。

### 區間庫存／銷售

曾討論按料號與倉庫列示區間存貨，以及以 OINV／INV1 統計銷售量。銷量全部為 0 時，要先區分「真的為零」和 LEFT JOIN 沒找到資料後被 ISNULL 轉成 0。核對日期參數、發票日期，以及實際只有交貨尚未開票的情境。

### 七日內到期批次

歷史公式是許可日期 InDate 加上期限月數：DATEADD(MONTH, TRY_CAST(Name AS INT), InDate)。七日邊界、已過期批次、空期限和月份加總的日期效果都要列入測試。

## 7. 分倉 FIFO 庫齡與最近售價

此處有兩個重要版本，不能混用限制。

| 項目 | 分倉庫齡與最近售價_草稿.sql | usp_InventoryLCM.sql |
|---|---|---|
| 形式 | 單一查詢、遞迴 CTE＋JSON | 預存程序、暫存表，檔案註明無 JSON |
| 庫存口徑 | 目前 OITW.OnHand | 截止日以前 OINM 入量－出量 |
| 成本口徑 | 目前 OITM.AvgPrice | 仍為目前 OITM.AvgPrice |
| 日期使用 | 不能只改日期就當作歷史庫存 | 支援截止日數量／事件／售價，但不等於歷史成本重建 |
| 環境條件 | 說明檔列 SQL Server 2017+、相容性至少 130 | 檔頭列 SQL Server 2016 SP1+ |
| 驗證 | 對應 JS 狀態機合成測試通過；SQL 執行受 SSPI 阻擋 | 檔頭明確註記尚未在 SAP 公司資料庫執行驗證 |

共同邏輯是分倉追蹤 FIFO 入庫層，調撥保留原入庫日期；庫齡不應因移倉重新歸零。草稿說明的測試涵蓋往返調撥、老貨先出、來源不足、小數數量與 180／181 天界線。

### 口徑限制

- 歷史入出庫事件只納入指定單據範圍；退貨、貸項、直接發票與其他異動可能未完整包含。
- 取消狀態使用目前資料，需確認截止日後取消的影響。
- 草稿中的最近售價為同倉最近未取消 AR 發票原幣、銷售單位、列折扣後未稅價；尚未統一本幣與庫存單位，也未分攤表頭折扣。
- 庫存差異為 0 不代表事件完整，可能有相互抵銷的漏列。
- 181 天以上金額為依指定公式推算的提列，不是已過帳損失。
- 查無價格、來源不足或庫存無法核對時，應保留不能計算的狀態，不能假裝成 0。
- 全品項、大歷史量與同日交易排序的效能／正確性尚待驗證。

## 8. 待辦與驗收

- [ ] U_ItemSpec：先測來源及群組，再測組合、MM、欄位長度及空欄位。
- [ ] U_ProductForm：確認中間空格、只有頭型、只有尾型、兩欄皆空。
- [ ] OIGE：確認實際儲存的查詢與會計科目欄位綁定。
- [ ] 整理每支 FMS 的表單、目標欄位、查詢名稱與刷新觸發條件。
- [ ] 驗證日期／數值格式，記錄 SQL Server 與 SAP 版本，避免混入 HANA 範例。
- [ ] 用同一料號和倉庫核對庫存日誌、FIFO 層、最近售價與成本。
- [ ] 確認淨變現係數 1.00／0.80 的使用口徑，以及歷史日成本限制。
- [ ] 在單料號正確且效能可接受後，再評估全品項報表。
