## My request:
我想請問一下 
銷售人員跟所有人 

當我銷售人員一開始選 A 下面會帶出 A員工
但我修改選B 下面還是A員工 為甚麼

[原對話含圖片，本文未嵌入圖片]

**歷史回答**

從畫面看起來是 **SAP Business One**。你描述的情況，可能是「所有人」只在一開始帶入，修改「銷售人員」時，沒有再重新帶入。

這兩個欄位代表不同資料：

- **銷售人員**：這張單據負責銷售的業務。
- **所有人**：這張單據的擁有人，是獨立儲存的欄位。[SAP 欄位說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/SAPbobsCOM~Documents~DocumentsOwner.html)

所以，**一開始選 A 能帶出 A 員工，不代表之後改成 B 就一定會同步更新**。目前要確認兩個地方：

1. **B 的員工關聯是否有設定**：到「員工主檔」查看 B 員工是否關聯到銷售人員 B。
2. **所有人欄位如何帶入**：是系統預設，還是另外設定的格式化搜尋／附加程式；若是客製帶入，可能只設定首次填入，沒有設定變更時更新。

你可以先測試：**開一張全新單據，第一次就選 B，下面會帶出 B 員工嗎？**  
如果可以，就比較像是後續變更沒有觸發更新；如果不行，就先查 B 的員工關聯設定。

### 4. 原本就有

來源：[S227-Q003](<../../原始問答/S227_釐清銷售人員初始選項.md#q3>)；2026-10-06

**問題**

原本就有

**歷史回答**

了解，那先以 **SAP B1 原本的帶入機制**來看。

依你測試的結果，「所有人」比較像是**首次帶入的預設值**：選 A 時填入 A 員工；之後改選 B，已經填好的所有人仍保留 A，不會跟著重新指定。

這兩個欄位可以不同：**負責銷售的業務換成 B，不一定代表單據所有人也要換成 B。** 如果這張單據的歸屬也要交給 B，就需要一併修改「所有人」。

但我前面把原因說得太確定了：目前能確認的是你系統的實際行為；是否為你使用版本的標準規則，還需要核對版本，不能只憑畫面斷定。

> “The owner of a document is assigned when the document is created”

### 9. 我要刪OSLP的時候 無法移除正在使用的銷售人員

我要刪OSLP的時候

**歷史回答**

你指的是 **SAP Business One 的 OSLP（銷售人員資料表）**嗎？

「無法移除正在使用的銷售人員」通常表示：**這名銷售人員仍被資料引用，不是指他目前正在登入。** 可以先檢查業務夥伴的預設銷售人員，以及相關單據、銷售機會。

- **只是離職或不再使用**：優先在銷售人員設定中取消「有效／Active」。OSLP 有此狀態欄位。[SAP 官方欄位說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OSLP.html)

- 不要直接用 `DELETE FROM OSLP` 強制刪除，以免造成關聯資料不一致。

你用的是 **SQL Server 還是 HANA**？要刪除的 **SlpCode** 是多少？我可以依你的環境提供查詢引用來源的唯讀 SQL。

### 11. 都沒有 SlpCode = 4 先小規模測試

來源：[S231-Q003](<../../原始問答/S231_修正 OSLP 刪除銷售人員問題.md#q3>)；2026-10-07

**問題**

都沒有 SlpCode = 4 先小規模測試

**歷史回答**

可以，先針對 **`SlpCode = 4` 做小範圍唯讀測試**。請在發生問題的公司資料庫執行。

先確認人員資料；`EmpID` 是 OSLP 的員工關聯欄位。[SAP 欄位說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OSLP.html)

```sql
SELECT "SlpCode", "SlpName", "Active", "EmpID"
FROM "OSLP"
WHERE "SlpCode" = 4;
```

再查業務夥伴、草稿（含明細）與銷售機會：

```sql
SELECT 'OCRD' AS "SourceTable", COUNT(*) AS "RefCount"
FROM "OCRD" WHERE "SlpCode" = 4

UNION ALL

SELECT 'ODRF', COUNT(*)
FROM "ODRF" WHERE "SlpCode" = 4

UNION ALL

SELECT 'DRF1', COUNT(*)
FROM "DRF1" WHERE "SlpCode" = 4

UNION ALL

SELECT 'OOPR', COUNT(*)
FROM "OOPR" WHERE "SlpCode" = 4;
```

把這兩段的結果貼給我。**若全部是 0，只能排除這四個來源**，下一步再縮小檢查其他關聯。

### 18. SAPB1 寫查詢 的查詢產生工具 OUSR 我查了之後，會跑出已經刪除的，我該怎麼避免

來源：[S258-Q001](<../../原始問答/S258_避免查詢顯示已刪除的 OUSR 使用者.md#q1>)；2026-10-19

**問題**

SAPB1 寫查詢 的查詢產生工具  OUSR 我查了之後，會跑出已經刪除的，我該怎麼避免

**歷史回答**

可以，在查詢條件加上 **`GROUPS <> 99`**，就能排除已刪除的使用者。SAP B1 的 `OUSR` 會保留這些資料，並以 `GROUPS = 99` 標記已刪除。[SAP 官方欄位說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/ousr.html)

**如果你使用 SQL Server：**

```sql
SELECT T0.[USER_CODE], T0.[U_NAME]
FROM OUSR T0
WHERE T0.[GROUPS] <> 99
```

在「查詢產生器」的 **Where 欄位**，填入以下條件即可，不用再寫 `WHERE`：

```sql
T0.[GROUPS] <> 99
```

**如果你使用 SAP HANA：**

```sql
SELECT T0."USER_CODE", T0."U_NAME"
FROM "OUSR" T0
WHERE T0."GROUPS" <> 99
```

如果原本已有查詢條件，就在後面加 `AND T0.[GROUPS] <> 99`（HANA 改用雙引號）。
