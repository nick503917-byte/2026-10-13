### 2. 2026/07/16 [Form=501 Item=3 Pane=0 Column=42 Row=90 Variable=62]

來源：[S048-Q002](<../../原始問答/S048_查看底部資訊.md#q2>)；2026-08-05

**問題**

2026/07/16 [Form=501 Item=3 Pane=0 Column=42 Row=90 Variable=62]

**歷史回答**

這是 SAP Business One 開啟「系統資訊」後顯示的欄位識別資料，不是會計交易內容。

- `2026/07/16`：游標目前指向欄位的值
- `Form=501`：目前視窗的表單 ID
- `Item=3`：畫面元件 ID
- `Pane=0`：頁籤／窗格編號
- `Column=42`：表格欄位 ID
- `Row=90`：目前指向第 90 列
- `Variable=62`：SAP 內部變數／資料欄位識別碼

這些資訊通常用於設定「格式化搜尋」、撰寫 SDK 外掛或排查畫面欄位問題。

### 3. 我是可以拉得出來嗎

來源：[S048-Q003](<../../原始問答/S048_查看底部資訊.md#q3>)；2026-08-05

**問題**

我是可以拉得出來嗎

**歷史回答**

可以拉出來，但要看你想拉哪一部分：

- 要拉 `2026/07/16`：可以用 SAP Business One UI API，從目前畫面的 `Item=3`、`Column=42`、`Row=90` 讀取儲存格。
- 要用 SQL 拉交易日期：也可以，但這串系統資訊沒有顯示資料表與欄位名稱，需先確認該畫面的資料來源。
- `[Form=501 ...]`：屬於 SAP 畫面內部資訊，通常用於 SDK/UI API 定位，不是資料庫中的交易資料。

C# UI API 概念如下：

```csharp
SAPbouiCOM.Form form =
    SBO_Application.Forms.ActiveForm;

SAPbouiCOM.Matrix matrix =
    (SAPbouiCOM.Matrix)form.Items.Item("3").Specific;

SAPbouiCOM.EditText cell =
    (SAPbouiCOM.EditText)matrix.Columns.Item("42")
        .Cells.Item(90).Specific;

string value = cell.Value; // 2026/07/16
```

不過 `Row=90` 只是當下游標所在列，資料排序或篩選後會改變，所以正式開發時應依文件號或交易號找列，不能固定寫死第 90 列。

### 4. 所以 如果我要客製報表 可以從裡面抓嗎

來源：[S048-Q004](<../../原始問答/S048_查看底部資訊.md#q4>)；2026-08-05

**問題**

所以 如果我要客製報表 可以從裡面抓嗎

**歷史回答**

可以，但這串資訊只能協助「定位畫面欄位」，不能直接作為客製報表的資料來源。

客製報表通常有兩種做法：

- 建議做法：從 SAP Business One 資料庫抓取  
  依文件號、交易號或客戶代碼，關聯 `OJDT/JDT1`、`OINV/INV1`、`ORCT/RCT2` 等資料表。適合 Crystal Reports、查詢報表與大量資料匯出，結果較穩定。

- 特殊情況：用 UI API 從畫面 Matrix 抓取  
  可透過 `Form=501、Item=3、Column=42` 讀取目前畫面載入的資料，但會受到排序、篩選、分頁、版本與語系影響，不適合作為正式報表的主要來源。

`Row=90` 不能寫死，因為它只是目前畫面的第 90 列；`Variable=62` 也不等於資料庫欄位。

因此答案是：畫面上的日期可以抓，但若要做可靠的客製報表，應先用文件號或交易號反查資料庫來源，再直接用 SQL 建報表。這張畫面看起來可先從總帳分錄的 `OJDT`（表頭）及 `JDT1`（明細）開始確認。

### 5. OJDT/JDT1、OINV/INV1、ORCT/RCT2 這三張有關連嗎

來源：[S048-Q005](<../../原始問答/S048_查看底部資訊.md#q5>)；2026-08-05

**問題**

OJDT/JDT1、OINV/INV1、ORCT/RCT2 這三張有關連嗎

**歷史回答**

有關聯，而且可以串起來，但不是「三組表直接互相 Join」。正確關係如下：

```text
OINV（應收發票表頭）
 ├─ DocEntry → INV1.DocEntry（發票明細）
 ├─ TransId  → OJDT.TransId（發票產生的會計分錄）
 └─ DocEntry → RCT2.DocEntry（付款沖銷的發票）

ORCT（收款表頭）
 ├─ DocEntry → RCT2.DocNum（付款沖銷明細）
 └─ TransId  → OJDT.TransId（收款產生的會計分錄）

OJDT（會計分錄表頭）
 └─ TransId  → JDT1.TransId（會計分錄明細）
```

各組表本身的關係：

| 表頭 | 明細 | Join 條件 |
|---|---|---|
| `OJDT` | `JDT1` | `OJDT.TransId = JDT1.TransId` |
| `OINV` | `INV1` | `OINV.DocEntry = INV1.DocEntry` |
| `ORCT` | `RCT2` | `ORCT.DocEntry = RCT2.DocNum` |

其中 `OINV` 是 A/R Invoice；其物件類型 `ObjType = 13`。[SAP OINV 資料表說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/oinv.html)

若要查「發票被哪張收款沖銷」，可使用：

```sql
SELECT
    I.DocEntry                    AS InvoiceEntry,
    I.DocNum                      AS InvoiceNo,
    I.CardCode,
    I.CardName,
    I.DocDate                     AS InvoiceDate,
    I.DocTotal,
    P.DocEntry                    AS PaymentEntry,
    P.DocNum                      AS PaymentNo,
    P.DocDate                     AS PaymentDate,
    A.SumApplied
FROM OINV I
LEFT JOIN RCT2 A
    ON A.DocEntry = I.DocEntry
   AND A.InvType = 13
LEFT JOIN ORCT P
    ON P.DocEntry = A.DocNum
ORDER BY I.DocNum, P.DocNum;
```

`A.InvType = 13` 非常重要，因為 `RCT2.DocEntry` 可能指向不同類型的單據；只用 `DocEntry` Join，可能把相同內碼的其他單據錯接進來。

如果還要加入發票品項：

```sql
LEFT JOIN INV1 L
    ON L.DocEntry = I.DocEntry
```

如果要加入發票的會計分錄：

```sql
LEFT JOIN OJDT J
    ON J.TransId = I.TransId
LEFT JOIN JDT1 JL
    ON JL.TransId = J.TransId
```

收款會有自己獨立的一張會計分錄，所以收款分錄應另外串：

```sql
LEFT JOIN OJDT PJ
    ON PJ.TransId = P.TransId
LEFT JOIN JDT1 PJL
    ON PJL.TransId = PJ.TransId
```

要注意：加入 `INV1` 和 `JDT1` 後，同一張發票會展開成多列，金額可能被重複加總。做客製報表時，通常要把「發票明細」「收款沖銷」「會計分錄」分別彙總後再 Join。另外，預收款、未指定發票的收款及內部調節，可能還需要查 `OITR/ITR1`，僅靠 `RCT2` 不一定能涵蓋。`OJDT.TransId` 是會計交易編號，而 `TransType=13` 代表 A/R Invoice。[SAP OJDT 資料表說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKhelp/OJDT.html)

### 6. 如果有內部調解的 可以查得到嗎

來源：[S048-Q006](<../../原始問答/S048_查看底部資訊.md#q6>)；2026-08-05

**問題**

如果有內部調解的 可以查得到嗎

**歷史回答**

可以。SAP Business One 的內部調節資料主要在：

- `OITR`：內部調節表頭
- `ITR1`：內部調節的交易列

關聯方式：

```text
OITR.ReconNum = ITR1.ReconNum

ITR1.TransId    = JDT1.TransId
ITR1.TransRowId = JDT1.Line_ID
```

`ITR1` 也保留來源單據：

- `SrcObjTyp = 13`：A/R Invoice（`OINV`）
- `SrcObjTyp = 24`：Incoming Payment（`ORCT`）
- `SrcObjTyp = 14`：A/R Credit Memo（`ORIN`）
- `SrcObjTyp = 30`：Journal Entry（`OJDT`）

SAP 官方資料表說明也列出 `ITR1.TransId`、`TransRowId`、`SrcObjTyp`、`SrcObjAbs` 等關聯欄位。[ITR1 資料表說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKhelp/ITR1.html)

例如，查某張發票的所有有效內部調節：

```sql
SELECT
    I.DocEntry,
    I.DocNum,
    I.CardCode,
    I.CardName,
    R.ReconNum,
    H.ReconDate,
    H.ReconType,
    R.TransId,
    R.TransRowId,
    R.ReconSum,
    R.ReconSumFC,
    R.ReconSumSC
FROM OINV I
INNER JOIN ITR1 R
    ON R.SrcObjTyp = '13'
   AND R.SrcObjAbs = I.DocEntry
INNER JOIN OITR H
    ON H.ReconNum = R.ReconNum
WHERE H.Canceled = 'N'
  AND H.ReconType <> '7'
ORDER BY I.DocNum, H.ReconDate;
```

`OITR.ReconType` 可用來判斷調節來源，例如：

- `0`：手動
- `1`：自動
- `2`：半自動
- `3`：付款
- `4`：貸項通知單
- `7`：取消調節

完整定義可參考 [SAP OITR 資料表說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OITR.html)。

若要查「發票被哪一張收款調節」，可以把同一個 `ReconNum` 下的收款列找出來：

```sql
SELECT
    I.DocNum        AS InvoiceNo,
    I.DocDate       AS InvoiceDate,
    I.DocTotal      AS InvoiceTotal,
    H.ReconNum,
    H.ReconDate,
    IR.ReconSum     AS InvoiceReconAmount,

    P.DocNum        AS PaymentNo,
    P.DocDate       AS PaymentDate,
    P.DocTotal      AS PaymentTotal,
    PR.ReconSum     AS PaymentReconAmount

FROM OINV I

INNER JOIN ITR1 IR
    ON IR.SrcObjTyp = '13'
   AND IR.SrcObjAbs = I.DocEntry

INNER JOIN OITR H
    ON H.ReconNum = IR.ReconNum
   AND H.Canceled = 'N'
   AND H.ReconType <> '7'

INNER JOIN ITR1 PR
    ON PR.ReconNum = IR.ReconNum
   AND PR.SrcObjTyp = '24'

INNER JOIN ORCT P
    ON P.DocEntry = PR.SrcObjAbs

ORDER BY I.DocNum, H.ReconDate, P.DocNum;
```

這種查法可以涵蓋：

- 收款時直接指定發票
- Payment on Account 之後再手動調節
- 部分付款、分次調節
- 一筆收款調節多張發票
- 多筆收款調節一張發票

因此，正式客製報表建議以 `OITR/ITR1` 為調節主體；`RCT2` 可以輔助查看付款建立時套用的單據，但只查 `RCT2` 可能漏掉後續手動內部調節。SAP 也說明，未指定發票的 Payment on Account 通常需要稍後手動調節。[SAP 內部調節說明](https://help.sap.com/docs/r/68a2e87fb29941b5bf959a184d9c6727/9.3/en-US/44f3e89dc4b80486e10000000a155369.html)

### 7. 如果我要寫一隻 查詢報表 跟 OCRD的 BALANCE的這個欄位很像。 我想知道這個業務夥伴的剩下餘額 以及明細

來源：[S050-Q001](<../../原始問答/S050_查詢業務夥伴剩餘餘額.md#q1>)；2026-08-05

**問題**

如果我要寫一隻 查詢報表

跟 OCRD的 BALANCE的這個欄位很像。

我想知道這個業務夥伴的剩下餘額 以及明細

**歷史回答**

在 SAP Business One 裡，`OCRD.Balance` 是業務夥伴「目前的總帳餘額」。如果要查看這個餘額由哪些未結清交易組成，建議從 `JDT1` 的未清餘額欄位查詢，而不是直接加總發票金額。

以下是 SQL Server 版，可直接放進 SAP B1 Query Manager。

### 業務夥伴餘額與未清明細

```sql
/* [%0] = 業務夥伴代碼 */

SELECT
    BP.CardCode                         AS N'業務夥伴代碼',
    BP.CardName                         AS N'業務夥伴名稱',
    BP.Balance                          AS N'OCRD目前餘額',

    T.TransId                           AS N'分錄號碼',
    T.Line_ID                           AS N'分錄列號',
    H.RefDate                           AS N'過帳日期',
    H.DueDate                           AS N'到期日',
    H.TaxDate                           AS N'文件日期',

    CASE H.TransType
        WHEN 13  THEN N'應收發票'
        WHEN 14  THEN N'應收貸項'
        WHEN 18  THEN N'應付發票'
        WHEN 19  THEN N'應付貸項'
        WHEN 24  THEN N'收款'
        WHEN 46  THEN N'付款'
        WHEN 30  THEN N'手動分錄'
        WHEN 203 THEN N'應收預付款'
        WHEN 204 THEN N'應付預付款'
        ELSE N'其他交易'
    END                                 AS N'交易類型',

    H.BaseRef                           AS N'來源文件號',
    H.Memo                              AS N'摘要',
    T.Ref1                              AS N'參考一',
    T.Ref2                              AS N'參考二',

    T.Debit                             AS N'借方金額',
    T.Credit                            AS N'貸方金額',
    T.BalDueDeb                         AS N'未清借方',
    T.BalDueCred                        AS N'未清貸方',

    T.BalDueDeb - T.BalDueCred          AS N'剩餘餘額',

    CASE
        WHEN H.DueDate < CAST(GETDATE() AS DATE)
        THEN DATEDIFF(DAY, H.DueDate, CAST(GETDATE() AS DATE))
        ELSE 0
    END                                 AS N'逾期天數'

FROM OCRD BP
INNER JOIN JDT1 T
    ON T.ShortName = BP.CardCode
INNER JOIN OJDT H
    ON H.TransId = T.TransId

WHERE BP.CardCode = '[%0]'
  AND ABS(T.BalDueDeb - T.BalDueCred) > 0.001

ORDER BY
    H.DueDate,
    H.RefDate,
    T.TransId;
```

### 查詢全部業務夥伴的餘額摘要

```sql
SELECT
    BP.CardCode                             AS N'業務夥伴代碼',
    BP.CardName                             AS N'業務夥伴名稱',
    CASE BP.CardType
        WHEN 'C' THEN N'客戶'
        WHEN 'S' THEN N'供應商'
        WHEN 'L' THEN N'潛在客戶'
    END                                     AS N'類型',
    BP.Currency                             AS N'幣別',
    BP.Balance                              AS N'OCRD餘額',
    SUM(
        ISNULL(T.BalDueDeb, 0)
        - ISNULL(T.BalDueCred, 0)
    )                                       AS N'未清明細合計'

FROM OCRD BP
LEFT JOIN JDT1 T
    ON T.ShortName = BP.CardCode
   AND ABS(T.BalDueDeb - T.BalDueCred) > 0.001

WHERE BP.CardType IN ('C', 'S')

GROUP BY
    BP.CardCode,
    BP.CardName,
    BP.CardType,
    BP.Currency,
    BP.Balance

HAVING
       ABS(BP.Balance) > 0.001
    OR ABS(SUM(
        ISNULL(T.BalDueDeb, 0)
        - ISNULL(T.BalDueCred, 0)
    )) > 0.001

ORDER BY BP.CardCode;
```

重要觀念：

- `OCRD.Balance`：業務夥伴目前的本幣總帳餘額。
- `JDT1.BalDueDeb - JDT1.BalDueCred`：每一筆分錄目前尚未沖銷的餘額。
- 正數通常代表應收／借方餘額；負數通常代表預收、貸項或應付／貸方餘額。
- 明細應包含發票、貸項、收付款及手動分錄，才有機會與 `OCRD.Balance` 對上。

### 20. 1). [Microsoft][ODBC Driver 18 for SQL Server][SQL Server]'AJDT' is not a recognized join …

**問題**

1). [Microsoft][ODBC Driver 18 for SQL Server][SQL Server]'AJDT' is not a recognized join option. 2). [Microsoft][ODBC Driver 18 for SQL Server][SQL Server]Statement '使用者定義的值' (CSHS) (s) could not be prepared.

第 2 条通常只是第 1 条导致的连带错误：SQL Server 无法解析 JOIN，因此整条语句无法 prepare。

核心错误是：

> `'AJDT' is not a recognized join option`

SQL Server 在预期 `JOIN` 类型或选项的位置读到了 `AJDT`。请检查 SQL 中 `AJDT` 附近，常见错误例如：

```sql
-- 错误
LEFT OUTER AJDT JOIN SomeTable ...
LEFT AJDT JOIN SomeTable ...
INNER AJDT JOIN SomeTable ...
```

如果 `AJDT` 是表别名，应写成：

```sql
LEFT OUTER JOIN SomeTable AS AJDT
    ON ...
```

如果 `AJDT` 是表名，应写成：

```sql
LEFT OUTER JOIN AJDT
    ON ...
```

也请检查动态拼接 SQL 是否漏了空格或关键字，例如：

```sql
... LEFT OUTER JOIN AJDT AS A ON ...
```

而不是：

```sql
... LEFT OUTER AJDT JOIN ...
```

`Statement(s) could not be prepared` 不需要单独处理；修正 JOIN 语法后通常会一起消失。若贴出包含 `AJDT` 前后约 10 行的完整 SQL，我可以直接指出需要修改的位置。

**歷史回答**

會計效果上可以理解成「借貸相反」，但在 SAP B1 標準取消收款時，系統通常採用：

- 原借方 → 借方負數
- 原貸方 → 貸方負數

而不是：

- 原借方 → 改列貸方正數
- 原貸方 → 改列借方正數

兩種方式的淨會計效果相同，例如：

| 方式 | 現金科目 | 客戶科目 |
|---|---:|---:|
| SAP 取消分錄 | 借方 -324 | 貸方 -324 |
| 借貸相反表示 | 貸方 324 | 借方 324 |

不建議為了顯示成正數而手動修改或另做反向分錄，否則可能無法正確解除收款、發票及內部調節的關聯。應直接使用原收款單的「取消」功能，讓 SAP 自動產生負數反向分錄。

### 28. 那如果我要看已取消的分錄跟被取消的收款可以嗎

來源：[S056-Q004](<../../原始問答/S056_確認SAP B1取消收款關聯.md#q4>)；2026-08-07

**問題**

那如果我要看已取消的分錄跟被取消的收款可以嗎

**歷史回答**

可以，兩者都能查到。

### 1. 查看被取消的收款單

進入：

`銀行業務 → 收款 → 收款`

用「尋找」模式輸入收款單號。原收款單仍會保留，畫面通常會顯示「已取消」或備註 `Cancelled`。

### 2. 查看原始分錄

在被取消的收款單上，點橘色箭頭進入「交易日記帳分錄」。這是建立收款時產生的原始分錄。

### 3. 查看取消分錄

進入：

`財務 → 日記帳分錄`

用以下條件尋找：

- 收款單號
- 交易日期
- 客戶代碼
- 分錄備註

取消分錄的備註通常會寫明這是某張收款單的反向交易。其金額會像截圖一樣，以借方負數、貸方負數呈現。

例如：

| 分錄 | 現金 | 客戶 |
|---|---:|---:|
| 原收款分錄 | 借方 324 | 貸方 324 |
| 取消分錄 | 借方 -324 | 貸方 -324 |
| 合計 | 0 | 0 |

需要注意的是，「關係地圖」未必會把兩筆分錄完整串在一起；最可靠的是從收款單的交易編號、日記帳備註及來源文件號交叉確認。原收款單與取消分錄都不會消失。

### 32. 對

來源：[S166-Q003](<../../原始問答/S166_確認內部調解外幣調整.md#q3>)；2026-09-11

**問題**

對

**歷史回答**

**可以，SAP Business One 的內部調節可以處理這種本幣匯差。** 外幣交易互相調節時，如果本幣金額因匯率不同而有差額，系統會自動產生「匯率差異」分錄，認列兌換損益。[SAP 官方說明](https://learning.sap.com/courses/handling-accounting-in-sap-business-one/managing-internal-reconciliation-1)

例如，本幣是台幣：

| 項目 | 外幣金額 | 本幣金額 |
|---|---:|---:|
| 應收發票，匯率 32 | USD 100 | NT$3,200 |
| 收款，匯率 33 | USD 100 | NT$3,300 |

這兩筆外幣金額相同，調節時的 **NT$100 差額會作為兌換利益處理**，不用修改原本的 USD 100。

操作時要確認選取的是對應的未調節交易，以及調節幣別、金額與日期；SAP 會使用調節日期產生匯差。[內部調節視窗說明](https://help.sap.com/docs/PRODUCT_ID/68a2e87fb29941b5bf959a184d9c6727/d8de97bc1c8742d69f0188c87354352a.html?locale=en-US&state=PRODUCTION&version=9.3)

你目前是調節**客戶／供應商帳款**，還是**外幣總帳科目**？

### 33. 收款

來源：[S166-Q004](<../../原始問答/S166_確認內部調解外幣調整.md#q4>)；2026-09-11

**問題**

收款

**歷史回答**

那就是**收款與應收發票做內部調節**。

如果收款尚未沖銷發票，而且兩筆的外幣金額相同、只有本幣因匯率不同出現差額，完成內部調節時，SAP B1 會自動產生匯差分錄，認列兌換損益。[SAP 官方說明](https://learning.sap.com/courses/handling-accounting-in-sap-business-one/managing-internal-reconciliation-1)

你可以在客戶的內部調節畫面：

1. 選取對應的應收發票與收款。
2. 確認外幣調節金額互相抵銷。
3. 確認調節日期，執行調節，再檢查產生的匯差分錄。

例如發票 **USD 100／NT$3,200**，收款 **USD 100／NT$3,300**，差額 **NT$100 為兌換利益**，不用修改外幣金額。
