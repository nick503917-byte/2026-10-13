### 1. sap b1 的價目表 作用是甚麼

來源：[S034-Q001](<../../原始問答/S034_了解 SAP B1 價目表作用.md#q1>)；2026-07-30

**問題**

sap b1 的價目表 作用是甚麼

**歷史回答**

SAP Business One（SAP B1）的「價目表」主要用來管理不同客戶、供應商與交易情境的商品價格。

常見作用包括：

- **設定基準價格**：為每個品項維護銷售價或採購價。
- **區分客戶價格**：例如零售價、批發價、經銷商價、VIP 價。
- **自動帶入單價**：建立報價單、銷售訂單、交貨單或採購單時，依業務夥伴指定的價目表自動取價。
- **建立價格關聯**：某張價目表可依另一張價目表乘上係數，例如「經銷價＝標準售價 × 0.8」。
- **管理幣別與計價單位**：同一品項可依不同幣別、包裝或計量單位設定價格。
- **支援期間與數量優惠**：搭配「期間與數量折扣」，設定促銷期間或大量購買的階梯價格。
- **作為折扣判斷基礎**：可再搭配折扣群組、特殊價格等規則決定最終成交價。

簡單來說，其運作方式是：

**品項價格 → 價目表 → 指派給客戶／供應商 → 建立單據時自動帶入**

例如，A 商品的標準售價是 1,000 元：

- 一般客戶價目表：1,000 元
- 經銷商價目表：800 元
- VIP 價目表：900 元

當建立銷售訂單並選擇經銷商客戶時，系統就會自動帶出 800 元；但若有「特殊價格、期間優惠或數量折扣」，最後價格仍可能被其他定價規則取代。

### 2. SQL／程式碼調整與說明

來源：[S113-Q001](<../../原始問答/S113_分析報價毛利率 SQL.md#q1>)；2026-08-26

**問題**

SELECT (    (        TRY\_CAST(            REPLACE(                REPLACE(                    REPLACE($[$38.14.0], ' VND', ''),                '.', ''),            ',', '.')        AS DECIMAL(19,6))        -         ISNULL(T0.AvgPrice,0)    )    /    NULLIF(        TRY\_CAST(            REPLACE(                REPLACE(                    REPLACE($[$38.14.0], ' VND', ''),                '.', ''),            ',', '.')        AS DECIMAL(19,6))    ,0)) \* 100\
FROM OITM T0\
WHERE T0.ItemCode = $[QUT1.ItemCode]

幫我分析一下

**歷史回答**

這段 SQL 應該是 SAP Business One 的格式化搜尋，用來計算「目前輸入價格相較於品項平均成本的毛利率／價差百分比」。

核心公式是：

```text
(輸入價格 - 平均成本) ÷ 輸入價格 × 100
```

也就是「以售價為分母」的毛利率，不是以成本為分母的加價率。

### 各部分說明

`$[$38.14.0]`

- 取得畫面矩陣第 `38` 項、第 `14` 欄的值。
- 在報價單中，這通常代表明細列的單價欄位。
- `.0` 表示取目前顯示值，因此內容可能包含千分位和貨幣字樣，例如：

```text
1.234.567,00 VND
```

以下轉換：

```sql
TRY_CAST(
    REPLACE(
        REPLACE(
            REPLACE($[$38.14.0], ' VND', ''),
            '.', ''
        ),
        ',', '.'
    )
    AS DECIMAL(19,6)
)
```

會依序執行：

1. 移除 ` VND`
2. 移除千分位的 `.`
3. 將小數點格式的 `,` 改成 `.`
4. 轉成 `DECIMAL(19,6)`

例如：

```text
1.234.567,89 VND
→ 1.234.567,89
→ 1234567,89
→ 1234567.89
→ DECIMAL 1234567.890000
```

`ISNULL(T0.AvgPrice, 0)` 是從 `OITM` 品項主檔取得平均成本；若平均成本是 `NULL`，就當成 `0`。

`NULLIF(輸入價格, 0)` 則是避免除以零。若輸入價格是 0，分母會轉成 `NULL`，最後結果也是 `NULL`，而不是拋出除以零錯誤。

### 計算範例

若：

```text
輸入價格 = 120
AvgPrice = 100
```

結果：

```text
(120 - 100) / 120 × 100
= 16.6667%
```

如果你想算的是「加價率」，公式應該改成：

```text
(輸入價格 - 平均成本) / 平均成本 × 100
```

此例會是：

```text
(120 - 100) / 100 × 100
= 20%
```

### 需要注意的問題

1. `AvgPrice` 通常是本幣成本  
   如果報價單價格是 VND，但公司本幣或 `AvgPrice` 不是 VND，就不能直接相減，必須先做匯率換算。

2. `AvgPrice` 未必是目前倉庫的成本  
   `OITM.AvgPrice` 是品項層級的平均成本。在多倉庫或依倉庫管理成本的環境，可能應改查 `OITW.AvgPrice`，並加上倉庫條件。

3. 價格可能含稅或折扣  
   `$[$38.14.0]` 取得哪一個價格欄位，會影響結果。需要確認它是折扣前單價、折扣後價格，還是含稅價格。

4. 轉換失敗時結果會是 `NULL`  
   `TRY_CAST` 不會報錯，但如果畫面值的貨幣格式不是固定的 ` VND`，結果可能直接變成空值。

5. 找不到品項時不會回傳資料  
   如果 `OITM` 中找不到 `$[QUT1.ItemCode]`，整個查詢會回傳零筆，而不是 `0` 或 `NULL`。

總結：這段 SQL 的邏輯是合理的，但它實際計算的是「毛利率」，而且前提是畫面單價與 `OITM.AvgPrice` 使用相同貨幣、相同價格基礎。

### 3. 但如果是USD 是不是就會有問題

來源：[S113-Q002](<../../原始問答/S113_分析報價毛利率 SQL.md#q2>)；2026-08-26

**問題**

但如果是USD 是不是就會有問題

**歷史回答**

會，而且可能有兩種問題。

第一，這段只移除固定字串 `' VND'`：

```sql
REPLACE($[$38.14.0], ' VND', '')
```

如果欄位顯示：

```text
1,234.56 USD
```

`USD` 不會被移除，`TRY_CAST` 轉換失敗，最後結果會變成 `NULL`。

第二，即使成功移除 USD，目前的格式轉換是按照歐洲式／越南式數字格式設計：

```text
1.234,56 → 1234.56
```

若 USD 顯示為：

```text
1,234.56
```

原本邏輯會變成：

```text
1,234.56
→ 1,23456       -- 移除所有句點
→ 1.23456       -- 逗號換成句點
```

結果會被錯誤解析成 `1.23456`，不是 `1234.56`。

另外還有更重要的問題：`OITM.AvgPrice` 通常是公司本幣成本。如果售價是 USD，而平均成本是 VND 或其他本幣，兩者不能直接相減：

```text
USD 售價 - VND 成本
```

即使 SQL 能執行，算出的毛利率也沒有意義。

如果 USD 與 VND 可能同時出現，建議不要解析畫面上的格式化文字，改用 SAP B1 資料來源中的「數值價格＋幣別＋匯率」，先統一成同一貨幣後再計算，例如概念上：

```sql
毛利率 =
(
    換算成本幣別後的售價 - AvgPrice
)
/
換算成本幣別後的售價
* 100
```

若只是先解決 USD 字樣，可以增加：

```sql
REPLACE(
    REPLACE($[$38.14.0], ' VND', ''),
    ' USD',
    ''
)
```

但這只能處理貨幣文字，不能可靠解決 `1,234.56` 與 `1.234,56` 的格式差異，也沒有解決匯率問題。最穩妥的做法是取得報價單的幣別與匯率後，再做換算。

### 4. 格式都會是一樣的

來源：[S113-Q003](<../../原始問答/S113_分析報價毛利率 SQL.md#q3>)；2026-08-26

**問題**

格式都會是一樣的

**歷史回答**

如果 USD 與 VND 的數字格式完全相同，例如都是：

```text
1.234,56 VND
1.234,56 USD
```

那千分位與小數點的轉換不會有問題；問題只剩下兩個。

第一，目前只移除 `' VND'`，USD 仍會造成 `TRY_CAST` 失敗。可以改成同時移除：

```sql
SELECT
    (
        TRY_CAST(
            REPLACE(
                REPLACE(
                    REPLACE(
                        REPLACE($[$38.14.0], ' VND', ''),
                        ' USD', ''
                    ),
                    '.', ''
                ),
                ',', '.'
            ) AS DECIMAL(19,6)
        )
        - ISNULL(T0.AvgPrice, 0)
    )
    /
    NULLIF(
        TRY_CAST(
            REPLACE(
                REPLACE(
                    REPLACE(
                        REPLACE($[$38.14.0], ' VND', ''),
                        ' USD', ''
                    ),
                    '.', ''
                ),
                ',', '.'
            ) AS DECIMAL(19,6)
        ),
        0
    ) * 100
FROM OITM T0
WHERE T0.ItemCode = $[QUT1.ItemCode]
```

第二，即使格式相同，貨幣價值仍不同。假設：

```text
畫面售價：100 USD
AvgPrice：2,500 VND
```

直接計算：

```text
(100 - 2500) / 100
```

仍然是錯的，因為 USD 和 VND 沒有先換成相同貨幣。

所以結論是：

- 如果 `AvgPrice` 已經與畫面價格是相同幣別，只需增加移除 `' USD'`。
- 如果 `AvgPrice` 是公司本幣，而畫面價格可能是 USD，就還要依報價單匯率換算。
- 若 SAP 欄位顯示不含貨幣文字，原 SQL 的 `' VND'` 移除其實可以完全拿掉。

### 5. sapb1 本國幣別 跟 系統幣別

來源：[S113-Q004](<../../原始問答/S113_分析報價毛利率 SQL.md#q4>)；2026-08-26

**問題**

sapb1 本國幣別 跟 系統幣別

**歷史回答**

在 SAP Business One 裡，這兩者是不同概念：

- 本國幣別（Local Currency，LC）：公司日常帳務使用的主要幣別。
- 系統幣別（System Currency，SC）：用於集團報表或跨國彙總的第二套幣別。

例如公司設定：

```text
本國幣別 LC：VND
系統幣別 SC：USD
```

`OITM` 常見成本欄位的幣別如下：

| 欄位 | 意義 | 幣別 |
|---|---|---|
| `AvgPrice` | 平均成本 | 本國幣別 LC |
| `LastPurPrc` | 最後採購價格 | 搭配 `LastPurCur` 判斷 |
| `LastPurCur` | 最後採購幣別 | 幣別代碼 |

因此：

```sql
T0.AvgPrice
```

通常應視為本國幣別金額。即使系統幣別是 USD，也不代表 `AvgPrice` 是 USD。

假設：

```text
本國幣別：VND
系統幣別：USD
AvgPrice：2,500,000 VND
報價單價格：100 USD
匯率：25,000 VND/USD
```

必須先統一幣別：

```text
100 USD × 25,000 = 2,500,000 VND
```

再計算毛利率：

```text
(2,500,000 - 2,500,000) / 2,500,000 × 100 = 0%
```

不能直接用：

```text
(100 - 2,500,000) / 100
```

### SAP B1 報價單相關欄位

報價單表頭 `OQUT` 通常包含：

| 欄位 | 用途 |
|---|---|
| `DocCur` | 文件幣別 |
| `DocRate` | 文件匯率 |
| `DocTotal` | 文件幣別總額 |
| `DocTotalFC` | 外幣總額 |
| `DocTotalSy` | 系統幣別總額 |

明細 `QUT1` 常見欄位：

| 欄位 | 用途 |
|---|---|
| `Price` | 明細價格，需配合文件情境判讀 |
| `Currency` | 明細幣別 |
| `Rate` | 明細匯率 |
| `TotalFrgn` | 外幣列總額 |
| `TotalSumSy` | 系統幣別列總額 |

### 你的公式應如何處理

如果 `AvgPrice` 是 VND，而報價價格可能是 USD，概念上應該是：

```sql
CASE
    WHEN 報價幣別 = 本國幣別
        THEN 畫面價格
    ELSE
        畫面價格 * 匯率
END
```

然後再算：

```sql
(本幣售價 - AvgPrice) / 本幣售價 * 100
```

若你想直接用「系統幣別 USD」計算，則要把 `AvgPrice` 從本幣換成系統幣別，不能因為 USD 是系統幣別就直接拿 `AvgPrice` 當 USD。

最穩定的設計是全部換成本國幣別再計算，因為 `OITM.AvgPrice` 本身就是本幣成本。

### 6. ordr 的 草稿 是甚麼table

來源：[S113-Q005](<../../原始問答/S113_分析報價毛利率 SQL.md#q5>)；2026-08-26

**問題**

ordr 的 草稿 是甚麼table

**歷史回答**

SAP Business One 中，`ORDR` 是正式銷售訂單；銷售訂單草稿存放在：

- 表頭：`ODRF`
- 明細：`DRF1`

草稿表共用於多種文件，所以查詢銷售訂單草稿時，要用 `ObjType = '17'` 篩選：

```sql
SELECT
    T0.DocEntry,
    T0.DocNum,
    T0.CardCode,
    T0.CardName,
    T0.DocDate,
    T0.DocTotal,
    T0.DocCur
FROM ODRF T0
WHERE T0.ObjType = '17';
```

查詢草稿明細：

```sql
SELECT
    T0.DocEntry,
    T0.DocNum,
    T0.CardCode,
    T1.LineNum,
    T1.ItemCode,
    T1.Dscription,
    T1.Quantity,
    T1.Price,
    T1.LineTotal
FROM ODRF T0
INNER JOIN DRF1 T1
    ON T1.DocEntry = T0.DocEntry
WHERE T0.ObjType = '17';
```

對照如下：

| 文件 | 正式表頭 | 正式明細 | 草稿表頭 | 草稿明細 | `ObjType` |
|---|---|---|---|---|---|
| 銷售訂單 | `ORDR` | `RDR1` | `ODRF` | `DRF1` | `17` |

注意：`ODRF`／`DRF1` 也會存放其他文件草稿，所以不能只查這兩張表而不限制 `ObjType`。

### 7. SQL／程式碼調整與說明

來源：[S113-Q006](<../../原始問答/S113_分析報價毛利率 SQL.md#q6>)；2026-08-26

**問題**

SELECT
    (
        TRY\_CAST(
            REPLACE(
                REPLACE(
                    REPLACE(
                        REPLACE($[$38.14.0], ' VND', ''),
                        ' USD', ''
                    ),
                    '.', ''
                ),
                ',', '.'
            ) AS DECIMAL(19,6)
        )
        \- ISNULL(T0.AvgPrice, 0)
    )
    /
    NULLIF(
        TRY\_CAST(
            REPLACE(
                REPLACE(
                    REPLACE(
                        REPLACE($[$38.14.0], ' VND', ''),
                        ' USD', ''
                    ),
                    '.', ''
                ),
                ',', '.'
            ) AS DECIMAL(19,6)
        ),
        0
    ) \* 100
FROM OITM T0
WHERE T0.ItemCode = $[QUT1.ItemCode]

我要 OQUT  這個TABLE  DocRate 

\*DocRate

**歷史回答**

如果目的是先將報價單價格乘上 `OQUT.DocRate`，換算成本國幣別，再與 `OITM.AvgPrice` 比較，可以改成：

```sql
SELECT
    (
        (
            TRY_CAST(
                REPLACE(
                    REPLACE(
                        REPLACE(
                            REPLACE($[$38.14.0], ' VND', ''),
                            ' USD', ''
                        ),
                        '.', ''
                    ),
                    ',', '.'
                ) AS DECIMAL(19,6)
            )
            * ISNULL(NULLIF($[OQUT.DocRate], 0), 1)
        )
        - ISNULL(T0.AvgPrice, 0)
    )
    /
    NULLIF(
        TRY_CAST(
            REPLACE(
                REPLACE(
                    REPLACE(
                        REPLACE($[$38.14.0], ' VND', ''),
                        ' USD', ''
                    ),
                    '.', ''
                ),
                ',', '.'
            ) AS DECIMAL(19,6)
        )
        * ISNULL(NULLIF($[OQUT.DocRate], 0), 1),
        0
    )
    * 100
FROM OITM T0
WHERE T0.ItemCode = $[QUT1.ItemCode]
```

核心變成：

```text
本幣售價 = 畫面單價 × OQUT.DocRate
毛利率 = (本幣售價 - AvgPrice) ÷ 本幣售價 × 100
```

這裡使用：

```sql
$[OQUT.DocRate]
```

直接取得目前報價單表頭的匯率，不需要再 `JOIN OQUT`。這對尚未新增、還沒有 `DocEntry` 的報價單也比較合適。

另外：

```sql
ISNULL(NULLIF($[OQUT.DocRate], 0), 1)
```

代表匯率若為 `NULL` 或 `0`，就改用 `1`，適用本國幣別文件。

需要確認 SAP 的匯率定義是：

```text
1 USD = DocRate 本國幣
```

在這種常見設定下，`USD 單價 × DocRate` 才會得到本國幣價格。若公司的匯率設定採間接匯率，則可能要改成除以 `DocRate`。

### 8. 我現在算出來數字是錯的

來源：[S113-Q007](<../../原始問答/S113_分析報價毛利率 SQL.md#q7>)；2026-08-26

**問題**

我現在算出來數字是錯的

**歷史回答**

### 9. 因為我這樣沒辦法跑 所以 可以先給我一版

來源：[S113-Q008](<../../原始問答/S113_分析報價毛利率 SQL.md#q8>)；2026-08-26

**問題**

因為我這樣沒辦法跑 所以 可以先給我一版

**歷史回答**

可以，先給你一版「只有 USD 才乘 `DocRate`，VND 不換匯」的版本：

```sql
SELECT
    (
        T1.LocalPrice - ISNULL(T0.AvgPrice, 0)
    )
    /
    NULLIF(T1.LocalPrice, 0)
    * 100
FROM OITM T0
CROSS APPLY
(
    SELECT
        CASE
            WHEN $[OQUT.DocCur] = 'USD'
            THEN
                TRY_CAST(
                    REPLACE(
                        REPLACE(
                            REPLACE(
                                REPLACE($[$38.14.0], ' VND', ''),
                                ' USD', ''
                            ),
                            '.', ''
                        ),
                        ',', '.'
                    ) AS DECIMAL(19,6)
                )
                * ISNULL(NULLIF($[OQUT.DocRate], 0), 1)
            ELSE
                TRY_CAST(
                    REPLACE(
                        REPLACE(
                            REPLACE(
                                REPLACE($[$38.14.0], ' VND', ''),
                                ' USD', ''
                            ),
                            '.', ''
                        ),
                        ',', '.'
                    ) AS DECIMAL(19,6)
                )
        END AS LocalPrice
) T1
WHERE T0.ItemCode = $[QUT1.ItemCode]
```

計算邏輯：

```text
USD：畫面單價 × DocRate → 換算成本國幣
VND：直接使用畫面單價
毛利率：(本幣售價 - AvgPrice) ÷ 本幣售價 × 100
```

如果 SAP 在這一行出現語法錯誤：

```sql
WHEN $[OQUT.DocCur] = 'USD'
```

改成：

```sql
WHEN '$[OQUT.DocCur]' = 'USD'
```

這取決於你目前 SAP B1 版本對格式化搜尋字串欄位的替換方式。其他部分不需要改。
