### 1. 越南的 小數分隔符號是 ' , ' 千位分隔符號 ' . ' RDR1 的 PriceBefDi 需要乘上 ORDR 的 U\_SALEPRICE 然後帶入到 RDR1 U\_GR…

來源：[S094-Q001](<../../原始問答/S094_修正越南價格格式與群組價格.md#q1>)；2026-08-20

**問題**

越南的 小數分隔符號是 ' , '  千位分隔符號 ' . '

RDR1 的 PriceBefDi 需要乘上 ORDR 的 U\_SALEPRICE 然後帶入到  RDR1 U\_GROUPPRICE

**歷史回答**

目前工作目錄內沒有程式或 SQL 檔案可修改。若需求是 SAP Business One／SQL Server 更新語法，可使用：

```sql
UPDATE T1
SET T1.U_GROUPPRICE =
    ISNULL(T1.PriceBefDi, 0) * ISNULL(T0.U_SALEPRICE, 0)
FROM ORDR T0
INNER JOIN RDR1 T1
    ON T1.DocEntry = T0.DocEntry
WHERE T0.DocEntry = @DocEntry;
```

計算規則：

```text
RDR1.U_GROUPPRICE = RDR1.PriceBefDi × ORDR.U_SALEPRICE
```

越南顯示格式如 `1.234,56` 只影響畫面呈現；若兩個欄位都是 SAP 數值型欄位，不需要自行替換 `.` 與 `,`。若 `U_SALEPRICE` 是文字欄位，則需要另外處理格式轉換。

請提供要修改的程式／SQL 檔案，或告訴我是要做 FMS、Transaction Notification 還是 Add-on，我便能直接套用。

### 2. 我沒辦法用UPDATE 因為不允許

來源：[S094-Q002](<../../原始問答/S094_修正越南價格格式與群組價格.md#q2>)；2026-08-20

**問題**

我沒辦法用UPDATE 因為不允許

**歷史回答**

了解，不能使用 `UPDATE` 的話，請在 `RDR1.U_GROUPPRICE` 設定「格式化搜尋（FMS）」，使用純 `SELECT`：

```sql
SELECT
    $[RDR1.PriceBefDi.NUMBER] *
    $[ORDR.U_SALEPRICE.NUMBER]
```

`.NUMBER` 會讓 SAP Business One 依數值處理，因此越南格式：

```text
1.234,56 → 1234.56
```

不需要自行用 `REPLACE` 處理分隔符號。

請將此查詢指定給銷售訂單明細的 `U_GROUPPRICE`，並設定：

- 自動更新
- 依欄位變更觸發
- 觸發欄位選擇 `PriceBefDi`
- 如果表頭 `U_SALEPRICE` 改變後也需重算，明細列可能需要重新觸發 FMS

若系統不接受資料表欄位語法，就必須改用畫面 Item UID，例如：

```sql
SELECT $[$38.PriceBefDi.NUMBER] * $[$表頭ItemUID.0.NUMBER]
```

其中表頭的 `Item UID` 需透過 SAP Business One 的「系統資訊」查出。

### 3. 現在不是格式的問題 撇開格式 FMS可以幫我 做計算嗎

來源：[S094-Q003](<../../原始問答/S094_修正越南價格格式與群組價格.md#q3>)；2026-08-20

**問題**

現在不是格式的問題 撇開格式 FMS可以幫我 做計算嗎

**歷史回答**

可以，FMS 能做這個乘法計算，不需要 `UPDATE`。

將以下查詢綁定到明細欄位 `RDR1.U_GROUPPRICE`：

```sql
SELECT
    ISNULL($[RDR1.PriceBefDi.NUMBER], 0)
    * ISNULL($[ORDR.U_SALEPRICE.NUMBER], 0)
```

如果 FMS 不接受 `ISNULL` 包住 SAP 欄位變數，改用最簡單版本：

```sql
SELECT
    $[RDR1.PriceBefDi.NUMBER]
    * $[ORDR.U_SALEPRICE.NUMBER]
```

設定方式：

- 目標欄位：`RDR1.U_GROUPPRICE`
- 自動重新整理：啟用
- 觸發欄位：`RDR1.PriceBefDi`
- 強制重新整理：啟用

計算結果就是：

```text
U_GROUPPRICE = PriceBefDi × U_SALEPRICE
```

但要注意：如果只修改表頭的 `ORDR.U_SALEPRICE`，SAP FMS 通常不會自動逐行重算所有明細。此時需逐行觸發，或用 Add-on 才能一次更新所有列。

### 4. 我的PriceBefDi 是 CHARACTERS ORDR.U_SALEPRICE 也是CHARACTERS

來源：[S094-Q004](<../../原始問答/S094_修正越南價格格式與群組價格.md#q4>)；2026-08-20

**問題**

我的PriceBefDi 是 CHARACTERS ORDR.U_SALEPRICE 也是CHARACTERS

**歷史回答**

可以，但因兩個欄位都是文字型別，FMS 必須先轉成數值再相乘。

若是 SQL Server，並且文字採越南格式（例如 `1.234,56`），使用：

```sql
SELECT
    COALESCE(
        TRY_CONVERT(
            DECIMAL(19, 6),
            REPLACE(REPLACE(NULLIF('$[RDR1.PriceBefDi.0]', ''), '.', ''), ',', '.')
        ),
        0
    )
    *
    COALESCE(
        TRY_CONVERT(
            DECIMAL(19, 6),
            REPLACE(REPLACE(NULLIF('$[ORDR.U_SALEPRICE.0]', ''), '.', ''), ',', '.')
        ),
        0
    )
```

例如：

```text
PriceBefDi       = 1.234,56
U_SALEPRICE      = 2
U_GROUPPRICE     = 2.469,12
```

這是純 `SELECT` 計算，可以用在 FMS，不需要 `UPDATE`。

如果你的資料庫是 SAP HANA，語法會不同：

```sql
SELECT
    IFNULL(
        TO_DECIMAL(
            REPLACE(REPLACE(NULLIF('$[RDR1.PriceBefDi.0]', ''), '.', ''), ',', '.'),
            19,
            6
        ),
        0
    )
    *
    IFNULL(
        TO_DECIMAL(
            REPLACE(REPLACE(NULLIF('$[ORDR.U_SALEPRICE.0]', ''), '.', ''), ',', '.'),
            19,
            6
        ),
        0
    )
FROM DUMMY
```

以上假設欄位内容是純數字文字；若 `U_SALEPRICE` 存的是百分比，例如 `20` 代表 `20%`，最後還要再除以 `100`。

### 5. 我的銷售訂單的表頭ORDR U\_SALEPRICE 乘 表身 RDR1 FINALPRICETEST 然後要帶入到 RDR1 PriceBefDi

來源：[S105-Q001](<../../原始問答/S105_更新銷售訂單價格計算.md#q1>)；2026-08-24

**問題**

我的銷售訂單的表頭ORDR U\_SALEPRICE  乘 表身 RDR1  FINALPRICETEST  然後要帶入到 RDR1 PriceBefDi

**歷史回答**

在 SAP Business One 的銷售訂單中，可以把「格式化搜尋（FMS）」綁定到表身的 `PriceBefDi`（折扣前單價），計算公式為：

```text
ORDR.U_SALEPRICE × RDR1.U_FINALPRICETEST
```

如果是 SAP HANA：

```sql
SELECT
    IFNULL($[ORDR.U_SALEPRICE.NUMBER], 0)
    * IFNULL($[RDR1.U_FINALPRICETEST.NUMBER], 0)
FROM DUMMY;
```

如果是 SQL Server：

```sql
SELECT
    ISNULL($[ORDR.U_SALEPRICE.NUMBER], 0)
    * ISNULL($[RDR1.U_FINALPRICETEST.NUMBER], 0);
```

把這個查詢指定到銷售訂單表身的「折扣前單價／PriceBefDi」欄位，並設定在欄位變動時自動更新。

如果你的實際欄位名稱確實是 `FINALPRICETEST`，而不是使用者自訂欄位 `U_FINALPRICETEST`，則改成：

```sql
$[RDR1.FINALPRICETEST.NUMBER]
```

注意：若 `U_SALEPRICE` 儲存的是百分比，例如 `120` 代表 120%，公式需改為：

```sql
$[ORDR.U_SALEPRICE.NUMBER] / 100
* $[RDR1.U_FINALPRICETEST.NUMBER]
```

另外，若系統不允許 FMS 直接寫入 `PriceBefDi`，就需要使用 UI API、Transaction Notification 或其他外掛方式處理；其中 Transaction Notification 不適合直接更新同一張訂單。

### 6. ORDR U\_SALEPRICE 這個如果是 char的話

來源：[S105-Q002](<../../原始問答/S105_更新銷售訂單價格計算.md#q2>)；2026-08-24

**問題**

ORDR U\_SALEPRICE    這個如果是  char的話

**歷史回答**

如果 `ORDR.U_SALEPRICE` 是字元欄位，必須先轉成數字才能相乘。

SAP HANA：

```sql
SELECT
    IFNULL(
        TO_DECIMAL(
            NULLIF(REPLACE(REPLACE($[ORDR.U_SALEPRICE], ',', ''), '%', ''), ''),
            19,
            6
        ),
        0
    )
    *
    IFNULL($[RDR1.U_FINALPRICETEST.NUMBER], 0)
FROM DUMMY;
```

SQL Server：

```sql
SELECT
    ISNULL(
        TRY_CONVERT(
            DECIMAL(19, 6),
            NULLIF(
                REPLACE(REPLACE($[ORDR.U_SALEPRICE], ',', ''), '%', ''),
                ''
            )
        ),
        0
    )
    *
    ISNULL($[RDR1.U_FINALPRICETEST.NUMBER], 0);
```

若 `U_SALEPRICE` 的內容是百分比，例如字串 `"120%"` 表示 `1.2` 倍，則需要再除以 `100`：

```sql
-- HANA
SELECT
    (
        IFNULL(
            TO_DECIMAL(
                NULLIF(REPLACE(REPLACE($[ORDR.U_SALEPRICE], ',', ''), '%', ''), ''),
                19,
                6
            ),
            0
        ) / 100
    )
    * IFNULL($[RDR1.U_FINALPRICETEST.NUMBER], 0)
FROM DUMMY;
```

如果字串是 `"1.2"`，代表直接乘以 `1.2`，就不需要除以 `100`。

**歷史回答**

這段 SQL 是在計算「最終售價」：

**最終售價＝清理後的 `ORDR.U_SALEPRICE` × `RDR1.U_FINALPRICETEST.NUMBER`**

處理順序如下：

1. **移除逗號與 `%` 符號**  
   例如：`"1,200"` → `"1200"`、`"15%"` → `"15"`。

2. **將空字串轉成 `NULL`**  
   `NULLIF(..., '')` 用來處理沒有填值的情況。

3. **嘗試轉成數字**  
   `TRY_CONVERT(DECIMAL(19, 6), ...)` 將文字轉成小數，最多共 19 位數，其中小數占 6 位。若內容無法轉換，例如 `"ABC"`，會得到 `NULL`。

4. **把無效值或空值當成 0**  
   外層 `ISNULL(..., 0)` 將上述 `NULL` 改為 `0`；乘數欄位若是 `NULL`，也會以 `0` 計算。

例如：

| 售價欄位 | 乘數欄位 | 計算結果 |
|---|---:|---:|
| `1,200` | 2 | 2400 |
| `15%` | 200 | 3000 |
| 空白或 `ABC` | 2 | 0 |

**要注意：這段程式只會移除 `%`，不會除以 100。** 所以 `15%` 會當成 `15`，而不是 `0.15`；如果你要算百分比，這段公式需要調整。

### 8. 但我的小數位會有6位 但我發現自度進位了

來源：[S229-Q002](<../../原始問答/S229_解讀「說迷」.md#q2>)；2026-10-07

**問題**

但我的小數位會有6位 但我發現自度進位了

**歷史回答**

`DECIMAL(19, 6)` 表示轉換時保留 **6 位小數**，超過第 6 位就會四捨五入，例如：

```sql
1.1234567 → 1.123457
```

你的公式也可能在其他地方進位：

- **轉換時**：`TRY_CONVERT(DECIMAL(19, 6), ...)` 會先四捨五入，再拿去相乘。
- **回填或顯示時**：即使計算結果有 6 位小數，目標欄位若只設定 2 位，仍可能顯示或儲存成 2 位。

如果你要「保留 6 位，超出的直接捨去」，可以先用較高精度轉換，再截斷：

```sql
CAST(
    ROUND(
        TRY_CONVERT(DECIMAL(28, 12), ...),
        6,
        1
    )
    AS DECIMAL(19, 6)
)
```

其中 `ROUND(數值, 6, 1)` 的第三個參數 `1` 代表**截斷，不四捨五入**。

你可以貼一個「原始數值、乘數、實際結果、預期結果」嗎？這樣才能判斷是轉換時進位，還是最後欄位的小數設定造成的。

### 10. 2.173300

來源：[S229-Q004](<../../原始問答/S229_解讀「說迷」.md#q4>)；2026-10-07

**問題**

`2.173300`

**歷史回答**

如果**完整公式直接查詢就得到 `2.173300`**，就要檢查乘法的資料型別，而不只是畫面顯示設定。

你原本只將第一個數值轉成 `DECIMAL(19,6)`，第二個乘數沒有明確轉型。可以先把**兩邊都轉成相同精度**，再將結果保留 6 位：

```sql
SELECT
    CAST(
        ISNULL(
            TRY_CONVERT(
                DECIMAL(19, 6),
                NULLIF(
                    REPLACE(
                        REPLACE($[ORDR.U_SALEPRICE], ',', ''),
                        '%', ''
                    ),
                    ''
                )
            ),
            0
        )
        *
        ISNULL(
            TRY_CONVERT(
                DECIMAL(19, 6),
                $[RDR1.U_FINALPRICETEST.NUMBER]
            ),
            0
        )
        AS DECIMAL(19, 6)
    );
```

當實際傳入的值是 `2.527100` 與 `0.86`，這段應得到 **`2.173306`**。

如果仍然是 `2.173300`，請執行下面這段，查看系統實際提供的兩個值：

```sql
SELECT
    $[ORDR.U_SALEPRICE] AS 原始售價,
    $[RDR1.U_FINALPRICETEST.NUMBER] AS 原始乘數;
```

**如果來源值在傳入前就已被取位，最後再轉成 6 位也無法補回精度。**

**歷史回答**

了解，那應該採用 **「文字轉數字 → 相乘 → 結果轉回文字」** 的方式：

| 欄位 | 處理方式 |
|---|---|
| `ORDR.U_SALEPRICE`：文字 | 將越南格式 `0,86` 轉成數字 |
| `RDR1.U_FINALPRICETEST`：數值 | 依最新截圖，`.NUMBER` 代入的是 `2.527100`，直接轉數字 |
| FMS 目標欄位：文字 | 將結果轉成保留 6 位小數的文字 |

**以下版本會回傳文字 `2,173306`**，符合你的小數逗號格式，也方便確認完整 6 位：

```sql
SELECT REPLACE(CONVERT(VARCHAR(50), CAST(ISNULL(TRY_CONVERT(DECIMAL(19,6), NULLIF(REPLACE(REPLACE(REPLACE($[ORDR.U_SALEPRICE], '%', ''), '.', ''), ',', '.'), '')), 0) * ISNULL(TRY_CONVERT(DECIMAL(19,6), '$[RDR1.U_FINALPRICETEST.NUMBER]'), 0) AS DECIMAL(19,6))), '.', ',');
```

這裡最後的 `REPLACE(..., '.', ',')` 只負責文字輸出的格式；乘法仍使用數字計算。
