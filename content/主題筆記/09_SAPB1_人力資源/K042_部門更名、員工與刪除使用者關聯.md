## My request:
部門可以做更新嗎 用DTW

**歷史回答**

**可以，你截圖「使用者－設定」裡的部門，可以透過 DTW 的 Users（OUSR）物件更新。**

重點是：`Department` 要填 **部門的內部數字代碼（OUDP.Code）**，不是直接填畫面上的 `V000000`。SAP 官方確認此欄位可讀寫，並對應 OUDP 部門表。[欄位說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/SAPbobsCOM~Users~Department.html)

操作方式：

1. 在 DTW 產生／開啟 **Users（OUSR）範本**。
2. 選擇 **Update Existing Data（更新現有資料）**。
3. 填入要更新的使用者識別欄位，並將 `Department` 填為目標部門的內部代碼；欄名與兩列標頭以你版本的範本為準。
4. 先用一位使用者測試，成功後再批次更新。

可以用以下唯讀 SQL 查部門對應：

```sql
SELECT "Code", "Name"
FROM "OUDP"
ORDER BY "Code";
```

例如查到 `V000000` 的 `Code` 是 `3`，DTW 的 `Department` 就填 **3**。

### 2. 8 Update Failed InternalKey Can not find this object in B1 Application-defined or object-d…

來源：[S252-Q002](<../../原始問答/S252_確認部門能否用 DTW 更新.md#q2>)；2026-10-16

**問題**

8 Update Failed InternalKey  Can not find this object in B1 Application-defined or object-defined error.65171

**歷史回答**

這個錯誤表示 **DTW 找不到要更新的使用者**。優先檢查 `InternalKey` 的值與欄位對應，還不能判定是部門值有問題。

我前面沒有把使用者識別欄位說清楚，補充一下：**`InternalKey` 對應 `OUSR.INTERNAL_K`**，要填系統的數字內碼，不能填 `manager` 或自行編列的流水號。[SAP 官方說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/SAPbobsCOM~Users~InternalKey.html)

先在 **DTW 登入的同一個公司資料庫**執行：

```sql
SELECT
    "INTERNAL_K",
    "USER_CODE",
    "U_NAME",
    "Department"
FROM "OUSR"
ORDER BY "USER_CODE";
```

再查目標部門代碼：

```sql
SELECT "Code", "Name"
FROM "OUDP"
ORDER BY "Code";
```

假設查到使用者的 `INTERNAL_K = 12`，目標部門的 `Code = 3`，匯入內容就是：

| InternalKey | Department |
|---|---|
| 12 | 3 |

以上是資料示意；**檔案前兩列標頭請保留原版 DTW 範本格式**，並確認欄位對應為 `InternalKey → InternalKey`、`Department → Department`，操作選「更新現有資料」。

你貼出的錯誤中出現文字 `InternalKey`，也值得檢查是否把標頭讀成資料列。**請貼上匯入檔的前兩列標頭及一筆失敗資料**，我可以直接幫你確認；不用提供密碼欄位。

### 3. 如果我的代碼已經刪除 但我的部門掛在那裏怎麼辦

來源：[S252-Q003](<../../原始問答/S252_確認部門能否用 DTW 更新.md#q3>)；2026-10-16

**問題**

如果我的代碼已經刪除 但我的部門掛在那裏怎麼辦

**歷史回答**

如果你是指 **部門代碼已刪除，但使用者的「部門」還掛著舊值**，先查目前的關聯：

```sql
SELECT
    U."INTERNAL_K",
    U."USER_CODE",
    U."Department",
    D."Name" AS "部門名稱"
FROM "OUSR" U
LEFT JOIN "OUDP" D
    ON U."Department" = D."Code"
ORDER BY U."USER_CODE";
```

若使用者有部門值、但查不到部門名稱，表示目前沒有對應的部門資料；也要排除原本就是「未指定部門」的情況。

處理方式：

- **改掛有效部門**：先在 SAP 畫面選一個現有部門並更新；批次處理時，DTW 的 `InternalKey` 填使用者內碼，`Department` 填有效的部門內碼。
- **想取消部門**：先在 SAP 畫面清空部門並更新，確認系統接受，再查 `OUSR.Department` 實際儲存的值，作為批次更新依據。**不要直接假設 DTW 留白就會清除。**
- **想重新建立同名部門**：新建後仍要確認內碼，不能假設同名就會自動接回原有使用者。

但如果你說的是 **使用者代碼已刪除**，DTW 更新就會找不到該使用者，這也符合前面的錯誤。

你刪掉的是「部門代碼」，還是「使用者代碼」？

### 4. 我刪除的是使用者代碼 因為使用者代碼已經刪除了 沒辦法更改部門

來源：[S252-Q004](<../../原始問答/S252_確認部門能否用 DTW 更新.md#q4>)；2026-10-16

**問題**

我刪除的是使用者代碼 因為使用者代碼已經刪除了 沒辦法更改部門

**歷史回答**

了解，**使用者已刪除，但資料庫仍留著他的部門關聯；這種情況不能當成一般使用者，用 DTW 更新部門。** 我前面建議修改 `InternalKey`，對你這種已刪除使用者的情況並不適用，抱歉。

SAP B1 刪除使用者時，只會標記為「已移除」，資料仍保留在資料庫；即使透過查詢開啟該使用者，更新時也會被系統拒絕。[SAP 刪除使用者說明](https://help.sap.com/docs/SAP_BUSINESS_ONE/68a2e87fb29941b5bf959a184d9c6727/2665f3f185b9406c8633b1c680a86dd6.html)

因此要看你現在要解決的是哪個問題：

- **只是查詢／報表還顯示他掛在該部門**：調整查詢，排除已刪除使用者即可，不必更動歷史資料。
- **要刪除部門，卻被這個已刪除使用者擋住**：請 SAP B1 維護顧問向 SAP Support 確認適用版本的修復方式，不能靠一般 DTW 更新處理。不要直接用 SQL 修改 `OUSR` 的部門或刪除狀態。

**你目前是「要刪除部門時被擋住」，還是「報表仍出現這個使用者」？**

### 5. 要刪除部門時被擋住

來源：[S252-Q005](<../../原始問答/S252_確認部門能否用 DTW 更新.md#q5>)；2026-10-16

**問題**

要刪除部門時被擋住

**歷史回答**

那就確認了：**已刪除使用者仍保留部門關聯，導致部門無法刪除；這個情況無法靠一般 DTW 更新已刪除使用者來解除。**

SAP 會保留已刪除使用者的資料，且不允許再從使用者設定更新。[SAP 官方說明](https://help.sap.com/docs/SAP_BUSINESS_ONE/68a2e87fb29941b5bf959a184d9c6727/2665f3f185b9406c8633b1c680a86dd6.html)

你現在可以這樣處理：

- **部門一定要刪除**：請維護顧問向 SAP Support 提交案件，確認你版本適用的修正方式。提供 SAP B1 版本／Patch、部門代碼、已刪除使用者代碼，以及刪除部門的完整錯誤訊息。
- **只是避免再被選用**：若畫面允許修改部門名稱，可先改成「停用－原部門名稱」。這只是標示，並不會真正禁止選取。

**不要直接用 SQL 清除 `OUSR.Department`，或修改使用者刪除狀態來繞過限制。**

給顧問的描述可以直接用：

> 刪除部門時，系統因已刪除使用者仍關聯該部門而阻擋。該使用者無法透過介面修改，DTW 更新也出現「Can not find this object in B1…65171」。請協助確認此版本是否有適用的 SAP Note 或官方資料修復程序，以解除關聯並刪除部門。

**這次是「部門名稱重複」的錯誤，與剛才已刪除使用者的錯誤不同。** SAP 的 `OUDP.Name` 有唯一性限制，不能重複。[SAP 表格定義](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OUDP.html)

從兩張圖看到這個衝突：

| 位置 | 貼上前 | 貼上後 |
|---|---|---|
| 第 8 列（IQC） | `VV51200` | `VV31000` |
| 第 15 列（生產線 2） | `V332200` | `VV51200` |

**很可能儲存第 15 列時，第 8 列的舊名稱 `VV51200` 尚未釋放**，所以即使貼上後畫面沒有重複，更新過程仍報錯。僅憑截圖還無法確認實際儲存順序。

請先用兩階段改名：

1. **取消這次未成功的修改，重新開啟部門設定**，確認回到貼上前資料。
2. 找到原本 IQC 的 `VV51200`，單獨改成未使用的暫存名稱，例如 `TMP_IQC_01`，按「更新」。
3. 重新開啟，確認暫存名稱已儲存。
4. 再貼上你第一張圖的完整目標內容，按「更新」。貼上時以部門說明核對位置，避免重新開啟後列順序改變。

另請注意：**這是在替原部門改名，原本掛在該部門內碼的使用者／員工會繼續掛在同一筆部門。** 左側 `#` 是畫面列號，不是 `OUDP.Code`，也不能拿來填 DTW 的 `Department`。
