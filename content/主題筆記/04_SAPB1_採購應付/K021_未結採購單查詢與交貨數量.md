### 1. 我想寫查詢報表關於： OPOR,POR1 然後我想用採購的物料或是 業務夥伴做搜尋

來源：[S061-Q001](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q1>)；2026-08-10

**問題**

我想寫查詢報表關於：
OPOR,POR1  然後我想用採購的物料或是 業務夥伴做搜尋

**歷史回答**

以下是 SAP Business One SQL Server 版查詢，可從 `OPOR`（採購訂單表頭）及 `POR1`（採購訂單明細）依「物料」或「業務夥伴」搜尋。兩個條件都可留空；若同時輸入，則會同時篩選。

```sql
/* SAP Business One－採購訂單查詢 */

DECLARE @ItemCode NVARCHAR(100)
DECLARE @CardCode NVARCHAR(100)

SET @ItemCode = /* SELECT T0.ItemCode FROM OITM T0 WHERE T0.ItemCode */ '[%0]'
SET @CardCode = /* SELECT T0.CardCode FROM OCRD T0 WHERE T0.CardType = 'S' */ '[%1]'

SELECT
    T0.DocNum                         AS N'採購單號',
    T0.DocDate                        AS N'過帳日期',
    T0.DocDueDate                     AS N'交貨日期',
    T0.CardCode                       AS N'供應商代碼',
    T0.CardName                       AS N'供應商名稱',
    T1.LineNum + 1                    AS N'列號',
    T1.ItemCode                       AS N'物料號碼',
    T1.Dscription                     AS N'物料說明',
    T1.Quantity                       AS N'訂購數量',
    T1.OpenQty                        AS N'未交數量',
    T1.Price                          AS N'單價',
    T1.LineTotal                      AS N'未稅金額',
    T0.DocCur                         AS N'幣別',
    T1.WhsCode                        AS N'倉庫',
    CASE T0.DocStatus
        WHEN 'O' THEN N'未結'
        WHEN 'C' THEN N'已結'
    END                               AS N'文件狀態',
    CASE T1.LineStatus
        WHEN 'O' THEN N'未結'
        WHEN 'C' THEN N'已結'
    END                               AS N'明細狀態',
    T0.NumAtCard                      AS N'供應商參考號碼',
    T0.Comments                       AS N'備註'
FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry
WHERE
    T0.CANCELED = 'N'
    AND (
        ISNULL(@ItemCode, '') = ''
        OR T1.ItemCode LIKE '%' + @ItemCode + '%'
        OR T1.Dscription LIKE '%' + @ItemCode + '%'
    )
    AND (
        ISNULL(@CardCode, '') = ''
        OR T0.CardCode LIKE '%' + @CardCode + '%'
        OR T0.CardName LIKE '%' + @CardCode + '%'
    )
ORDER BY
    T0.DocDate DESC,
    T0.DocNum DESC,
    T1.LineNum
```

查詢時：

- `[%0]`：可輸入物料號碼或物料說明，留空代表全部物料。
- `[%1]`：可輸入供應商代碼或名稱，留空代表全部供應商。
- 同時輸入物料與供應商時，會查出符合兩項條件的採購訂單。
- 查詢已排除取消的採購訂單。

如果資料庫是 SAP HANA，語法會不同，以上版本適用於 Microsoft SQL Server。

### 2. FMS 沒辦用DECLARE

來源：[S061-Q002](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q2>)；2026-08-10

**問題**

FMS 沒辦用DECLARE

**歷史回答**

對，SAP Business One 的「格式化搜尋（FMS）」不能使用 `DECLARE`，需要直接使用畫面欄位變數。

如果是在採購訂單畫面：

- `$[$4.0.0]`：目前畫面的供應商代碼
- `$[$38.1.0]`：目前選取列的物料號碼

可改成：

```sql
SELECT
    T0.DocNum,
    T0.DocDate,
    T0.CardCode,
    T0.CardName,
    T1.ItemCode,
    T1.Dscription,
    T1.Quantity,
    T1.OpenQty,
    T1.Price,
    T1.LineTotal
FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry
WHERE T0.CANCELED = 'N'
  AND (
        T0.CardCode = $[$4.0.0]
        OR T1.ItemCode = $[$38.1.0]
      )
ORDER BY T0.DocDate DESC, T0.DocNum DESC
```

但要注意：FMS 通常只能把「單一結果值」帶回一個欄位，並不適合顯示多欄、多筆的查詢報表。上面的查詢比較適合透過「查詢管理員」執行。

如果你的需求是在查詢管理員內讓使用者輸入物料或供應商，但不能使用 `DECLARE`，可以直接這樣寫：

```sql
SELECT
    T0.DocNum                         AS N'採購單號',
    T0.DocDate                        AS N'過帳日期',
    T0.DocDueDate                     AS N'交貨日期',
    T0.CardCode                       AS N'供應商代碼',
    T0.CardName                       AS N'供應商名稱',
    T1.LineNum + 1                    AS N'列號',
    T1.ItemCode                       AS N'物料號碼',
    T1.Dscription                     AS N'物料說明',
    T1.Quantity                       AS N'訂購數量',
    T1.OpenQty                        AS N'未交數量',
    T1.Price                          AS N'單價',
    T1.LineTotal                      AS N'未稅金額',
    T1.WhsCode                        AS N'倉庫',
    CASE T0.DocStatus
        WHEN 'O' THEN N'未結'
        WHEN 'C' THEN N'已結'
    END                               AS N'文件狀態'
FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry
WHERE T0.CANCELED = 'N'
  AND (
        '[%0]' = ''
        OR T1.ItemCode LIKE '%[%0]%'
        OR T1.Dscription LIKE '%[%0]%'
      )
  AND (
        '[%1]' = ''
        OR T0.CardCode LIKE '%[%1]%'
        OR T0.CardName LIKE '%[%1]%'
      )
ORDER BY T0.DocDate DESC, T0.DocNum DESC, T1.LineNum
```

其中 `[%0]` 是物料條件、`[%1]` 是供應商條件，皆可留空。真正的 FMS 則要依「目前畫面欄位」搜尋，不能跳出 `[%0]`、`[%1]` 輸入視窗。

### 3. 我變成要篩選是否為取消單據，我想要不要篩選是否為篩選單據，以及我搜尋出來都是沒有結果

來源：[S061-Q003](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q3>)；2026-08-10

**問題**

我變成要篩選是否為取消單據，我想要不要篩選是否為篩選單據，以及我搜尋出來都是沒有結果

**歷史回答**

沒有結果的主要原因可能是 `LIKE '%[%0]%'` 的參數組合方式。SAP B1 SQL Server 建議使用字串串接。另外，`OPOR.CANCELED`：

- `N`：未取消
- `Y`：已取消
- 留空：全部單據

以下版本不使用 `DECLARE`：

```sql
SELECT
    T0.DocNum                         AS N'採購單號',
    T0.DocDate                        AS N'過帳日期',
    T0.DocDueDate                     AS N'交貨日期',
    T0.CardCode                       AS N'供應商代碼',
    T0.CardName                       AS N'供應商名稱',
    T1.LineNum + 1                    AS N'列號',
    T1.ItemCode                       AS N'物料號碼',
    T1.Dscription                     AS N'物料說明',
    T1.Quantity                       AS N'訂購數量',
    T1.OpenQty                        AS N'未交數量',
    T1.Price                          AS N'單價',
    T1.LineTotal                      AS N'未稅金額',
    T1.WhsCode                        AS N'倉庫',
    CASE T0.CANCELED
        WHEN 'N' THEN N'未取消'
        WHEN 'Y' THEN N'已取消'
    END                               AS N'取消狀態',
    CASE T0.DocStatus
        WHEN 'O' THEN N'未結'
        WHEN 'C' THEN N'已結'
    END                               AS N'文件狀態'
FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry
WHERE
    (
        '[%0]' = ''
        OR T1.ItemCode LIKE N'%' + '[%0]' + N'%'
        OR T1.Dscription LIKE N'%' + '[%0]' + N'%'
    )
    AND
    (
        '[%1]' = ''
        OR T0.CardCode LIKE N'%' + '[%1]' + N'%'
        OR T0.CardName LIKE N'%' + '[%1]' + N'%'
    )
    AND
    (
        '[%2]' = ''
        OR T0.CANCELED = '[%2]'
    )
ORDER BY
    T0.DocDate DESC,
    T0.DocNum DESC,
    T1.LineNum
```

輸入方式：

1. `[%0]`：物料號碼或物料說明；不限制就留空。
2. `[%1]`：供應商代碼或供應商名稱；不限制就留空。
3. `[%2]`：取消狀態：
   - 輸入 `N`：只看未取消
   - 輸入 `Y`：只看已取消
   - 留空：取消與未取消都顯示

先測試時，三個條件全部留空，應該會列出所有採購訂單。如果仍然完全沒有資料，先執行這個最小測試：

```sql
SELECT TOP 100
    T0.DocNum,
    T0.CardCode,
    T0.CardName,
    T0.CANCELED,
    T1.ItemCode,
    T1.Dscription
FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry
ORDER BY T0.DocEntry DESC
```

如果最小測試有資料，代表問題是在參數篩選；如果沒有資料，則要確認目前登入的公司資料庫是否確實有採購訂單。

另外，如果你執行的位置真的是「格式化搜尋 FMS」，而不是「查詢管理員」，`[%0]` 這類人工輸入參數不適用；FMS 必須改用 `$[$欄位UID.欄位.類型]` 讀取畫面欄位。

### 4. 如果我三個為空值 是有資料

來源：[S061-Q004](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q4>)；2026-08-10

**問題**

如果我三個為空值 是有資料

**歷史回答**

這表示資料表與 JOIN 都正常，問題是在「輸入值與篩選條件不相符」。

特別注意取消狀態不能輸入「是／否」或「已取消／未取消」，原查詢只能輸入資料庫代碼：

- `N`：未取消
- `Y`：原單據已取消
- `C`：取消單據（部分 SAP B1 版本會出現）
- 空白：全部

建議把條件改成可接受中文，並清除前後空白：

```sql
AND (
       LTRIM(RTRIM('[%2]')) IN ('', N'全部', 'A')
    OR (
           LTRIM(RTRIM('[%2]')) IN ('N', N'未取消')
       AND T0.CANCELED = 'N'
    )
    OR (
           LTRIM(RTRIM('[%2]')) IN ('Y', N'已取消')
       AND T0.CANCELED = 'Y'
    )
    OR (
           LTRIM(RTRIM('[%2]')) IN ('C', N'取消單據')
       AND T0.CANCELED = 'C'
    )
)
```

完整的 `WHERE` 可改成：

```sql
WHERE
    (
        LTRIM(RTRIM('[%0]')) = ''
        OR ISNULL(T1.ItemCode, '') LIKE N'%' + LTRIM(RTRIM('[%0]')) + N'%'
        OR ISNULL(T1.Dscription, '') LIKE N'%' + LTRIM(RTRIM('[%0]')) + N'%'
    )
    AND
    (
        LTRIM(RTRIM('[%1]')) = ''
        OR ISNULL(T0.CardCode, '') LIKE N'%' + LTRIM(RTRIM('[%1]')) + N'%'
        OR ISNULL(T0.CardName, '') LIKE N'%' + LTRIM(RTRIM('[%1]')) + N'%'
    )
    AND
    (
           LTRIM(RTRIM('[%2]')) IN ('', N'全部', 'A')
        OR (
               LTRIM(RTRIM('[%2]')) IN ('N', N'未取消')
           AND T0.CANCELED = 'N'
        )
        OR (
               LTRIM(RTRIM('[%2]')) IN ('Y', N'已取消')
           AND T0.CANCELED = 'Y'
        )
        OR (
               LTRIM(RTRIM('[%2]')) IN ('C', N'取消單據')
           AND T0.CANCELED = 'C'
        )
    )
```

測試時依序進行：

1. 只輸入物料，其他留空。
2. 只輸入供應商，其他留空。
3. 前兩個留空，取消狀態輸入 `N`。
4. 前兩個留空，取消狀態輸入 `Y`。

另外，物料與供應商之間目前使用 `AND`。如果兩個都有輸入，代表必須是「這個供應商的這個物料」才會顯示；不是任一條件符合就顯示。

### 5. 但只要有填資料進去 就會沒有資料

來源：[S061-Q005](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q5>)；2026-08-10

**問題**

但只要有填資料進去 就會沒有資料

**歷史回答**

既然三個空白有資料，但任何欄位一輸入就沒有，表示 SAP B1 傳入的參數值可能不是我們預期的內容。先不要繼續改主查詢，請執行以下診斷查詢：

```sql
SELECT
    N'>' + '[%0]' + N'<' AS N'物料輸入值',
    LEN('[%0]')           AS N'物料字數',
    N'>' + '[%1]' + N'<' AS N'供應商輸入值',
    LEN('[%1]')           AS N'供應商字數',
    N'>' + '[%2]' + N'<' AS N'取消狀態輸入值',
    LEN('[%2]')           AS N'狀態字數'
```

例如只在第一個欄位輸入一個確定存在的物料號碼，看看查詢結果顯示什麼。

也可以用下面這個最簡單版本分別測試。

物料測試：

```sql
SELECT TOP 100
    T1.ItemCode,
    T1.Dscription,
    T0.DocNum
FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry
WHERE T1.ItemCode = '[%0]'
```

供應商測試：

```sql
SELECT TOP 100
    T0.CardCode,
    T0.CardName,
    T0.DocNum
FROM OPOR T0
WHERE T0.CardCode = '[%0]'
```

取消狀態測試：

```sql
SELECT
    T0.CANCELED,
    COUNT(*) AS N'單據數量'
FROM OPOR T0
GROUP BY T0.CANCELED
```

最後一個查詢不需要輸入參數，可以確認你的資料庫實際存在的狀態，例如：

| CANCELED | 意義 |
|---|---|
| N | 未取消 |
| Y | 已取消 |
| C | 取消單據 |

另外有一個關鍵點：如果你確實是在「格式化搜尋 FMS」執行，而不是「查詢管理員」，就不能用 `[%0]`、`[%1]`、`[%2]` 作為畫面欄位值。FMS 應使用像這樣的欄位變數：

```sql
$[$4.0.0]
```

### 6. 可以再給我一份，我想要篩選 業務主檔 或 物料

來源：[S061-Q006](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q6>)；2026-08-10

**問題**

可以再給我一份，我想要篩選 業務主檔 或 物料

    T1.ItemCode                       AS N'物料號碼',
    T1.Dscription                     AS N'物料說明',
    T1.Quantity                       AS N'訂購數量',
    T1.OpenQty                        AS N'未交數量',
    T1.Price                          AS N'單價',
    T1.LineTotal                      AS N'未稅金額',
    T1.WhsCode                        AS N'倉庫',

    CASE T0.CANCELED
        WHEN 'N' THEN N'未取消'
        WHEN 'Y' THEN N'已取消'
        WHEN 'C' THEN N'取消單據'
        ELSE T0.CANCELED
    END                               AS N'取消狀態',

    CASE T0.DocStatus
        WHEN 'O' THEN N'未結'
        WHEN 'C' THEN N'已結'
        ELSE T0.DocStatus
    END                               AS N'文件狀態'

FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry

WHERE
    (
        '[%0]' = ''
        OR T0.CardCode LIKE N'%[%0]%'
        OR T0.CardName LIKE N'%[%0]%'
        OR T1.ItemCode LIKE N'%[%0]%'
        OR T1.Dscription LIKE N'%[%0]%'
    )
    AND
    (
        '[%1]' = ''
        OR '[%1]' = N'全部'
        OR T0.CANCELED = '[%1]'
    )

ORDER BY
    T0.DocDate DESC,
    T0.DocNum DESC,
    T1.LineNum
```

輸入方式：

- `[%0]` 搜尋關鍵字：

```text
[%0]：A0001
[%1]：N
```

這份是「查詢管理員」使用的查詢；若是綁定畫面欄位的格式化搜尋 FMS，則不能使用 `[%0]` 輸入視窗。

### 10. 你要寫兩個Where 一個是條件A，條件B空白 一個是條件B，條件A空白啊

**問題**

了解，你要的是互斥條件：

- 條件 A（業務夥伴）有值時，條件 B（物料）必須空白。
- 條件 B（物料）有值時，條件 A（業務夥伴）必須空白。

同一個 `SELECT` 不能寫兩次 `WHERE`，要在 `WHERE` 裡寫兩組條件，再用 `OR` 連接：

```sql

    T0.DocNum             AS N'採購單號',
    T0.DocDate            AS N'過帳日期',
    T0.DocDueDate         AS N'交貨日期',
    T0.CardCode           AS N'供應商代碼',
    T0.CardName           AS N'供應商名稱',
    T1.LineNum + 1        AS N'列號',
    T1.ItemCode           AS N'物料號碼',
    T1.Dscription         AS N'物料說明',
    T1.Quantity           AS N'訂購數量',
    T1.OpenQty            AS N'未交數量',
    T1.Price              AS N'單價',
    T1.LineTotal          AS N'未稅金額',
    T1.WhsCode            AS N'倉庫',

    CASE T0.CANCELED
        WHEN 'N' THEN N'未取消'
        WHEN 'Y' THEN N'已取消'
        WHEN 'C' THEN N'取消單據'
        ELSE T0.CANCELED
    END                   AS N'取消狀態'

FROM OPOR T0
INNER JOIN POR1 T1
    ON T0.DocEntry = T1.DocEntry

WHERE
    (
        /* 條件A有值、條件B空白：依供應商搜尋 */
        '[%0]' <> ''
        AND '[%1]' = ''
        AND T0.CardCode = '[%0]'
    )
    OR
    (
        /* 條件B有值、條件A空白：依物料搜尋 */
        '[%1]' <> ''
        AND '[%0]' = ''
        AND T1.ItemCode = '[%1]'
    )

ORDER BY
    T0.DocDate DESC,
    T0.DocNum DESC,
    T1.LineNum
```

參數：

- `[%0]`：條件 A，供應商代碼。
- `[%1]`：條件 B，物料號碼。

使用方式：

| `[%0]` 供應商 | `[%1]` 物料 | 結果 |
|---|---|---|
| 有值 | 空白 | 依供應商搜尋 |
| 空白 | 有值 | 依物料搜尋 |
| 有值 | 有值 | 不顯示資料 |
| 空白 | 空白 | 不顯示資料 |

如果希望兩個都空白時顯示全部，再於 `WHERE` 最後加入：

```sql
    OR
    (
        '[%0]' = ''
        AND '[%1]' = ''
    )
```

如果要模糊搜尋，把兩個完全比對條件改成：

```sql
AND (
       T0.CardCode LIKE N'%[%0]%'
    OR T0.CardName LIKE N'%[%0]%'
)
```

以及：

```sql
AND (
       T1.ItemCode LIKE N'%[%1]%'
    OR T1.Dscription LIKE N'%[%1]%'
)
```

    N'過帳日期' DESC,
    N'採購單號' DESC,
    N'列號'
```

輸入規則：

- 依供應商查詢：
  - `[%0]` 輸入完整的 `CardCode`
  - `[%1]` 必須留空

- 依物料查詢：
  - `[%0]` 必須留空
  - `[%1]` 輸入完整的 `ItemCode`

如果空白參數實際上會被 FMS 傳入空格，改用這個版本的空白判斷：

```sql
LTRIM(RTRIM(ISNULL('[%1]', ''))) = ''
```

以及：

```sql
LTRIM(RTRIM(ISNULL('[%0]', ''))) = ''
```

也就是第一個 `WHERE` 攓成：

```sql
WHERE T0.CardCode = LTRIM(RTRIM('[%0]'))
  AND LTRIM(RTRIM(ISNULL('[%1]', ''))) = ''
```

第二個改成：

```sql
WHERE T1.ItemCode = LTRIM(RTRIM('[%1]'))
  AND LTRIM(RTRIM(ISNULL('[%0]', ''))) = ''
```

如果這份仍然沒有資料，問題就不是 `WHERE` 邏輯，而是目前執行環境沒有把 `[%0]`、`[%1]` 替換成輸入值；這在真正的 FMS 或後端排程 `OBSJ` 中很常見，因為這兩種執行方式不能使用互動式參數。

### 12. 我可不可以 在ssms 存 這隻查訊報表的邏輯然後我再fms 呼叫這隻存取程序

來源：[S061-Q012](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q12>)；2026-08-10

**問題**

我可不可以 在ssms 存 這隻查訊報表的邏輯然後我再fms 呼叫這隻存取程序

**歷史回答**

可以把查詢邏輯存進 SSMS，但如果要由 SAP B1 原生 FMS 呼叫，我更建議使用「資料表值函數（Table-Valued Function）」而不是預存程序。因為 FMS 本質上是用查詢結果回填欄位，`SELECT FROM 函數` 通常比 `EXEC 預存程序` 穩定。

## 方案一：建立資料表值函數

先在 SSMS 選擇正確的 SAP 公司資料庫，再執行：

```sql
CREATE OR ALTER FUNCTION dbo.Z_FN_OPOR_SEARCH
(
    @CardCode NVARCHAR(15),
    @ItemCode NVARCHAR(50),
    @Canceled NVARCHAR(1)
)
RETURNS TABLE
AS
RETURN
(
    SELECT
        T0.DocEntry,
        T0.DocNum,
        T0.DocDate,
        T0.DocDueDate,
        T0.CardCode,
        T0.CardName,
        T1.LineNum,
        T1.ItemCode,
        T1.Dscription,
        T1.Quantity,
        T1.OpenQty,
        T1.Price,
        T1.LineTotal,
        T1.WhsCode,
        T0.CANCELED,
        T0.DocStatus
    FROM OPOR T0
    INNER JOIN POR1 T1
        ON T0.DocEntry = T1.DocEntry
    WHERE
        (
            /* 條件A：供應商有值、物料空白 */
            (
                NULLIF(LTRIM(RTRIM(@CardCode)), '') IS NOT NULL
                AND NULLIF(LTRIM(RTRIM(@ItemCode)), '') IS NULL
                AND T0.CardCode = LTRIM(RTRIM(@CardCode))
            )

            OR

            /* 條件B：物料有值、供應商空白 */
            (
                NULLIF(LTRIM(RTRIM(@ItemCode)), '') IS NOT NULL
                AND NULLIF(LTRIM(RTRIM(@CardCode)), '') IS NULL
                AND T1.ItemCode = LTRIM(RTRIM(@ItemCode))
            )
        )
        AND
        (
            NULLIF(LTRIM(RTRIM(@Canceled)), '') IS NULL
            OR T0.CANCELED = UPPER(LTRIM(RTRIM(@Canceled)))
        )
);
```

在 SSMS 先測試供應商：

```sql
SELECT *
FROM dbo.Z_FN_OPOR_SEARCH
(
    N'供應商代碼',
    N'',
    N''
)
ORDER BY DocDate DESC, DocNum DESC, LineNum
```

測試物料：

```sql
SELECT *
FROM dbo.Z_FN_OPOR_SEARCH
(
    N'',
    N'物料號碼',
    N''
)
ORDER BY DocDate DESC, DocNum DESC, LineNum
```

務必用實際的 `CardCode` 與 `ItemCode` 取代範例文字。如果 SSMS 測試有資料，就代表核心查詢邏輯正確。

## 在查詢管理員呼叫

```sql
SELECT
    DocNum                         AS N'採購單號',
    DocDate                        AS N'過帳日期',
    DocDueDate                     AS N'交貨日期',
    CardCode                       AS N'供應商代碼',
    CardName                       AS N'供應商名稱',
    LineNum + 1                    AS N'列號',
    ItemCode                       AS N'物料號碼',
    Dscription                     AS N'物料說明',
    Quantity                       AS N'訂購數量',
    OpenQty                        AS N'未交數量',
    Price                          AS N'單價',
    LineTotal                      AS N'未稅金額',
    WhsCode                        AS N'倉庫',
    CANCELED                       AS N'取消狀態'
FROM dbo.Z_FN_OPOR_SEARCH
(
    '[%0]',
    '[%1]',
    '[%2]'
)

```

參數：

- `[%0]`：供應商代碼
- `[%1]`：物料號碼
- `[%2]`：`N`、`Y`、`C`，留空代表全部

`[%0]` 和 `[%1]` 只能擇一填寫。

## 如果是真正的 FMS

原生 FMS 不適合顯示這種多欄、多筆報表。它主要是把查詢結果帶回目前畫面的一個欄位；SAP 官方也將格式化搜尋描述為把預先定義搜尋取得的值指派到欄位。[SAP Formatted Searches 說明](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/SAPbobsCOM~FormattedSearches.html)

若只是要回傳目前供應商最近一張採購單號，可以這樣呼叫函數：

```sql
SELECT TOP 1
    DocNum
FROM dbo.Z_FN_OPOR_SEARCH
(
    $[$4.0.0],
    '',
    ''
)
ORDER BY DocDate DESC, DocNum DESC
```

如果需要多筆報表，應由「查詢管理員」執行，不是綁在單一欄位的 FMS。

SAP 官方確實有「從 SAP Business One 查詢呼叫預存程序」的做法，但範例需要額外建立 UDT/UDF 來傳遞參數，設定比函數複雜。[SAP 官方 Stored Procedure 指南](https://help.sap.com/doc/012002523100020233302014e/9.1/en-US/GL_CUST_B1_StoredProc_91.pdf)

建立自訂函數或預存程序前，建議先備份公司資料庫，物件名稱使用 `Z_` 前綴，且不要修改 SAP 原有資料表或系統預存程序。

### 13. 我確定可以呼叫

來源：[S061-Q013](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q13>)；2026-08-10

**問題**

我確定可以呼叫

**歷史回答**

既然你的 FMS 確定可以呼叫預存程序，就把全部篩選邏輯放在 Stored Procedure，FMS 只負責傳入三個參數。

在 SSMS 的 SAP 公司資料庫建立：

```sql
CREATE OR ALTER PROCEDURE dbo.Z_SP_OPOR_SEARCH
(
    @CardCode NVARCHAR(50) = NULL,  -- 條件A：業務夥伴
    @ItemCode NVARCHAR(100) = NULL, -- 條件B：物料
    @Canceled NVARCHAR(10) = NULL   -- N、Y、C；空白為全部
)
AS
BEGIN
    SET NOCOUNT ON;

    /* 清除參數前後空白，空字串轉成 NULL */
    SET @CardCode = NULLIF(LTRIM(RTRIM(@CardCode)), '');
    SET @ItemCode = NULLIF(LTRIM(RTRIM(@ItemCode)), '');
    SET @Canceled = NULLIF(UPPER(LTRIM(RTRIM(@Canceled))), '');

    SELECT
        T0.DocEntry                       AS N'內部號碼',
        T0.DocNum                         AS N'採購單號',
        T0.DocDate                        AS N'過帳日期',
        T0.DocDueDate                     AS N'交貨日期',
        T0.CardCode                       AS N'供應商代碼',
        T0.CardName                       AS N'供應商名稱',
        T1.LineNum + 1                    AS N'列號',
        T1.ItemCode                       AS N'物料號碼',
        T1.Dscription                     AS N'物料說明',
        T1.Quantity                       AS N'訂購數量',
        T1.OpenQty                        AS N'未交數量',
        T1.Price                          AS N'單價',
        T1.LineTotal                      AS N'未稅金額',
        T1.WhsCode                        AS N'倉庫',

        CASE T0.CANCELED
            WHEN 'N' THEN N'未取消'
            WHEN 'Y' THEN N'已取消'
            WHEN 'C' THEN N'取消單據'
            ELSE T0.CANCELED
        END                               AS N'取消狀態',

        CASE T0.DocStatus
            WHEN 'O' THEN N'未結'
            WHEN 'C' THEN N'已結'
            ELSE T0.DocStatus
        END                               AS N'文件狀態'

    FROM OPOR T0
    INNER JOIN POR1 T1
        ON T0.DocEntry = T1.DocEntry

    WHERE
        (
            /* 條件A有值、條件B空白 */
            (
                @CardCode IS NOT NULL
                AND @ItemCode IS NULL
                AND T0.CardCode = @CardCode
            )

            OR

            /* 條件B有值、條件A空白 */
            (
                @ItemCode IS NOT NULL
                AND @CardCode IS NULL
                AND T1.ItemCode = @ItemCode
            )

            OR

            /* 條件A、B都空白：顯示全部 */
            (
                @CardCode IS NULL
                AND @ItemCode IS NULL
            )
        )

        /* 取消狀態 */
        AND
        (
            @Canceled IS NULL
            OR T0.CANCELED = @Canceled
        )

    ORDER BY
        T0.DocDate DESC,
        T0.DocNum DESC,
        T1.LineNum;
END;
```

在 SSMS 測試：

```sql
/* 依供應商 */
EXEC dbo.Z_SP_OPOR_SEARCH
    @CardCode = N'供應商代碼',
    @ItemCode = N'',
    @Canceled = N'';
```

```sql
/* 依物料 */
EXEC dbo.Z_SP_OPOR_SEARCH
    @CardCode = N'',
    @ItemCode = N'物料號碼',
    @Canceled = N'';
```

```sql
/* 不限制供應商及物料，只看未取消 */
EXEC dbo.Z_SP_OPOR_SEARCH
    @CardCode = N'',
    @ItemCode = N'',
    @Canceled = N'N';
```

FMS 呼叫：

```sql
EXEC dbo.Z_SP_OPOR_SEARCH
    @CardCode = '[%0]',
    @ItemCode = '[%1]',
    @Canceled = '[%2]'
```

如果 FMS 參數直接來自畫面欄位，則改成類似：

```sql
EXEC dbo.Z_SP_OPOR_SEARCH
    @CardCode = '$[$4.0.0]',
    @ItemCode = '$[$38.1.0]',
    @Canceled = ''
```

這份邏輯中，供應商與物料只能擇一輸入；兩者同時輸入時不會有結果。兩者都空白則顯示全部，再依取消狀態篩選。

### 17. 1). [Microsoft][ODBC Driver 18 for SQL Server][SQL Server]Must specify table to select fro…

來源：[S061-Q017](<../../原始問答/S061_新增採購物料與夥伴查詢報表.md#q17>)；2026-08-10

**問題**

1). [Microsoft][ODBC Driver 18 for SQL Server][SQL Server]Must specify table to select from. 2). [Microsoft][ODBC Driver 18 for SQL Server][SQL Server]Statement '收到的警示' (OAIB) (s) could not be prepared.

**歷史回答**

找到問題了：SAP B1 在預先解析 `DECLARE/SET` 時，註解式的 `/* SELECT ... */` 在你目前環境沒有被正確識別，所以 SQL Server 最後收到不完整的 `SELECT`。

改成真正執行的子查詢，不使用參數註解：

```sql
DECLARE @CardCode NVARCHAR(50)
DECLARE @ItemCode NVARCHAR(100)
DECLARE @Canceled NVARCHAR(10)

SET @CardCode =
(
    SELECT MIN(T0.CardCode)
    FROM OCRD T0
    WHERE T0.CardCode = '[%0]'
)

SET @ItemCode =
(
    SELECT MIN(T0.ItemCode)
    FROM OITM T0
    WHERE T0.ItemCode = '[%1]'
)

SET @Canceled =
(
    SELECT MIN(T0.CANCELED)
    FROM OPOR T0
    WHERE T0.CANCELED = '[%2]'
)

EXECUTE [_CmSp_OPOR_Search]
    @CardCode,
    @ItemCode,
    @Canceled
```

這種寫法的效果是：

- `[%0]` 有正確供應商代碼：`@CardCode` 取得該代碼。
- `[%0]` 空白：查不到資料，`@CardCode` 自動變成 `NULL`。
- `[%1]` 有正確物料號碼：`@ItemCode` 取得該物料。
- `[%1]` 空白：`@ItemCode` 自動變成 `NULL`。
- `[%2]` 空白：`@Canceled` 自動變成 `NULL`。

更精簡的版本：

```sql
DECLARE @CardCode NVARCHAR(50)
DECLARE @ItemCode NVARCHAR(100)
DECLARE @Canceled NVARCHAR(10)

SET @CardCode=(SELECT MIN(CardCode) FROM OCRD WHERE CardCode='[%0]')
SET @ItemCode=(SELECT MIN(ItemCode) FROM OITM WHERE ItemCode='[%1]')
SET @Canceled=(SELECT MIN(CANCELED) FROM OPOR WHERE CANCELED='[%2]')

EXECUTE [_CmSp_OPOR_Search] @CardCode, @ItemCode, @Canceled
```

請輸入完整代碼：

- `[%0]` 必須是 `OCRD.CardCode`，不是供應商名稱。
- `[%1]` 必須是 `OITM.ItemCode`，不是物料說明。
- `[%2]` 輸入 `N`、`Y` 或 `C`。

這是針對 `Must specify table to select from` 常用的 SAP B1 SQL Server處理方式：讓每個參數都來自一個真正、完整且有 `FROM` 的子查詢。

了解，你的環境可以使用這種「單一參數＋註解 SELECT」格式。為避免多個 `[%0]、[%1]、[%2]` 導致 SAP B1 預解析失敗，我們沿用你的成功範例：每一支 B1 查詢只接收一個參數。

- `@PARAM`：供應商代碼或物料號碼
- `@TYPE`：固定傳入 `CARD` 或 `ITEM`

## SSMS：建立 Stored Procedure

```sql
CREATE OR ALTER PROCEDURE [_CmSp_OPOR_Search]
    @PARAM NVARCHAR(100),
    @TYPE  NVARCHAR(10)
AS
BEGIN
    SET NOCOUNT ON;

    SELECT
        T0.DocEntry                       AS N'內部號碼',
        T0.DocNum                         AS N'採購單號',
        T0.DocDate                        AS N'過帳日期',
        T0.DocDueDate                     AS N'交貨日期',
        T0.CardCode                       AS N'供應商代碼',
        T0.CardName                       AS N'供應商名稱',
        T1.LineNum + 1                    AS N'列號',
        T1.ItemCode                       AS N'物料號碼',
        T1.Dscription                     AS N'物料說明',
        T1.Quantity                       AS N'訂購數量',
        T1.OpenQty                        AS N'未交數量',
        T1.Price                          AS N'單價',
        T1.LineTotal                      AS N'未稅金額',
        T1.WhsCode                        AS N'倉庫',

        CASE T0.CANCELED
            WHEN 'N' THEN N'未取消'
            WHEN 'Y' THEN N'已取消'
            WHEN 'C' THEN N'取消單據'
            ELSE T0.CANCELED
        END                               AS N'取消狀態',

        CASE T0.DocStatus
            WHEN 'O' THEN N'未結'
            WHEN 'C' THEN N'已結'
            ELSE T0.DocStatus
        END                               AS N'文件狀態'

    FROM OPOR T0
    INNER JOIN POR1 T1
        ON T0.DocEntry = T1.DocEntry

    WHERE
        (
            @TYPE = 'CARD'
            AND T0.CardCode = @PARAM
        )
        OR
        (
            @TYPE = 'ITEM'
            AND T1.ItemCode = @PARAM
        )

    ORDER BY
        T0.DocDate DESC,
        T0.DocNum DESC,
        T1.LineNum;
END
```

### 20. 沒有取消狀態 我的取消狀態 可以直接寫進去 我只找未結單據

**問題**

沒有取消狀態 我的取消狀態 可以直接寫進去 我只找未結單據

**歷史回答**

了解，不需要「取消狀態」參數，直接固定只查：

```sql
T0.CANCELED = 'N'
AND T0.DocStatus = 'O'
```

也就是「未取消、未結案」的採購訂單。

## SSMS：Stored Procedure

```sql
CREATE OR ALTER PROCEDURE [_CmSp_OPOR_Search]
    @CardCode NVARCHAR(50),
    @ItemCode NVARCHAR(100)
AS
BEGIN
    SET NOCOUNT ON;

    /* 空字串轉成 NULL */
    SET @CardCode = NULLIF(LTRIM(RTRIM(@CardCode)), '');
    SET @ItemCode = NULLIF(LTRIM(RTRIM(@ItemCode)), '');

    SELECT
        T0.DocEntry                       AS N'內部號碼',
        T0.DocNum                         AS N'採購單號',
        T0.DocDate                        AS N'過帳日期',
        T0.DocDueDate                     AS N'交貨日期',
        T0.CardCode                       AS N'供應商代碼',
        T0.CardName                       AS N'供應商名稱',
        T1.LineNum + 1                    AS N'列號',
        T1.ItemCode                       AS N'物料號碼',
        T1.Dscription                     AS N'物料說明',
        T1.Quantity                       AS N'訂購數量',
        T1.OpenQty                        AS N'未交數量',
        T1.Price                          AS N'單價',
        T1.LineTotal                      AS N'未稅金額',
        T1.WhsCode                        AS N'倉庫',

        CASE T1.LineStatus
            WHEN 'O' THEN N'未結'
            WHEN 'C' THEN N'已結'
            ELSE T1.LineStatus
        END                               AS N'明細狀態'

    FROM OPOR T0
    INNER JOIN POR1 T1
        ON T0.DocEntry = T1.DocEntry

    WHERE
        /* 固定只找未取消單據 */
        T0.CANCELED = 'N'

        /* 固定只找未結採購訂單 */
        AND T0.DocStatus = 'O'

        /* 供應商條件；空白時不篩選 */
        AND (
            @CardCode IS NULL
            OR T0.CardCode = @CardCode
        )

        /* 物料條件；空白時不篩選 */
        AND (
            @ItemCode IS NULL
            OR T1.ItemCode = @ItemCode
        )

    ORDER BY
        T0.DocDate DESC,
        T0.DocNum DESC,
        T1.LineNum;
END
```

這次不要使用註解式 `/* SELECT 1... */`，改用完整子查詢，避免再次出現 `Must specify table to select from`：

```sql

```

篩選邏輯：

| `[%0]` 供應商 | `[%1]` 物料 | 結果 |
|---|---|---|
| 有值 | 空白 | 該供應商的未結採購訂單 |
| 空白 | 有值 | 該物料的未結採購訂單 |
| 有值 | 有值 | 該供應商且包含該物料 |
| 空白 | 空白 | 全部未結採購訂單 |

### 23. SAPB1 的我記得是OPOR

來源：[S068-Q002](<../../原始問答/S068_建立未結採購單查詢報表.md#q2>)；2026-08-11

**問題**

SAPB1 的我記得是OPOR

**歷史回答**

對，SAP Business One：

- `OPOR`：採購單表頭
- `POR1`：採購單明細
- `OPDN`：收貨採購單表頭
- `PDN1`：收貨採購單明細

採購流程中的「交貨／收貨單」通常是 `OPDN/PDN1`；`ODLN/DLN1` 是銷售交貨單，不適合接採購單。

以未結採購明細為核心，可這樣寫：

```sql
SELECT
    PO.DocEntry                        AS 採購單內碼,
    PO.DocNum                          AS 採購單號,
    PO.DocDate                         AS 採購日期,
    PO.DocDueDate                      AS 採購到期日,
    PO.CardCode                        AS 供應商代碼,
    PO.CardName                        AS 供應商名稱,

    POL.LineNum + 1                    AS 採購項次,
    POL.ItemCode                       AS 品號,
    POL.Dscription                     AS 品名,
    POL.Quantity                       AS 採購數量,
    POL.OpenQty                        AS 未交數量,
    POL.Price                          AS 單價,
    POL.WhsCode                        AS 倉庫代碼,

    GRPO.DocNum                        AS 收貨單號,
    GRPO.DocDate                       AS 收貨日期,
    GRPO.NumAtCard                     AS 廠商交貨單號,
    GRPO_LINE.Quantity                 AS 本次收貨數量

FROM OPOR PO

INNER JOIN POR1 POL
    ON POL.DocEntry = PO.DocEntry

LEFT JOIN (
    PDN1 GRPO_LINE
    INNER JOIN OPDN GRPO
        ON GRPO.DocEntry = GRPO_LINE.DocEntry
       AND GRPO.CANCELED = 'N'
)
    ON GRPO_LINE.BaseType  = 22
   AND GRPO_LINE.BaseEntry = POL.DocEntry
   AND GRPO_LINE.BaseLine  = POL.LineNum

WHERE PO.CANCELED = 'N'
  AND POL.LineStatus = 'O'
  AND POL.OpenQty > 0

ORDER BY
    PO.DocNum,
    POL.LineNum,
    GRPO.DocDate,
    GRPO.DocNum;
```

關聯邏輯是：

```text
OPOR.DocEntry = POR1.DocEntry

PDN1.BaseType  = 22
PDN1.BaseEntry = POR1.DocEntry
PDN1.BaseLine  = POR1.LineNum
```

其中 `22` 是採購單的物件類型。

這份查詢會保留所有未結採購明細：

- 尚未收過貨：收貨單欄位為 `NULL`
- 部分收貨：顯示相關收貨單，`POR1.OpenQty` 顯示剩餘數量
- 同一採購項次分批收貨：會產生多列，每張收貨單一列

### 25. 會讓沒有收貨單的未結採購項目被排除， 這句不懂

來源：[S068-Q004](<../../原始問答/S068_建立未結採購單查詢報表.md#q4>)；2026-08-11

**問題**

會讓沒有收貨單的未結採購項目被排除， 這句不懂

**歷史回答**

因為沒有收貨單時，`T3` 的所有欄位都會是 `NULL`。

假設有兩筆未結採購單：

| 採購單 | 收貨單 | T3.CANCELED |
|---|---|---|
| PO001 | GR001 | N |
| PO002 | 尚未收貨 | NULL |

如果把條件寫在 `WHERE`：

```sql
WHERE T3.CANCELED = 'N'
```

資料庫會檢查：

```text
PO001：N = N       → 成立，保留
PO002：NULL = N    → 不成立，排除
```

所以原本應該顯示的 `PO002`，會因為尚無收貨單而消失。此時效果就接近 `INNER JOIN`。

正確方式是放在 `LEFT JOIN`：

```sql
LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry
   AND T3.CANCELED = 'N'
```

意思是：「只連接未取消的收貨單；即使連不到，左邊的未結採購單仍然保留。」

若一定要寫在 `WHERE`，則必須允許 `NULL`：

```sql
WHERE (T3.CANCELED = 'N' OR T3.DocEntry IS NULL)
```

不過 SAP B1 查詢通常直接把條件寫在 `LEFT JOIN ... ON` 裡最清楚。

### 26. 我不能直接抓採購單是未結就好嗎

來源：[S068-Q005](<../../原始問答/S068_建立未結採購單查詢報表.md#q5>)；2026-08-11

**問題**

我不能直接抓採購單是未結就好嗎

**歷史回答**

可以，完全可以。若你的目的只是抓「目前未結的採購單明細」，直接判斷 `POR1` 就好，不需要用收貨單判斷未結。

```sql
SELECT
    T0.DocNum        AS '採購單號',
    T0.DocDate       AS '採購日期',
    T0.CardCode      AS '供應商代碼',
    T0.CardName      AS '供應商名稱',
    T1.LineNum + 1   AS '項次',
    T1.ItemCode      AS '品號',
    T1.Dscription    AS '品名',
    T1.Quantity      AS '採購數量',
    T1.OpenQty       AS '未交數量'
FROM OPOR T0
INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry
WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0
ORDER BY T0.DocNum, T1.LineNum
```

核心條件是：

```sql
T1.LineStatus = 'O'
```

代表採購單明細尚未結清。`T1.OpenQty > 0` 是再確認仍有未交數量。

如果還要顯示已經產生的收貨單，再單純加上：

```sql
LEFT JOIN PDN1 T2
    ON T2.BaseType  = 22
   AND T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry
```

然後原本的未結條件保持不變：

```sql
WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0
```

也就是：

- 是否未結：由 `POR1.LineStatus/OpenQty` 判斷
- 收貨單：只是拿來補充顯示
- 收貨單不存在：未結採購項目仍然會顯示

這正是「未結採購單為核心，收貨單 LEFT JOIN」的做法。

### 27. 如果我想 退回數量

來源：[S068-Q006](<../../原始問答/S068_建立未結採購單查詢報表.md#q6>)；2026-08-11

**問題**

如果我想 退回數量

**歷史回答**

如果要抓「採購收貨後的退貨數量」，SAP B1 使用：

- `ORPD`：採購退貨表頭（Goods Return）
- `RPD1`：採購退貨明細
- `BaseType = 20`：來源是收貨採購單 `OPDN/PDN1`

接法是：

```sql
LEFT JOIN PDN1 T2
    ON T2.BaseType  = 22
   AND T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry

LEFT JOIN RPD1 T4
    ON T4.BaseType  = 20
   AND T4.BaseEntry = T2.DocEntry
   AND T4.BaseLine  = T2.LineNum

LEFT JOIN ORPD T5
    ON T5.DocEntry = T4.DocEntry
```

在 `SELECT` 加入：

```sql
T3.DocNum AS '收貨單號',
T2.Quantity AS '收貨數量',

T5.DocNum AS '退貨單號',
CASE
    WHEN T5.CANCELED = 'N' THEN T4.Quantity
    ELSE 0
END AS '退回數量'
```

完整關聯流程：

```text
採購單 OPOR/POR1
       ↓ BaseType = 22
收貨單 OPDN/PDN1
       ↓ BaseType = 20
退貨單 ORPD/RPD1
```

如果同一採購項次有多張收貨單或退貨單，查詢會顯示多列。若報表只想顯示「每個採購項次一列」，退回數量需要彙總：

```sql
SUM(
    CASE
        WHEN T5.CANCELED = 'N' THEN T4.Quantity
        ELSE 0
    END
) AS '退回數量'
```

但使用 `SUM()` 後，其他欄位必須搭配 `GROUP BY`。另外，`POR1.OpenQty` 是否因退貨而重新開啟，會受到 SAP B1「退貨時重新開啟基礎文件」設定影響；若要看實際退貨歷史，仍以 `RPD1.Quantity` 為準。

### 28. 好 那你給我 各別兩種模式 有加總跟沒有加總

來源：[S068-Q007](<../../原始問答/S068_建立未結採購單查詢報表.md#q7>)；2026-08-11

**問題**

好 那你給我 各別兩種模式 有加總跟沒有加總

**歷史回答**

下面分成兩種：明細模式會列出每張收貨／退貨單；加總模式則每個採購項次只顯示一列。

## 1. 沒有加總：逐張收貨單、退貨單顯示

```sql
SELECT
    T0.DocNum                    AS '採購單號',
    T0.DocDate                   AS '採購日期',
    T0.DocDueDate                AS '採購到期日',
    T0.CardCode                  AS '供應商代碼',
    T0.CardName                  AS '供應商名稱',

    T1.LineNum + 1               AS '採購項次',
    T1.ItemCode                  AS '品號',
    T1.Dscription                AS '品名',
    T1.Quantity                  AS '採購數量',
    T1.OpenQty                   AS '目前未結數量',
    T1.WhsCode                   AS '倉庫',

    T3.DocNum                    AS '收貨單號',
    T3.DocDate                   AS '收貨日期',
    T3.NumAtCard                 AS '廠商交貨單號',
    ISNULL(T2.Quantity, 0)       AS '收貨數量',

    T5.DocNum                    AS '退貨單號',
    T5.DocDate                   AS '退貨日期',
    ISNULL(T4.Quantity, 0)       AS '退回數量'

FROM OPOR T0

INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry

LEFT JOIN PDN1 T2
    ON T2.BaseType  = 22
   AND T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry

LEFT JOIN RPD1 T4
    ON T4.BaseType  = 20
   AND T4.BaseEntry = T2.DocEntry
   AND T4.BaseLine  = T2.LineNum

LEFT JOIN ORPD T5
    ON T5.DocEntry = T4.DocEntry

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

  -- 排除取消的收貨單，但保留完全沒有收貨單的採購項目
  AND (T3.CANCELED = 'N' OR T2.DocEntry IS NULL)

  -- 排除取消的退貨單，但保留完全沒有退貨單的收貨項目
  AND (T5.CANCELED = 'N' OR T4.DocEntry IS NULL)

ORDER BY
    T0.DocNum,
    T1.LineNum,
    T3.DocDate,
    T3.DocNum,
    T5.DocDate,
    T5.DocNum
```

這個模式可能出現：

```text
PO001 第1項 → 收貨單 GR001 → 退貨單 RT001
PO001 第1項 → 收貨單 GR002 → 無退貨
```

## 2. 有加總：每個採購項次一列

這個版本分開計算收貨量與退貨量，避免同一張收貨單有多張退貨單時，把收貨數量重複加總。

```sql
SELECT
    T0.DocNum                    AS '採購單號',
    T0.DocDate                   AS '採購日期',
    T0.DocDueDate                AS '採購到期日',
    T0.CardCode                  AS '供應商代碼',
    T0.CardName                  AS '供應商名稱',

    T1.LineNum + 1               AS '採購項次',
    T1.ItemCode                  AS '品號',
    T1.Dscription                AS '品名',
    T1.Quantity                  AS '採購數量',
    T1.OpenQty                   AS '目前未結數量',
    T1.WhsCode                   AS '倉庫',

    ISNULL((
        SELECT SUM(PDN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0) AS '累計收貨數量',

    ISNULL((
        SELECT SUM(RTN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        INNER JOIN RPD1 RTN
            ON RTN.BaseType  = 20
           AND RTN.BaseEntry = PDN.DocEntry
           AND RTN.BaseLine  = PDN.LineNum
        INNER JOIN ORPD GR_RETURN
            ON GR_RETURN.DocEntry = RTN.DocEntry
           AND GR_RETURN.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0) AS '累計退回數量',

    ISNULL((
        SELECT SUM(PDN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0)
    -
    ISNULL((
        SELECT SUM(RTN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        INNER JOIN RPD1 RTN
            ON RTN.BaseType  = 20
           AND RTN.BaseEntry = PDN.DocEntry
           AND RTN.BaseLine  = PDN.LineNum
        INNER JOIN ORPD GR_RETURN
            ON GR_RETURN.DocEntry = RTN.DocEntry
           AND GR_RETURN.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0) AS '收貨淨額數量'

FROM OPOR T0

INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

ORDER BY
    T0.DocNum,
    T1.LineNum
```

欄位意義：

```text
累計收貨數量 = 所有未取消的收貨採購單數量
累計退回數量 = 所有未取消的採購退貨數量
收貨淨額數量 = 累計收貨數量 − 累計退回數量
目前未結數量 = SAP POR1.OpenQty
```

`目前未結數量` 建議直接採用 SAP 的 `POR1.OpenQty`；不要自行用「採購量－收貨＋退貨」取代，因為手動關閉與「退貨後是否重新開啟基礎文件」設定都可能影響 SAP 的未結數量。

    T0.DocNum                                 AS [採購單號],
    T1.LineNum + 1                            AS [項],
    T0.CardCode                               AS [廠商],

    ON T1.DocEntry = T0.DocEntry

LEFT JOIN (

        A.BaseEntry,
        A.BaseLine,
        SUM(A.Quantity) AS 入庫數量
    FROM PDN1 A
    INNER JOIN OPDN B
        ON B.DocEntry = A.DocEntry
       AND B.CANCELED = 'N'
    WHERE A.BaseType = 22
    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T2
    ON T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

/* 累計退回數量 */
LEFT JOIN (
    SELECT
        A.BaseEntry,
        A.BaseLine,
        SUM(C.Quantity) AS 退回數量

    INNER JOIN OPDN B
        ON B.DocEntry = A.DocEntry
       AND B.CANCELED = 'N'
    INNER JOIN RPD1 C

       AND C.BaseEntry = A.DocEntry
       AND C.BaseLine  = A.LineNum
    INNER JOIN ORPD D
        ON D.DocEntry = C.DocEntry
       AND D.CANCELED = 'N'
    WHERE A.BaseType = 22
    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T3
    ON T3.BaseEntry = T1.DocEntry
   AND T3.BaseLine  = T1.LineNum

/* 採購單直接由請購單建立 */
LEFT JOIN PRQ1 T4
    ON T1.BaseType  = 1470000113
   AND T1.BaseEntry = T4.DocEntry

LEFT JOIN OPRQ T5
    ON T5.DocEntry = T4.DocEntry

LEFT JOIN OCRD T6
    ON T6.CardCode = T0.CardCode

LEFT JOIN OUSR T7
    ON T7.USERID = T0.UserSign

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

ORDER BY
    T1.ShipDate,
    T0.DocNum,
    T1.LineNum
```

注意：

- 圖片的「交貨日期」我先對應 `POR1.ShipDate`。

### 34. 如果已退數量跟已交數量 可以抓得出來嗎

來源：[S068-Q013](<../../原始問答/S068_建立未結採購單查詢報表.md#q13>)；2026-08-12

**問題**

如果已退數量跟已交數量 可以抓得出來嗎

**歷史回答**

可以抓出來。

定義建議：

```text
已交數量 = 未取消的收貨採購單 PDN1.Quantity 加總
已退數量 = 未取消的採購退貨單 RPD1.Quantity 加總
實收數量 = 已交數量－已退數量
```

查詢可以這樣寫：

```sql
SELECT
    T1.ShipDate                         AS [交貨日期],
    T0.DocNum                           AS [採購單號],
    T1.LineNum + 1                      AS [項],
    T0.CardCode                         AS [廠商],
    T0.CardName                         AS [廠商簡稱],
    T1.ItemCode                         AS [品料號],
    T1.unitMsr                          AS [單位],

    T1.Quantity                         AS [採購數量],
    ISNULL(T2.已交數量, 0)              AS [已交數量],
    ISNULL(T3.已退數量, 0)              AS [已退數量],

    ISNULL(T2.已交數量, 0)
        - ISNULL(T3.已退數量, 0)         AS [實收數量],

    T1.OpenQty                          AS [未交數量],
    T1.Price                            AS [採購單價],
    T1.OpenQty * T1.Price               AS [未交金額]

FROM OPOR T0

INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry

/* 已交數量：收貨採購單加總 */
LEFT JOIN (
    SELECT
        A.BaseEntry,
        A.BaseLine,
        SUM(A.Quantity) AS [已交數量]
    FROM PDN1 A
    INNER JOIN OPDN B
        ON B.DocEntry = A.DocEntry
       AND B.CANCELED = 'N'
    WHERE A.BaseType = 22
    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T2
    ON T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

/* 已退數量：採購退貨單加總 */
LEFT JOIN (
    SELECT
        A.BaseEntry,
        A.BaseLine,
        SUM(C.Quantity) AS [已退數量]
    FROM PDN1 A

    INNER JOIN OPDN B
        ON B.DocEntry = A.DocEntry
       AND B.CANCELED = 'N'

    INNER JOIN RPD1 C
        ON C.BaseType  = 20
       AND C.BaseEntry = A.DocEntry
       AND C.BaseLine  = A.LineNum

    INNER JOIN ORPD D
        ON D.DocEntry = C.DocEntry
       AND D.CANCELED = 'N'

    WHERE A.BaseType = 22

    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T3
    ON T3.BaseEntry = T1.DocEntry
   AND T3.BaseLine  = T1.LineNum

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

ORDER BY
    T1.ShipDate,
    T0.DocNum,
    T1.LineNum
```

例如：

```text
採購數量：100
已交數量：60
已退數量：10
實收數量：50
```

另外還有一個簡單寫法：

```sql
T1.Quantity - T1.OpenQty AS [已完成數量]
```

但這是 SAP 採購單目前的「已完成數量」，會受退貨後是否重新開啟採購單及手動關閉影響。若要準確呈現實際單據交易，應使用上面的 `PDN1` 與 `RPD1` 加總。

# Files mentioned by the user:

## codex-clipboard-39987e9b-80cc-4813-b00e-f97d3705bf58.png: C:/Users/nick_yeh/AppData/Local/Temp/codex-clipboard-39987e9b-80cc-4813-b00e-f97d3705bf58.png

## My request:
為甚麼會有這麼多小數位後的數字

[原對話含圖片，本文未嵌入圖片]

**歷史回答**

因為 SAP B1 的數量、價格欄位通常是 `DECIMAL(19,6)`，查詢結果會依資料庫精度顯示 6 位小數，例如：

```text
2000.000000
1.890000
```

這不是計算錯誤，只是顯示格式。可以在 `SELECT` 使用 `CAST` 控制小數位數。

建議格式：

- 數量：2 位小數
- 單價：4 位小數
- 金額：2 位小數

```sql
CAST(T1.Quantity AS DECIMAL(19,2)) AS [採購數量],

CAST(ISNULL(T2.已交數量, 0)
     AS DECIMAL(19,2))             AS [已交數量],

CAST(ISNULL(T3.已退數量, 0)
     AS DECIMAL(19,2))             AS [已退數量],

CAST(
    ISNULL(T2.已交數量, 0)
    - ISNULL(T3.已退數量, 0)
    AS DECIMAL(19,2)
)                                  AS [實收數量],

CAST(T1.OpenQty AS DECIMAL(19,2))  AS [未交數量],

CAST(T1.Price AS DECIMAL(19,4))    AS [採購單價],

CAST(
    T1.OpenQty * T1.Price
    AS DECIMAL(19,2)
)                                  AS [未交金額]
```

結果會變成：

```text
採購數量：2,000.00
採購單價：1.8900
未交金額：3,780.00
```

如果數量確定只能是整數，例如全部都是 `PCS`，可以改為零位小數：

```sql
CAST(T1.Quantity AS DECIMAL(19,0)) AS [採購數量]
```

不過若還有公斤、米等可能出現小數的單位，建議數量保留兩位：

```sql
DECIMAL(19,2)
```

不要使用 `FORMAT()`，因為它會把數字轉成文字，之後在 Excel 排序、加總可能不方便；`CAST(... AS DECIMAL)` 能維持數值格式。

       AND C.BaseEntry = A.DocEntry
       AND C.BaseLine  = A.LineNum

    INNER JOIN ORPD D
        ON D.DocEntry = C.DocEntry
       AND D.CANCELED = 'N'

    WHERE A.BaseType = 22

    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T3
    ON T3.BaseEntry = T1.DocEntry
   AND T3.BaseLine  = T1.LineNum

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

ORDER BY
    T1.ShipDate,
    T0.DocNum,
    T1.LineNum
```

### 40. 〔程式碼〕

來源：[S070-Q001](<../../原始問答/S070_解釋已交數量格式化語法.md#q1>)；2026-08-12

**問題**

```less
FORMAT(
        ISNULL(T2.DeliveredQty, 0),
        'N2',
        'en-US'
    )                                                AS [已交數量], 

甚麼意思
```

**歷史回答**

這段是 SQL Server 查詢，用來把「已交數量」格式化顯示：

```sql
FORMAT(
    ISNULL(T2.DeliveredQty, 0),
    'N2',
    'en-US'
) AS [已交數量]
```

意思如下：

- `T2.DeliveredQty`：取得已交數量。
- `ISNULL(..., 0)`：如果數值是 `NULL`，改成 `0`。
- `FORMAT(..., 'N2', 'en-US')`：以美式數字格式顯示，保留兩位小數並加千分位逗號。
- `AS [已交數量]`：把輸出欄位命名為「已交數量」。

例如：

| 原始值 | 輸出 |
|---:|---:|
| `1234.5` | `1,234.50` |
| `10` | `10.00` |
| `NULL` | `0.00` |

注意：`FORMAT()` 的結果是「文字」，不是數值。如果後續還要計算或排序，建議保留數值型別，例如：

```sql
CAST(ISNULL(T2.DeliveredQty, 0) AS decimal(18, 2)) AS [已交數量]
```

### 41. 我想再用一次cast

來源：[S068-Q019](<../../原始問答/S068_建立未結採購單查詢報表.md#q19>)；2026-08-12

**問題**

我想再用一次cast

**歷史回答**

可以，以下改回 `CAST()`，保留數值型態，匯出 Excel 可以直接加總。

```sql
SELECT
    T1.ShipDate                                   AS [交貨日期],
    T0.DocNum                                     AS [採購單號],
    T1.LineNum + 1                                AS [項],
    T0.CardCode                                   AS [廠商],
    T0.CardName                                   AS [廠商簡稱],
    T1.ItemCode                                   AS [品料號],
    T1.unitMsr                                    AS [單位],

    CAST(T1.Quantity AS DECIMAL(19,2))            AS [採購數量],

    CAST(
        ISNULL(T2.DeliveredQty, 0)
        AS DECIMAL(19,2)
    )                                             AS [已交數量],

    CAST(
        ISNULL(T3.ReturnedQty, 0)
        AS DECIMAL(19,2)
    )                                             AS [已退數量],

    CAST(
        ISNULL(T2.DeliveredQty, 0)
        - ISNULL(T3.ReturnedQty, 0)
        AS DECIMAL(19,2)
    )                                             AS [實收數量],

    CAST(T1.OpenQty AS DECIMAL(19,2))             AS [未交數量],

    CAST(T1.Price AS DECIMAL(19,4))               AS [採購單價],

    CAST(
        T1.OpenQty * T1.Price
        AS DECIMAL(19,2)
    )                                             AS [未交金額]

FROM OPOR T0

INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry

/* 已交數量：未取消的收貨採購單 */
LEFT JOIN (
    SELECT
        A.BaseEntry,
        A.BaseLine,
        SUM(A.Quantity) AS DeliveredQty
    FROM PDN1 A

    INNER JOIN OPDN B
        ON B.DocEntry = A.DocEntry
       AND B.CANCELED = 'N'

    WHERE A.BaseType = 22

    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T2
    ON T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

/* 已退數量：未取消的採購退貨單 */
LEFT JOIN (
    SELECT
        A.BaseEntry,
        A.BaseLine,
        SUM(C.Quantity) AS ReturnedQty
    FROM PDN1 A

    INNER JOIN OPDN B
        ON B.DocEntry = A.DocEntry
       AND B.CANCELED = 'N'

    INNER JOIN RPD1 C
        ON C.BaseType  = 20
       AND C.BaseEntry = A.DocEntry
       AND C.BaseLine  = A.LineNum

    INNER JOIN ORPD D
        ON D.DocEntry = C.DocEntry
       AND D.CANCELED = 'N'

    WHERE A.BaseType = 22

    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T3
    ON T3.BaseEntry = T1.DocEntry
   AND T3.BaseLine  = T1.LineNum

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

ORDER BY
    T1.ShipDate,
    T0.DocNum,
    T1.LineNum
```

這個版本設定：

```text
數量：2 位小數
採購單價：4 位小數
未交金額：2 位小數
```

如果 SAP B1 畫面仍顯示六位小數，代表查詢視窗使用系統顯示設定覆蓋了 `CAST`；但匯出到 Excel 時，欄位仍是可運算的數字。

### 42. 為甚麼匯出EXCEL 小數點會不一致

來源：[S068-Q020](<../../原始問答/S068_建立未結採購單查詢報表.md#q20>)；2026-08-12

**問題**

為甚麼匯出EXCEL 小數點會不一致

**歷史回答**

因為 Excel 的「數值」與「顯示格式」是兩件事。

例如下面三個值在 Excel 裡其實相同：

```text
180
180.00
180.000000
```

SQL 的 `CAST(... AS DECIMAL(19,2))` 可以控制計算精度，但 SAP B1 匯出到 Excel 後，Excel 可能套用：

- 一般格式：`180`
- SAP B1 數量格式：`180.000000`
- 原有 Excel 欄位格式：`180.00`
- 使用過 `FORMAT()` 的欄位：變成文字 `"180.00"`

因此畫面可能不一致。

建議統一使用 `CAST`，不要混用 `FORMAT`：

```sql
CAST(ROUND(T1.Quantity, 2) AS DECIMAL(19,2))
    AS [採購數量],

CAST(ROUND(ISNULL(T2.DeliveredQty, 0), 2) AS DECIMAL(19,2))
    AS [已交數量],

CAST(ROUND(ISNULL(T3.ReturnedQty, 0), 2) AS DECIMAL(19,2))
    AS [已退數量],

CAST(
    ROUND(
        ISNULL(T2.DeliveredQty, 0)
        - ISNULL(T3.ReturnedQty, 0),
        2
    )
    AS DECIMAL(19,2)
) AS [實收數量],

CAST(ROUND(T1.OpenQty, 2) AS DECIMAL(19,2))
    AS [未交數量],

CAST(ROUND(T1.Price, 4) AS DECIMAL(19,4))
    AS [採購單價],

CAST(
    ROUND(T1.OpenQty * T1.Price, 2)
    AS DECIMAL(19,2)
) AS [未交金額]
```

但要讓 Excel「畫面」完全一致，匯出後還是要設定 Excel 欄位格式：

- 採購數量～未交數量：數值、小數位數 `2`
- 採購單價：數值、小數位數 `4`
- 未交金額：數值、小數位數 `2`

另外，請重新匯出成一個新的 Excel 檔案，不要覆蓋舊檔。舊檔欄位可能保留先前 `FORMAT()` 產生的文字格式。

核心原則是：

```text
CAST／ROUND：確保資料仍是數字，可以計算
Excel 欄位格式：控制實際顯示幾位小數
FORMAT：強制顯示，但會變成文字
```
