### 1. AP貸項通知書 表身RPC1 列裡面有一個不含數量過帳 NoInvtryMv 我想寫SP 如果表身列有多個項目 如果有勾一個 就全部都要勾 如果沒有 則全部都不勾

來源：[S028-Q001](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q1>)；2026-07-27

**問題**

AP貸項通知書 表身RPC1 列裡面有一個不含數量過帳 NoInvtryMv 我想寫SP 

如果表身列有多個項目 如果有勾一個 就全部都要勾 如果沒有 則全部都不勾

**歷史回答**

可以在 `SBO_SP_TransactionNotification` 驗證：同一張 AP 貸項通知書的 `RPC1.NoInvtryMv` 必須全部一致，只要有些勾、有些沒勾，就禁止新增或更新。

AP 貸項通知書的 Object Type 是 `19`。以下為 SQL Server 版本：

```sql
IF @object_type = '19'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM RPC1
        WHERE DocEntry = CONVERT(INT, @list_of_cols_val_tab_del)
        GROUP BY DocEntry
        HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1
    )
    BEGIN
        SET @error = -19001
        SET @error_message = N'不含數量過帳必須全部勾選或全部不勾選，請檢查表身資料。'
    END
END
```

請把這段放在 `SBO_SP_TransactionNotification` 最後面的：

```sql
SELECT @error, @error_message
```

之前。

判斷邏輯是：

- 全部为 `Y`：允許過帳
- 全部为 `N`：允許過帳
- 同時存在 `Y` 與 `N`：禁止過帳並顯示錯誤

如果你的需求是「使用者只勾其中一列，系統自動幫其他列全部勾起來」，不建議在 `TransactionNotification` 裡直接 `UPDATE RPC1`，因為直接修改 SAP B1 系統資料表可能造成資料不一致，也不受 SAP 支援。這種自動連動應透過 SAP B1 Add-on/UI API 實作；SP 比較適合做上述的過帳驗證。

### 2. 對 我只是要資料驗證

對 我只是要資料驗證

-- AP 貸項通知書：表身「不含數量過帳」必須全部一致

SELECT @error, @error_message

### 3. SQL／程式碼調整與說明

來源：[S028-Q003](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q3>)；2026-07-27

**問題**

IF @object_type = '19'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM RPC1
        WHERE DocEntry = CONVERT(INT, @list_of_cols_val_tab_del)
        GROUP BY DocEntry
        HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1
    )
    BEGIN
        SET @error = -19001
        SET @error_message = N'不含數量過帳必須全部勾選或全部不勾選，請檢查表身資料。'
    END
END

可以給我這段的解析嗎

**歷史回答**

這段程式放在 SAP Business One 的 `SBO_SP_TransactionNotification` 中，用來驗證 AP 貸項通知書的所有表身列，其「不含數量過帳」是否一致。

```sql
IF @object_type = '19'
   AND @transaction_type IN ('A', 'U')
```

這是判斷執行時機：

- `@object_type = '19'`：目前處理的單據是 AP 貸項通知書。
- `@transaction_type = 'A'`：新增單據。
- `@transaction_type = 'U'`：更新單據。
- `IN ('A', 'U')`：只有新增或更新 AP 貸項通知書時才執行驗證。

---

```sql
IF EXISTS
(
    SELECT 1
    FROM RPC1
```

- `RPC1` 是 AP 貸項通知書的表身資料表。
- `IF EXISTS` 用來判斷括號內的查詢是否有找到資料。
- `SELECT 1` 只是用來判斷資料是否存在，數字 `1` 沒有其他特殊意義。

---

```sql
WHERE DocEntry = CONVERT(INT, @list_of_cols_val_tab_del)
```

只檢查目前正在新增或更新的那張 AP 貸項通知書。

- `DocEntry`：單據內部編號。
- `@list_of_cols_val_tab_del`：SAP 傳入目前單據的主鍵值。
- 這個參數是字串型別，所以用 `CONVERT(INT, ...)` 轉成整數後，再跟 `RPC1.DocEntry` 比較。

例如目前處理的單據 `DocEntry = 1234`，實際條件相當於：

```sql
WHERE DocEntry = 1234
```

---

```sql
GROUP BY DocEntry
```

把同一張單據的表身資料歸成一組，讓下一行可以針對整張單據判斷。

例如表身有三列：

| DocEntry | LineNum | NoInvtryMv |
|---:|---:|:---:|
| 1234 | 0 | Y |
| 1234 | 1 | Y |
| 1234 | 2 | N |

這三列會被視為同一組。

---

```sql
HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1
```

這一行是主要的驗證邏輯。

先看內層：

```sql
ISNULL(NoInvtryMv, 'N')
```

如果 `NoInvtryMv` 是 `NULL`，就將它視為 `N`：

- `Y`：有勾選「不含數量過帳」
- `N`：沒有勾選
- `NULL`：視為沒有勾選

接著：

```sql
DISTINCT ISNULL(NoInvtryMv, 'N')
```

取得不重複的值。

如果三列表身是：

```text
Y、Y、Y
```

不重複的值只有：

```text
Y
```

如果三列表身是：

```text
N、N、N
```

不重複的值只有：

```text
N
```

如果三列表身是：

```text
Y、Y、N
```

不重複的值有：

```text
Y、N
```

接著計算不同值的數量：

```sql
COUNT(DISTINCT ISNULL(NoInvtryMv, 'N'))
```

| 表身内容 | 不同值數量 | 結果 |
|---|---:|---|
| `Y、Y、Y` | 1 | 通過 |
| `N、N、N` | 1 | 通過 |
| `Y、Y、N` | 2 | 不通過 |
| `Y、N、N` | 2 | 不通過 |
| 只有一列 `Y` | 1 | 通過 |
| 只有一列 `N` | 1 | 通過 |

最後：

```sql
> 1
```

代表同一張單據同時存在兩種以上的值，也就是有些列勾選、有些列沒勾選。

---

```sql
BEGIN
    SET @error = -19001
    SET @error_message =
        N'不含數量過帳必須全部勾選或全部不勾選，請檢查表身資料。'
END
```

查到不一致的資料時，設定 SAP B1 的錯誤資訊：

- `@error = -19001`：自訂錯誤代碼；只要不是 `0`，SAP 就會阻止交易。
- `@error_message`：顯示給使用者看的錯誤訊息。
- 字串前面的 `N` 表示 Unicode 字串，避免中文出現亂碼。

整體邏輯可以簡化理解為：

```text
目前是新增或更新 AP 貸項通知書嗎？
    ↓ 是
取得目前單據的全部 RPC1 表身列
    ↓
NoInvtryMv 是否同時存在 Y 與 N？
    ↓ 是
回傳錯誤，阻止新增或更新
```

因此，這段只做資料驗證，不會自動修改任何表身資料。

### 4. HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1這段不懂

來源：[S028-Q004](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q4>)；2026-07-27

**問題**

HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1這段不懂

**歷史回答**

這行可以拆成三層理解：

```sql
HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1
```

它的意思是：

> 同一張單據的 `NoInvtryMv` 如果出現超過一種值，就判定為不一致。

### 第一層：處理空值

```sql
ISNULL(NoInvtryMv, 'N')
```

若欄位是 `NULL`，把它當成 `N`。

| 原始值 | 處理後 |
|---|---|
| `Y` | `Y` |
| `N` | `N` |
| `NULL` | `N` |

### 第二層：只保留不同的值

```sql
DISTINCT ISNULL(NoInvtryMv, 'N')
```

`DISTINCT` 是去除重複。

例如：

```text
原本：Y、Y、Y
去重：Y
```

```text
原本：N、N、N
去重：N
```

```text
原本：Y、Y、N
去重：Y、N
```

### 第三層：計算有幾種值

```sql
COUNT(DISTINCT ISNULL(NoInvtryMv, 'N'))
```

| 表身資料 | 去除重複後 | COUNT |
|---|---|---:|
| `Y、Y、Y` | `Y` | 1 |
| `N、N、N` | `N` | 1 |
| `Y、Y、N` | `Y、N` | 2 |
| `Y、N、N` | `Y、N` | 2 |

最後的：

```sql
> 1
```

就是判斷種類是否超過一種：

- `COUNT = 1`：全部相同，驗證通過
- `COUNT > 1`：同時有 `Y` 和 `N`，驗證失敗

所以整行可以用白話表示為：

```text
如果表身的「不含數量過帳」同時存在勾選和未勾選，就抓出這張單據。
```

`HAVING` 是在 `GROUP BY DocEntry` 分組完成後，針對整張單據的那一組表身資料進行判斷。

### 5. HAVING 的意思

來源：[S028-Q005](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q5>)；2026-07-27

**問題**

HAVING 的意思

**歷史回答**

`HAVING` 是用來篩選「分組後的結果」。

你前面有：

```sql
GROUP BY DocEntry
```

意思是把相同 `DocEntry` 的表身資料分成一組；接著 `HAVING` 再判斷這一組是否符合條件：

```sql
HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1
```

白話就是：

> 只留下 `NoInvtryMv` 出現超過一種值的單據。

### `WHERE` 和 `HAVING` 的差別

- `WHERE`：在分組前，篩選「每一筆資料」
- `HAVING`：在分組後，篩選「整個群組」

以這段為例：

```sql
SELECT DocEntry
FROM RPC1
WHERE DocEntry = 1234
GROUP BY DocEntry
HAVING COUNT(DISTINCT ISNULL(NoInvtryMv, 'N')) > 1
```

執行順序可理解成：

1. `WHERE DocEntry = 1234`  
   先取出單據 1234 的所有表身列。

2. `GROUP BY DocEntry`  
   將單據 1234 的表身列歸成一組。

3. `HAVING ... > 1`  
   判斷這一組是否同時存在 `Y` 和 `N`。

例如：

```text
DocEntry 1234：Y、Y、N
```

去除重複後是：

```text
Y、N
```

數量為 `2`，符合：

```sql
HAVING 2 > 1
```

所以這張單據會被查出來，接著觸發錯誤。

之所以不能寫成下面這樣：

```sql
WHERE COUNT(...) > 1
```

是因為 `COUNT()` 是分組完成後才能計算的彙總結果，因此需要使用 `HAVING`。

### 6. 那是放 POSTTransactionNotification 還是 TransactionNotification

來源：[S028-Q006](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q6>)；2026-07-27

**問題**

那是放 POSTTransactionNotification 還是 TransactionNotification

**歷史回答**

放在 `SBO_SP_TransactionNotification`。

因為你的需求是「資料驗證，若表身勾選不一致，就不允許單據過帳」。

- `SBO_SP_TransactionNotification`：交易完成前執行，可以回傳錯誤並阻止新增或更新。
- `SBO_SP_PostTransactionNotice`：交易完成後才執行，此時單據已經寫入，無法用 `@error` 阻止交易。

請放在 `SBO_SP_TransactionNotification` 裡，並且要位於最後這行之前：

```sql
SELECT @error, @error_message
```

結構大致如下：

```sql
ALTER PROCEDURE [dbo].[SBO_SP_TransactionNotification]
    @object_type NVARCHAR(30),
    @transaction_type NCHAR(1),
    @num_of_cols_in_key INT,
    @list_of_key_cols_tab_del NVARCHAR(255),
    @list_of_cols_val_tab_del NVARCHAR(255)
AS
BEGIN

    DECLARE @error INT
    DECLARE @error_message NVARCHAR(200)

    SELECT @error = 0
    SELECT @error_message = N'Ok'

    -- AP 貸項通知書資料驗證
    IF @object_type = '19'
       AND @transaction_type IN ('A', 'U')
    BEGIN
        IF EXISTS
        (
            SELECT 1
            FROM RPC1
            WHERE DocEntry =
                  CONVERT(INT, @list_of_cols_val_tab_del)
            GROUP BY DocEntry
            HAVING COUNT(
                DISTINCT ISNULL(NoInvtryMv, 'N')
            ) > 1
        )
        BEGIN
            SET @error = -19001
            SET @error_message =
                N'不含數量過帳必須全部勾選或全部不勾選，請檢查表身資料。'
        END
    END

    -- 必須放在所有驗證規則的最後
    SELECT @error, @error_message

END
```

因此結論是：

```text
需要擋單及顯示錯誤 → SBO_SP_TransactionNotification
交易完成後執行其他處理 → SBO_SP_PostTransactionNotice
```

### 7. 過了欸

來源：[S028-Q007](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q7>)；2026-07-27

**問題**

過了欸

**歷史回答**

如果「部分勾、部分沒勾」還是可以過帳，先確認資料庫實際存的值，以及 `@error` 是否被後面的程式重設。

先找剛才測試單據的 `DocEntry`，執行：

```sql
SELECT
    DocEntry,
    LineNum,
    ItemCode,
    NoInvtryMv
FROM RPC1
WHERE DocEntry = 你的DocEntry
ORDER BY LineNum
```

如果結果確實同時有 `Y`、`N`，建議把驗證改成更直白的寫法：

```sql
IF @object_type = '19'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM RPC1
        WHERE DocEntry = TRY_CONVERT(INT, @list_of_cols_val_tab_del)
          AND ISNULL(NoInvtryMv, 'N') = 'Y'
    )
    AND EXISTS
    (
        SELECT 1
        FROM RPC1
        WHERE DocEntry = TRY_CONVERT(INT, @list_of_cols_val_tab_del)
          AND ISNULL(NoInvtryMv, 'N') <> 'Y'
    )
    BEGIN
        SET @error = -19001
        SET @error_message =
            N'不含數量過帳必須全部勾選或全部不勾選，請檢查表身資料。'
    END
END
```

白話邏輯是：

- 找到至少一列 `Y`
- 同時又找到至少一列不是 `Y`
- 兩個條件都成立就擋單

另外務必檢查 SP 的後半段。在這段驗證之後，不能再有：

```sql
SET @error = 0
SET @error_message = N'Ok'
```

否則剛設定的錯誤會被清掉。最後只能回傳：

```sql
SELECT @error, @error_message
```

你也可以先放一個最簡單的測試，確認 Object Type 及 SP 確實有執行：

```sql
IF @object_type = '19'
   AND @transaction_type IN ('A', 'U')
BEGIN
    SET @error = -19099
    SET @error_message = N'AP 貸項通知書測試擋單'
END
```

如果這樣仍然能過帳，代表較可能是：

- 修改的不是目前公司資料庫內的 `SBO_SP_TransactionNotification`
- 程式碼放在 `SELECT @error, @error_message` 之後
- 後面的程式又把 `@error` 設回 `0`
- SP 中途有 `RETURN`，尚未執行到這段程式碼

### 8. 沒有成功卡到

來源：[S028-Q008](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q8>)；2026-07-27

**問題**

### 11. 還是應該是要post?

來源：[S028-Q011](<../../原始問答/S028_撰寫AP貸項通知書RPC1 SP.md#q11>)；2026-07-27

**問題**

還是應該是要post?

**歷史回答**

不是，資料驗證一定要放在 `SBO_SP_TransactionNotification`，不是 `SBO_SP_PostTransactionNotice`。

原因很明確：

- `TransactionNotification`：單據寫入交易中，可用 `@error` 阻止新增。
- `PostTransactionNotice`：單據已經成功寫入後才執行，無法擋單。

目前「沒有卡到」的原因，很可能是 `TransactionNotification` 執行時，直接查 `RPC1` 尚未取得預期值，或你測試的是尚未新增成功的新單據。可改成一次彙總判斷：

```sql
IF @object_type = '19'
   AND @transaction_type IN ('A', 'U')
BEGIN
    DECLARE @DocEntry INT
    DECLARE @CheckedCount INT
    DECLARE @UncheckedCount INT

    SET @DocEntry =
        TRY_CONVERT(INT, @list_of_cols_val_tab_del)

    SELECT
        @CheckedCount =
            SUM(
                CASE
                    WHEN ISNULL(NoInvtryMv, 'N') = 'Y'
                    THEN 1
                    ELSE 0
                END
            ),
        @UncheckedCount =
            SUM(
                CASE
                    WHEN ISNULL(NoInvtryMv, 'N') <> 'Y'
                    THEN 1
                    ELSE 0
                END
            )
    FROM dbo.RPC1
    WHERE DocEntry = @DocEntry

    IF ISNULL(@CheckedCount, 0) > 0
       AND ISNULL(@UncheckedCount, 0) > 0
    BEGIN
        SET @error = -19001
        SET @error_message =
            N'表身「不含數量過帳」必須全部勾選或全部不勾選。'
    END
END
```

必須放在 SP 最後這行之前：

```sql
SELECT @error, @error_message
```

但請先做一個關鍵測試：

```sql
IF @object_type = '19'
BEGIN
    SET @error = -19099
    SET @error_message =
        N'已進入 AP 貸項通知書 TransactionNotification'
END
```

如果這段都無法阻止正式新增 AP 貸項通知書，換成 `PostTransactionNotice` 也不會解決；這代表目前修改的不是 SAP 正在使用的公司資料庫 SP、程式沒有成功儲存，或者後面把 `@error` 清成 `0`。

`PostTransactionNotice` 最多只能在過帳後記錄問題，不能阻止該單據。

### 13. 我想要寫卡控。 如果我在sapb1裡面已經有自定義表格@FORM_NUM。 然後我想用這個表格做驗證。 我的收貨採購單的series 固定為11 所以我收貨採購單的自定義欄位 U_…

來源：[S029-Q001](<../../原始問答/S029_新增採購收貨單卡控.md#q1>)；2026-07-28

**問題**

我想要寫卡控。

如果我在sapb1裡面已經有自定義表格@FORM_NUM。

然後我想用這個表格做驗證。

我的收貨採購單的series 固定為11 

所以我收貨採購單的自定義欄位 U_TypeName 應該要按照我的自定義表格@FORM_NUM 的邏輯規則走 

我的@FORM_NUM 有兩個欄位 一個是U_SystemCode 另一個是U_CategoryName

series = U_SystemCode
U_TypeName  = U_CategoryName

**歷史回答**

可以透過 SAP Business One 的 `SBO_SP_TransactionNotification` 做卡控。

收貨採購單的物件類型是 `20`，主檔資料表是 `OPDN`。以下先以 SQL Server 版本為例：當 `Series = 11` 時，檢查 `U_TypeName` 是否符合 `@FORM_NUM` 中相同 `U_SystemCode` 對應的 `U_CategoryName`。

```sql
/* 收貨採購單：U_TypeName 必須符合 @FORM_NUM 設定 */
IF @object_type = '20'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM OPDN T0
        WHERE T0.DocEntry = CAST(@list_of_cols_val_tab_del AS INT)
          AND T0.Series = 11
          AND NOT EXISTS
          (
              SELECT 1
              FROM [@FORM_NUM] T1
              WHERE ISNULL(T1.U_SystemCode, '') =
                    CAST(T0.Series AS NVARCHAR(20))
                AND ISNULL(T1.U_CategoryName, '') =
                    ISNULL(T0.U_TypeName, '')
          )
    )
    BEGIN
        SET @error = -5001
        SET @error_message =
            N'收貨採購單的類型名稱不符合設定，請依照 @FORM_NUM 的類別名稱填寫。'
    END
END
```

這段邏輯等同於：

```text
OPDN.Series = @FORM_NUM.U_SystemCode
OPDN.U_TypeName = @FORM_NUM.U_CategoryName
```

因此，如果 `@FORM_NUM` 有以下資料：

| U_SystemCode | U_CategoryName |
|---|---|
| 11 | 原物料收貨 |

那麼 `Series = 11` 的收貨採購單，其 `U_TypeName` 就只能填寫「原物料收貨」。

如果你希望錯誤訊息直接告訴使用者「正確值應該填什麼」，可以改成下面這個版本：

```sql
/* 收貨採購單：顯示 @FORM_NUM 所設定的正確類型 */
IF @object_type = '20'
   AND @transaction_type IN ('A', 'U')
BEGIN
    DECLARE @ExpectedTypeName NVARCHAR(100)
    DECLARE @CurrentTypeName  NVARCHAR(100)

    SELECT
        @CurrentTypeName = ISNULL(T0.U_TypeName, '')
    FROM OPDN T0
    WHERE T0.DocEntry = CAST(@list_of_cols_val_tab_del AS INT)
      AND T0.Series = 11

    SELECT TOP 1
        @ExpectedTypeName = T1.U_CategoryName
    FROM [@FORM_NUM] T1
    WHERE T1.U_SystemCode = '11'

    IF EXISTS
    (
        SELECT 1
        FROM OPDN T0
        WHERE T0.DocEntry = CAST(@list_of_cols_val_tab_del AS INT)
          AND T0.Series = 11
    )
    AND
    (
        ISNULL(@ExpectedTypeName, '') = ''
        OR ISNULL(@CurrentTypeName, '') <> ISNULL(@ExpectedTypeName, '')
    )
    BEGIN
        SET @error = -5001

        IF ISNULL(@ExpectedTypeName, '') = ''
            SET @error_message =
                N'@FORM_NUM 尚未設定 SystemCode = 11 的類別名稱。'
        ELSE
            SET @error_message =
                N'類型名稱錯誤，Series 11 的 U_TypeName 應為：'
                + @ExpectedTypeName
    END
END
```

建議確認 `@FORM_NUM` 裡的 `U_SystemCode = '11'` 只有一筆，否則同一個 Series 可能會對應到多個類別。程式碼要放在 `SBO_SP_TransactionNotification` 最後的：

```sql
SELECT @error, @error_message
```

之前。

### 14. 也不能存成草稿

來源：[S029-Q002](<../../原始問答/S029_新增採購收貨單卡控.md#q2>)；2026-07-28

**問題**

也不能存成草稿

**歷史回答**

可以，草稿也要另外卡控。SAP B1 草稿的物件類型是 `112`、資料表是 `ODRF`；並以 `ODRF.ObjType = '20'` 判斷它是收貨採購單草稿。

把下面兩段都加入 `SBO_SP_TransactionNotification`：

```sql
/*==========================================================
  1. 正式收貨採購單
  Object Type = 20
==========================================================*/
IF @object_type = '20'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM OPDN T0
        WHERE T0.DocEntry = CAST(@list_of_cols_val_tab_del AS INT)
          AND T0.Series = 11
          AND NOT EXISTS
          (
              SELECT 1
              FROM [@FORM_NUM] T1
              WHERE ISNULL(T1.U_SystemCode, '') =
                    CAST(T0.Series AS NVARCHAR(20))
                AND ISNULL(T1.U_CategoryName, '') =
                    ISNULL(T0.U_TypeName, '')
          )
    )
    BEGIN
        SET @error = -5001
        SET @error_message =
            N'收貨採購單的類型名稱不符合 @FORM_NUM 設定，請確認 U_TypeName。'
    END
END


/*==========================================================
  2. 收貨採購單草稿
  Object Type = 112
  ODRF.ObjType = 20
==========================================================*/
IF @object_type = '112'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM ODRF T0
        WHERE T0.DocEntry = CAST(@list_of_cols_val_tab_del AS INT)
          AND T0.ObjType = '20'
          AND T0.Series = 11
          AND NOT EXISTS
          (
              SELECT 1
              FROM [@FORM_NUM] T1
              WHERE ISNULL(T1.U_SystemCode, '') =
                    CAST(T0.Series AS NVARCHAR(20))
                AND ISNULL(T1.U_CategoryName, '') =
                    ISNULL(T0.U_TypeName, '')
          )
    )
    BEGIN
        SET @error = -5002
        SET @error_message =
            N'收貨採購單草稿的類型名稱不符合 @FORM_NUM 設定，無法儲存草稿。'
    END
END
```

這樣的結果是：

- 正式新增或更新收貨採購單時會檢查。
- 儲存或更新收貨採購單草稿時也會檢查。
- 只有 `Series = 11` 才套用。
- `U_TypeName` 空白、填錯，或 `@FORM_NUM` 沒有對應設定，都無法儲存。
- 其他類型的文件草稿不受影響。

程式必須放在預存程序最後這行之前：

```sql
SELECT @error, @error_message
```
