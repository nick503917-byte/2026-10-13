### 1. OWOR U\_avgworkforce 的欄位 要帶入 U\_energy/ U\_workforce

來源：[S126-Q001](<../../原始問答/S126_更新 OWOR U_avgworkforce 欄位.md#q1>)；2026-09-02

**問題**

OWOR U\_avgworkforce 的欄位 要帶入 U\_energy/ U\_workforce

**歷史回答**

目前工作目錄只有兩個 CSS 檔，找不到 `OWOR` 相關程式或 SQL，無法直接修改。

請提供程式／SQL 檔案位置。預期公式會寫成：

```sql
U_avgworkforce = U_energy / NULLIF(U_workforce, 0)
```

`NULLIF` 可避免 `U_workforce = 0` 時發生除以零錯誤。

<a id="qa2"></a>

### 2. 我要寫在 OWOR U\_avgworkforce欄位裡面

來源：[S126-Q002](<../../原始問答/S126_更新 OWOR U_avgworkforce 欄位.md#q2>)；2026-09-02

**問題**

我要寫在 OWOR U\_avgworkforce欄位裡面

**歷史回答**

如果是 SAP Business One 的「格式化搜尋」，請把下面查詢指定到 `OWOR.U_avgworkforce` 欄位：

```sql
SELECT
    $[OWOR.U_energy.NUMBER] /
    NULLIF($[OWOR.U_workforce.NUMBER], 0)
```

設定自動重新整理，觸發欄位選擇 `U_energy` 與 `U_workforce`。如此 `U_avgworkforce` 就會帶入：

```text
U_energy ÷ U_workforce
```

當 `U_workforce` 為 0 時會回傳空值，避免除以零錯誤。

### 5. (1/OWOR.U\_energy)\OWOR.U\_Workforce 這樣嗎

來源：[S172-Q001](<../../原始問答/S172_確認 OWOR 能源人力公式.md#q1>)；2026-09-15

**問題**

(1/OWOR.U\_energy)\*OWOR.U\_Workforce 這樣嗎

**歷史回答**

對，如果你要計算「Workforce ÷ energy」，這樣寫是正確的：

```sql
(1 / OWOR.U_energy) * OWOR.U_Workforce
```

也可以直接寫成：

```sql
OWOR.U_Workforce / OWOR.U_energy
```

若用於 SQL，建議避免整數除法與除以零：

```sql
1.0 * OWOR.U_Workforce / NULLIF(OWOR.U_energy, 0)
```

### 9. 我要問的是 生產工單的優先順序的欄位 給我介紹

來源：[S172-Q005](<../../原始問答/S172_確認 OWOR 能源人力公式.md#q5>)；2026-09-15

**問題**

我要問的是 生產工單的優先順序的欄位 給我介紹

**歷史回答**

了解，你問的是 **SAP Business One 生產工單上的「優先順序（Priority）」欄位**，剛才我誤解了。

### 欄位用途

用來標示這張生產工單的重要程度，讓生管人員判斷哪些工單應優先處理。這是可手動設定的整數欄位，**預設值為 `100`，數字越小代表越優先，例如 `1` 表示最高優先順序**。[SAP 官方說明](https://learning.sap.com/courses/managing-logistics-in-sap-business-one/running-the-production-process-in-sap-business-one)

### 設定範例

公司可以自行訂定一致的分級規則，例如：

| 優先順序 | 使用情境 |
|---|---|
| 1 | 緊急插單、必須優先處理 |
| 10 | 急單、交期接近 |
| 50 | 比一般工單優先 |
| 100 | 一般工單，使用預設值 |

以上是管理範例，並非系統內建的固定分類。

### 查詢時的欄位

標準欄位名稱是 `Priority`，生產工單查詢可使用：

```sql
OWOR.Priority
```

依優先順序排列時使用升冪：

```sql
ORDER BY OWOR.Priority ASC
```

欄位名稱與預設值可參考 [SAP SDK 文件](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/SAPbobsCOM~ProductionOrders~Priority.html)。

實務上可搭配交期、缺料狀況與產能一起判斷；**填入優先順序本身，不代表已完成自動排程**。

### 10. 會有關於MRP嗎

來源：[S172-Q006](<../../原始問答/S172_確認 OWOR 能源人力公式.md#q6>)；2026-09-15

**問題**

會有關於MRP嗎

**歷史回答**

**如果你問「修改生產工單的優先順序，會不會影響 MRP？」——標準 SAP Business One 一般不會依這個欄位決定 MRP 的先後順序。**

兩者的用途如下：

| 項目 | 用途 |
|---|---|
| **工單優先順序 `Priority`** | 標示工單重要程度，供人員在揀貨、生產管理及未結清項目清單中參考 |
| **MRP（物料需求規劃）** | 根據庫存、供需數量、日期、BOM、前置時間與規劃參數，計算何時需要採購或生產多少 |

這個區分依據 SAP 對 [工單優先順序](https://learning.sap.com/courses/managing-logistics-in-sap-business-one/running-the-production-process-in-sap-business-one)及 [MRP 計算方式](https://help.sap.com/docs/SAP_BUSINESS_ONE/68a2e87fb29941b5bf959a184d9c6727/44e98a287851363de10000000a1553f6.html)的說明；官方文件未將 `Priority` 列為 MRP 計算參數。

**例如：**把某張工單從 `100` 改成 `1`，表示它更急，但不能因此預期 MRP 自動提早備料。若要讓 MRP 反映提前的需求，應調整工單相關需求日期，包括物料元件的開始日期，並重新執行 MRP。

若你們有加裝排程外掛或客製程式，則可能另外使用這個欄位。
