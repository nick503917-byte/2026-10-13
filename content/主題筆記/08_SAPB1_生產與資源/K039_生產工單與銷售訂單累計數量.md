# 生產工單與銷售訂單累計數量

[回總覽](../../00_閱讀入口.md)

工單卡控不能只檢查單張 PlannedQty，還需考慮同銷售來源累計工單量。同品號多列、取消工單與來源列對應是歷史討論指出的邊界情境。

### 2. 我想寫SP 關於 OWOR 當 LinlToObj = 17 會抓originaNum的單號與ordr 的 DocNum 想相同的單號。 然後OWOR的 PlannedQty 不能…

來源：[S035-Q002](<../../原始問答/S035_查找 OWOR 与 ORDR 关联.md#q2>)；2026-07-30

**問題**

我想寫SP 關於

OWOR 當 LinlToObj = 17 會抓originaNum的單號與ordr 的 DocNum 想相同的單號。

然後OWOR的 PlannedQty 不能大於 rdr1的同個項目主檔的銷售數量

**歷史回答**

可以放在 SQL Server 版的 `SBO_SP_TransactionNotification` 中。當新增或更新生產訂單時，如果 `OWOR.LinkToObj = 17`，就依 `OriginNum = ORDR.DocNum` 找銷售訂單，並將同品號的 `RDR1.Quantity` 加總後比較。

```sql
/* 生產訂單：計劃數量不可大於來源銷售訂單同品號的銷售數量 */
IF @object_type = '202'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM OWOR W
        INNER JOIN ORDR H
            ON H.DocNum = W.OriginNum
        WHERE W.DocEntry = CONVERT(INT, @list_of_cols_val_tab_del)
          AND W.LinkToObj = '17'
          AND W.PlannedQty >
              ISNULL
              (
                  (
                      SELECT SUM(L.Quantity)
                      FROM RDR1 L
                      WHERE L.DocEntry = H.DocEntry
                        AND L.ItemCode = W.ItemCode
                  ),
                  0
              )
    )
    BEGIN
        SET @error = -20201
        SET @error_message =
            N'生產訂單的計劃數量不可大於來源銷售訂單同品號的銷售數量。'
    END
END
```

關聯邏輯如下：

```sql
OWOR.OriginNum = ORDR.DocNum
ORDR.DocEntry  = RDR1.DocEntry
OWOR.ItemCode  = RDR1.ItemCode
```

這段使用 `SUM(RDR1.Quantity)`，所以同一張銷售訂單若同品號出現在多個列，會把數量加總後再比較。

更穩定的做法是，如果你們的 `OWOR` 有正確保存來源單據內碼，優先使用：

```sql
OWOR.OriginAbs = ORDR.DocEntry
```

因為 `DocEntry` 是系統內部唯一鍵；`DocNum` 可能因不同單據系列而重複。此時把 JOIN 改成：

```sql
INNER JOIN ORDR H
    ON H.DocEntry = W.OriginAbs
```

### 3. 如果我有不同張的生產訂單 但 連結同一張銷售訂單 這樣我的卡控會有問題嗎

來源：[S035-Q003](<../../原始問答/S035_查找 OWOR 与 ORDR 关联.md#q3>)；2026-07-30

**問題**

如果我有不同張的生產訂單 但 連結同一張銷售訂單 這樣我的卡控會有問題嗎

**歷史回答**

會有問題。前一版只檢查「目前這一張」生產訂單的 `PlannedQty`。

例如：

- 銷售訂單數量：100
- 生產訂單 A：60
- 生產訂單 B：60

A、B 各自都沒有超過 100，因此都會通過，但合計已經是 120。

應改成加總所有連結同一張銷售訂單、同品號且未取消的生產訂單：

```sql
/* 生產訂單累計計劃數量，不可超過來源銷售訂單數量 */
IF @object_type = '202'
   AND @transaction_type IN ('A', 'U')
BEGIN
    IF EXISTS
    (
        SELECT 1
        FROM OWOR W
        INNER JOIN ORDR H
            ON H.DocNum = W.OriginNum
        WHERE W.DocEntry = CONVERT(INT, @list_of_cols_val_tab_del)
          AND W.LinkToObj = '17'

          /* 所有連結相同銷售訂單及相同品號的生產數量 */
          AND
          (
              SELECT ISNULL(SUM(W2.PlannedQty), 0)
              FROM OWOR W2
              WHERE W2.LinkToObj = '17'
                AND W2.OriginNum = W.OriginNum
                AND W2.ItemCode  = W.ItemCode
                AND W2.Status <> 'C'
          )
          >
          (
              /* 銷售訂單相同品號的銷售數量 */
              SELECT ISNULL(SUM(L.Quantity), 0)
              FROM RDR1 L
              WHERE L.DocEntry = H.DocEntry
                AND L.ItemCode = W.ItemCode
          )
    )
    BEGIN
        SET @error = -20201
        SET @error_message =
            N'同一張銷售訂單、同品號的生產訂單累計計劃數量，不可大於銷售數量。'
    END
END
```

`W2.Status <> 'C'` 表示排除已取消的生產訂單，但已結案的生產訂單仍會納入累計，避免結案後又重新開生產訂單而超量。

如果 `OWOR.OriginAbs` 有正確保存銷售訂單的 `DocEntry`，建議改用它，避免不同號碼系列出現相同 `DocNum`：

```sql
INNER JOIN ORDR H
    ON H.DocEntry = W.OriginAbs
```

累計條件也改成：

```sql
AND W2.OriginAbs = W.OriginAbs
```

這會比使用 `OriginNum = DocNum` 更安全。

### 4. 這樣卡 幫我列出可能會出問題的情境

來源：[S035-Q004](<../../原始問答/S035_查找 OWOR 与 ORDR 关联.md#q4>)；2026-07-30

**問題**

這樣卡 幫我列出可能會出問題的情境

**歷史回答**

這種「同銷售訂單＋同品號，累計生產數量不得超過銷售數量」的卡控，以下情境可能出問題。

### 1. 銷售訂單同品號有多列

例如同一張訂單：

| 列號 | 品號 | 數量 | 交期 |
|---|---|---:|---|
| 0 | A001 | 50 | 8/1 |
| 1 | A001 | 50 | 8/15 |

目前用 `ItemCode` 加總，會視為銷售數量 100，無法區分生產訂單到底對應哪一列或哪個交期。

如果需要逐列管控，必須額外記錄 `RDR1.LineNum`。

---

### 2. 不同單據系列有相同 DocNum

如果用：

```sql
OWOR.OriginNum = ORDR.DocNum
```

不同系列可能存在相同的 `DocNum`，造成連到錯誤的銷售訂單，甚至讓銷售數量重複。

建議優先用：

```sql
OWOR.OriginAbs = ORDR.DocEntry
```

---

### 3. 生產訂單沒有直接從銷售訂單建立

使用者可能手動新增生產訂單，只在備註填寫銷售訂單號碼。這時：

```sql
LinkToObj <> '17'
```

卡控不會執行。

也有可能 `OriginNum` 或 `OriginAbs` 沒有值，導致完全沒有檢查。

---

### 4. 已取消與已結案生產訂單的計算方式

目前排除：

```sql
Status = 'C'
```

但已結案生產訂單仍依原始 `PlannedQty` 計算。

例如：

- 銷售數量：100
- 第一張生產訂單計劃 100，實際只完成 80，之後結案
- 想再建立一張生產訂單補做 20

如果仍以 `PlannedQty = 100` 累計，新單 20 會被擋住。

需要先決定卡控基準是：

- 累計原始計劃數量
- 累計完成數量
- 已結案用完成數量、未結案用計劃數量

第三種通常比較符合補產需求，例如：

```sql
SUM(
    CASE
        WHEN Status = 'L' THEN CmpltQty
        ELSE PlannedQty
    END
)
```

---

### 5. 生產訂單已發料或完成後又取消

若已經產出或發料，之後將生產訂單取消，因為卡控排除取消單，系統就會釋放其數量。

使用者可能再開新生產訂單，造成實際生產超量。

需要決定取消單是否真的完全不計，或有 `CmpltQty > 0` 時仍納入。

---

### 6. 修改銷售訂單數量

原本：

- 銷售數量：100
- 生產訂單累計：100

之後使用者把銷售訂單改成 80。若卡控只放在生產訂單，修改銷售訂單時不會阻擋，造成既有生產數量 100 大於銷售數量 80。

因此最好在 `ORDR` 更新時也反向檢查。

---

### 7. 取消銷售訂單或銷售訂單列

銷售訂單已連結生產訂單後，使用者可能：

- 取消整張銷售訂單
- 關閉銷售訂單
- 關閉其中一列
- 刪除尚未被鎖定的列

如果只卡生產訂單，不會處理這些後續變化。

---

### 8. 銷售訂單使用替代品號

例如銷售品號是 `FG-A`，實際生產使用 `FG-A-NEW`。

因為條件是：

```sql
OWOR.ItemCode = RDR1.ItemCode
```

系統找不到相同品號，銷售數量會被視為 0，生產訂單會被擋住。

如果公司允許替代品、客戶品號轉換或舊新料號切換，就需要額外的對照表。

---

### 9. 銷售單位與庫存單位不同

銷售訂單可能用「箱」，生產訂單用「個」。

例如：

- 銷售：10 箱
- 每箱：12 個
- 實際可生產：120 個

直接比較 `RDR1.Quantity = 10` 和 `OWOR.PlannedQty = 120`，就會錯誤擋單。

需要確認 `RDR1.Quantity` 在你們版本與設定下使用的單位，必要時換算成庫存單位數量。

---

### 10. 小數與四捨五入

例如：

- 銷售數量：10
- 三張生產訂單：3.3333、3.3333、3.3334

資料庫精度、畫面顯示精度和單位換算可能不同，造成畫面看起來相等，SP 卻判斷超量。

可以加入允許誤差，例如：

```sql
生產數量 > 銷售數量 + 0.000001
```

---

### 11. 公司允許合理超產

某些品項因良率或最小生產批量，必須允許超產，例如：

- 銷售數量：100
- 最小生產批量：110
- 或允許超產 5%

完全禁止超過銷售量會影響正常作業。

可以依品號或品項群組設定允許超產比例。

---

### 12. 不同倉庫、分公司或專案

同一張銷售訂單、同品號可能分別屬於：

- 不同倉庫
- 不同分公司
- 不同專案
- 不同交期
- 不同成本中心

目前只按銷售訂單與品號加總，會全部混在一起。若業務需要分開控制，就要把相關欄位加入條件。

---

### 13. 生產的是 BOM 母件，但銷售的是其他包裝品號

銷售訂單可能賣套裝品或虛擬品號，生產訂單則生產實際母件。兩邊 `ItemCode` 不同，現有邏輯無法對應。

---

### 14. 一張生產訂單供應多張銷售訂單

SAP 標準來源欄位通常只能表示一個來源。如果一張生產訂單數量同時供應多張銷售訂單，單靠 `OriginAbs` 無法正確分攤。

這類情況需要自訂分攤明細表，而不是只使用 `OWOR` 的來源欄位。

---

### 15. 同時新增造成競爭問題

兩位使用者可能幾乎同時建立生產訂單：

- 目前可生產數量剩 50
- 使用者 A 新增 40
- 使用者 B 同時新增 40

兩個交易在特定隔離層級下，都可能看到「尚未包含對方」的資料，因此同時通過，最後累計變成 80。

這是資料庫併發問題，單純 `EXISTS + SUM` 不一定能完全避免。

---

### 16. 匯入工具或外部系統資料不完整

使用 DTW、API、Service Layer 或外部 MES 建立生產訂單時，可能：

- 沒帶 `LinkToObj`
- 沒帶 `OriginAbs`
- 來源欄位格式不同
- 先建立單據，之後才補寫自訂欄位

SP 可能直接放行，或因找不到銷售訂單而錯誤擋單。

---

### 建議先確認的卡控規則

實作前最好明確定義：

1. 用 `OriginAbs/DocEntry`，不要只用 `OriginNum/DocNum`。
2. 是按銷售訂單＋品號加總，還是要精確到 `RDR1.LineNum`。
3. 已結案生產訂單使用 `PlannedQty` 還是 `CmpltQty`。
4. 已取消但曾經完成生產的訂單是否納入。
5. 是否允許超產比例或數量。
6. 銷售訂單減量、關閉或取消時是否反向卡控。
7. 是否存在單位換算、替代品號或一張生產訂單供應多張銷售訂單。

最容易遇到的實務問題通常是：**多張生產訂單累計、已結案後補產、銷售訂單減量、同品號多列，以及銷售/庫存單位不同。**
