**當時回答**

草稿在 SAP Business One 的 `Object Type` 是 `112`，資料表是 `ODRF`；再透過 `ODRF.ObjType` 判斷草稿原本是採購單、A/R 發票或銷售訂單。

可以把正式單據與草稿一起整理成 `DOC`，再統一驗證：

```sql
/* 採購單、A/R 發票、銷售訂單，以及其草稿 */
IF @transaction_type IN ('A', 'U')
AND @object_type IN ('22', '13', '17', '112')
BEGIN

    IF EXISTS
    (
        SELECT 1
        FROM
        (
            /* 8. 採購單 */
            SELECT
                T0.Series,
                T0.U_TypeName,
                T0.U_ChangeType,
                T0.U_ChangeReason
            FROM OPOR T0
            WHERE @object_type = '22'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 9. A/R 發票 */
            SELECT
                T0.Series,
                T0.U_TypeName,
                T0.U_ChangeType,
                T0.U_ChangeReason
            FROM OINV T0
            WHERE @object_type = '13'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 11. 銷售訂單 */
            SELECT
                T0.Series,
                T0.U_TypeName,
                T0.U_ChangeType,
                T0.U_ChangeReason
            FROM ORDR T0
            WHERE @object_type = '17'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 草稿：採購單、A/R 發票、銷售訂單 */
            SELECT
                T0.Series,
                T0.U_TypeName,
                T0.U_ChangeType,
                T0.U_ChangeReason
            FROM ODRF T0
            WHERE @object_type = '112'
              AND CONVERT(NVARCHAR(20), T0.ObjType)
                  IN ('22', '13', '17')
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)
        ) DOC
        WHERE NOT EXISTS
        (
            SELECT 1
            FROM [@FORM_NUM] UDO
            WHERE UDO.U_SystemCode =
                  CAST(DOC.Series AS NVARCHAR(20))
              AND ISNULL(UDO.U_CategoryName, '') =
                  ISNULL(DOC.U_TypeName, '')
              AND ISNULL(UDO.U_ChangeType, '') =
                  ISNULL(DOC.U_ChangeType, '')
              AND ISNULL(UDO.U_ChangeReason, '') =
                  ISNULL(DOC.U_ChangeReason, '')
        )
    )
    BEGIN
        SET @error = 2008;
        SET @error_message =
            N'類別名稱、異動區分或異動原因與該單據系列別設定不符，請重新確認。';
    END;

END;
```

重點是：

- 正式單據：
  - `22` → `OPOR`
  - `13` → `OINV`
  - `17` → `ORDR`
- 草稿一律是：
  - `@object_type = '112'`
  - Table：`ODRF`
  - `ODRF.ObjType` 才是草稿預計建立的正式單據類型。
- `ISNULL(..., '')` 可讓空值也能正常比對；否則 SQL Server 中 `NULL = NULL` 不會成立。
- 使用 `TRY_CAST` 可避免傳入值無法轉成整數時直接讓 Transaction Notification 發生轉型錯誤。

## S133-Q002｜我只要 TYPENAME

**你的提問**

**當時回答**

如果只要卡 `U_TypeName`，把 `U_ChangeType`、`U_ChangeReason` 的比對拿掉即可：

```sql
IF @transaction_type IN ('A', 'U')
AND @object_type IN ('22', '13', '17', '112')
BEGIN

    IF EXISTS
    (
        SELECT 1
        FROM
        (
            /* 採購單 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM OPOR T0
            WHERE @object_type = '22'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* A/R 發票 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM OINV T0
            WHERE @object_type = '13'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 銷售訂單 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM ORDR T0
            WHERE @object_type = '17'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 草稿 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM ODRF T0
            WHERE @object_type = '112'
              AND CONVERT(NVARCHAR(20), T0.ObjType)
                  IN ('22', '13', '17')
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)
        ) DOC
        WHERE NOT EXISTS
        (
            SELECT 1
            FROM [@FORM_NUM] UDO
            WHERE UDO.U_SystemCode =
                  CAST(DOC.Series AS NVARCHAR(20))
              AND ISNULL(UDO.U_CategoryName, '') =
                  ISNULL(DOC.U_TypeName, '')
        )
    )
    BEGIN
        SET @error = 2008;
        SET @error_message =
            N'類別名稱與該單據系列別設定不符，請重新確認。';
    END;

END;
```

核心條件只剩：

```sql
WHERE UDO.U_SystemCode = CAST(DOC.Series AS NVARCHAR(20))
  AND ISNULL(UDO.U_CategoryName, '') =
      ISNULL(DOC.U_TypeName, '')
```

## S133-Q003｜給我完整的

日期：2026-09-04

**你的提問**

給我完整的

**當時回答**

以下是可直接放進 `SBO_SP_TransactionNotification` 的完整卡控，只檢查 `U_TypeName`，並包含採購單、A/R 發票、銷售訂單及草稿：

```sql
/* =========================================================
   單據系列別與類別名稱卡控
   正式單據：
       22  採購單      OPOR
       13  A/R 發票    OINV
       17  銷售訂單    ORDR

   草稿：
       112 草稿        ODRF
   ========================================================= */

IF @error = 0
   AND @transaction_type IN ('A', 'U')
   AND @object_type IN ('22', '13', '17', '112')
BEGIN

    IF EXISTS
    (
        SELECT 1
        FROM
        (
            /* 1. 採購單 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM OPOR T0
            WHERE @object_type = '22'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 2. A/R 發票 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM OINV T0
            WHERE @object_type = '13'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 3. 銷售訂單 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM ORDR T0
            WHERE @object_type = '17'
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

            UNION ALL

            /* 4. 採購單、A/R 發票、銷售訂單草稿 */
            SELECT
                T0.Series,
                T0.U_TypeName
            FROM ODRF T0
            WHERE @object_type = '112'
              AND CONVERT(NVARCHAR(20), T0.ObjType)
                  IN ('22', '13', '17')
              AND T0.DocEntry =
                  TRY_CAST(@list_of_cols_val_tab_del AS INT)

        ) DOC
        WHERE NOT EXISTS
        (
            SELECT 1
            FROM [@FORM_NUM] UDO
            WHERE UDO.U_SystemCode =
                  CONVERT(NVARCHAR(20), DOC.Series)
              AND ISNULL(UDO.U_CategoryName, '') =
                  ISNULL(DOC.U_TypeName, '')
        )
    )
    BEGIN
        SET @error = 2008;
        SET @error_message =
            N'類別名稱與該單據系列別設定不符，請重新確認。';
    END;

END;
```

放置位置是在 `SBO_SP_TransactionNotification` 最後這段之前：

```sql
SELECT @error, @error_message;
```

這版只會比對：

```sql
UDO.U_SystemCode = 單據 Series
UDO.U_CategoryName = 單據 U_TypeName
```

不會再檢查 `U_ChangeType` 和 `U_ChangeReason`。
