## S068-Q001｜未結採購單 查詢報表 我想要未結採購單然後跟交貨單做 LEFT JOIN 未結採購單做核心，

日期：2026-08-11

**你的提問**

未結採購單 查詢報表

我想要未結採購單然後跟交貨單做 LEFT JOIN 
未結採購單做核心，

**當時回答**

可以，查詢邏輯會是：

```sql
SELECT
    PO.*,
    DN.*
FROM 未結採購單 AS PO
LEFT JOIN 交貨單 AS DN
    ON DN.採購單號 = PO.採購單號
   AND DN.採購項次 = PO.採購項次
WHERE PO.未交數量 > 0;
```

重點是把「未結採購單」放在 `FROM`，交貨單放在 `LEFT JOIN`，如此即使尚無任何交貨紀錄，採購單仍會出現在報表中。

- 交貨單的表頭、明細資料表名稱
- 兩邊的關聯鍵（通常是採購單號＋項次）
- 「未結」的判斷方式，例如 `訂購量 > 已交量` 或狀態欄位

## S068-Q002｜SAPB1 的我記得是OPOR

日期：2026-08-11

**你的提問**

SAPB1 的我記得是OPOR

**當時回答**

對，SAP Business One：

- `OPOR`：採購單表頭
- `POR1`：採購單明細
- `OPDN`：收貨採購單表頭
- `PDN1`：收貨採購單明細

採購流程中的「交貨／收貨單」通常是 `OPDN/PDN1`；`ODLN/DLN1` 是銷售交貨單，不適合接採購單。

以未結採購明細為核心，可這樣寫：

```sql
SELECT
    PO.DocEntry                        AS 採購單內碼,
    PO.DocNum                          AS 採購單號,
    PO.DocDate                         AS 採購日期,
    PO.DocDueDate                      AS 採購到期日,
    PO.CardCode                        AS 供應商代碼,
    PO.CardName                        AS 供應商名稱,

    POL.LineNum + 1                    AS 採購項次,
    POL.ItemCode                       AS 品號,
    POL.Dscription                     AS 品名,
    POL.Quantity                       AS 採購數量,
    POL.OpenQty                        AS 未交數量,
    POL.Price                          AS 單價,
    POL.WhsCode                        AS 倉庫代碼,

    GRPO.DocNum                        AS 收貨單號,
    GRPO.DocDate                       AS 收貨日期,
    GRPO.NumAtCard                     AS 廠商交貨單號,
    GRPO_LINE.Quantity                 AS 本次收貨數量

FROM OPOR PO

INNER JOIN POR1 POL
    ON POL.DocEntry = PO.DocEntry

LEFT JOIN (
    PDN1 GRPO_LINE
    INNER JOIN OPDN GRPO
        ON GRPO.DocEntry = GRPO_LINE.DocEntry
       AND GRPO.CANCELED = 'N'
)
    ON GRPO_LINE.BaseType  = 22
   AND GRPO_LINE.BaseEntry = POL.DocEntry
   AND GRPO_LINE.BaseLine  = POL.LineNum

WHERE PO.CANCELED = 'N'
  AND POL.LineStatus = 'O'
  AND POL.OpenQty > 0

ORDER BY
    PO.DocNum,
    POL.LineNum,
    GRPO.DocDate,
    GRPO.DocNum;
```

關聯邏輯是：

```text
OPOR.DocEntry = POR1.DocEntry

PDN1.BaseType  = 22
PDN1.BaseEntry = POR1.DocEntry
PDN1.BaseLine  = POR1.LineNum
```

其中 `22` 是採購單的物件類型。

這份查詢會保留所有未結採購明細：

- 尚未收過貨：收貨單欄位為 `NULL`
- 部分收貨：顯示相關收貨單，`POR1.OpenQty` 顯示剩餘數量
- 同一採購項次分批收貨：會產生多列，每張收貨單一列

SAP 官方資料表說明：[OPDN—Goods Receipt PO](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/OPDN.html)、[PDN1—Goods Receipt PO Rows](https://help.sap.com/doc/089315d8d0f8475a9fc84fb919b501a3/10.0/en-US/SDKHelp/pdn1.html)。

## S068-Q004｜會讓沒有收貨單的未結採購項目被排除， 這句不懂

日期：2026-08-11

**你的提問**

會讓沒有收貨單的未結採購項目被排除， 這句不懂

**當時回答**

因為沒有收貨單時，`T3` 的所有欄位都會是 `NULL`。

假設有兩筆未結採購單：

| 採購單 | 收貨單 | T3.CANCELED |
|---|---|---|
| PO001 | GR001 | N |
| PO002 | 尚未收貨 | NULL |

如果把條件寫在 `WHERE`：

```sql
WHERE T3.CANCELED = 'N'
```

資料庫會檢查：

```text
PO001：N = N       → 成立，保留
PO002：NULL = N    → 不成立，排除
```

所以原本應該顯示的 `PO002`，會因為尚無收貨單而消失。此時效果就接近 `INNER JOIN`。

正確方式是放在 `LEFT JOIN`：

```sql
LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry
   AND T3.CANCELED = 'N'
```

意思是：「只連接未取消的收貨單；即使連不到，左邊的未結採購單仍然保留。」

若一定要寫在 `WHERE`，則必須允許 `NULL`：

```sql
WHERE (T3.CANCELED = 'N' OR T3.DocEntry IS NULL)
```

不過 SAP B1 查詢通常直接把條件寫在 `LEFT JOIN ... ON` 裡最清楚。

## S068-Q005｜我不能直接抓採購單是未結就好嗎

日期：2026-08-11

**你的提問**

我不能直接抓採購單是未結就好嗎

**當時回答**

可以，完全可以。若你的目的只是抓「目前未結的採購單明細」，直接判斷 `POR1` 就好，不需要用收貨單判斷未結。

```sql
SELECT
    T0.DocNum        AS '採購單號',
    T0.DocDate       AS '採購日期',
    T0.CardCode      AS '供應商代碼',
    T0.CardName      AS '供應商名稱',
    T1.LineNum + 1   AS '項次',
    T1.ItemCode      AS '品號',
    T1.Dscription    AS '品名',
    T1.Quantity      AS '採購數量',
    T1.OpenQty       AS '未交數量'
FROM OPOR T0
INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry
WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0
ORDER BY T0.DocNum, T1.LineNum
```

核心條件是：

```sql
T1.LineStatus = 'O'
```

代表採購單明細尚未結清。`T1.OpenQty > 0` 是再確認仍有未交數量。

如果還要顯示已經產生的收貨單，再單純加上：

```sql
LEFT JOIN PDN1 T2
    ON T2.BaseType  = 22
   AND T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry
```

然後原本的未結條件保持不變：

```sql
WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0
```

也就是：

- 是否未結：由 `POR1.LineStatus/OpenQty` 判斷
- 收貨單：只是拿來補充顯示
- 收貨單不存在：未結採購項目仍然會顯示

這正是「未結採購單為核心，收貨單 LEFT JOIN」的做法。

## S068-Q006｜如果我想 退回數量

日期：2026-08-11

**你的提問**

如果我想 退回數量

**當時回答**

如果要抓「採購收貨後的退貨數量」，SAP B1 使用：

- `ORPD`：採購退貨表頭（Goods Return）
- `RPD1`：採購退貨明細
- `BaseType = 20`：來源是收貨採購單 `OPDN/PDN1`

接法是：

```sql
LEFT JOIN PDN1 T2
    ON T2.BaseType  = 22
   AND T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry

LEFT JOIN RPD1 T4
    ON T4.BaseType  = 20
   AND T4.BaseEntry = T2.DocEntry
   AND T4.BaseLine  = T2.LineNum

LEFT JOIN ORPD T5
    ON T5.DocEntry = T4.DocEntry
```

在 `SELECT` 加入：

```sql
T3.DocNum AS '收貨單號',
T2.Quantity AS '收貨數量',

T5.DocNum AS '退貨單號',
CASE
    WHEN T5.CANCELED = 'N' THEN T4.Quantity
    ELSE 0
END AS '退回數量'
```

完整關聯流程：

```text
採購單 OPOR/POR1
       ↓ BaseType = 22
收貨單 OPDN/PDN1
       ↓ BaseType = 20
退貨單 ORPD/RPD1
```

如果同一採購項次有多張收貨單或退貨單，查詢會顯示多列。若報表只想顯示「每個採購項次一列」，退回數量需要彙總：

```sql
SUM(
    CASE
        WHEN T5.CANCELED = 'N' THEN T4.Quantity
        ELSE 0
    END
) AS '退回數量'
```

但使用 `SUM()` 後，其他欄位必須搭配 `GROUP BY`。另外，`POR1.OpenQty` 是否因退貨而重新開啟，會受到 SAP B1「退貨時重新開啟基礎文件」設定影響；若要看實際退貨歷史，仍以 `RPD1.Quantity` 為準。

## S068-Q007｜好 那你給我 各別兩種模式 有加總跟沒有加總

日期：2026-08-11

**你的提問**

好 那你給我 各別兩種模式 有加總跟沒有加總

**當時回答**

下面分成兩種：明細模式會列出每張收貨／退貨單；加總模式則每個採購項次只顯示一列。

## 1. 沒有加總：逐張收貨單、退貨單顯示

```sql
SELECT
    T0.DocNum                    AS '採購單號',
    T0.DocDate                   AS '採購日期',
    T0.DocDueDate                AS '採購到期日',
    T0.CardCode                  AS '供應商代碼',
    T0.CardName                  AS '供應商名稱',

    T1.LineNum + 1               AS '採購項次',
    T1.ItemCode                  AS '品號',
    T1.Dscription                AS '品名',
    T1.Quantity                  AS '採購數量',
    T1.OpenQty                   AS '目前未結數量',
    T1.WhsCode                   AS '倉庫',

    T3.DocNum                    AS '收貨單號',
    T3.DocDate                   AS '收貨日期',
    T3.NumAtCard                 AS '廠商交貨單號',
    ISNULL(T2.Quantity, 0)       AS '收貨數量',

    T5.DocNum                    AS '退貨單號',
    T5.DocDate                   AS '退貨日期',
    ISNULL(T4.Quantity, 0)       AS '退回數量'

FROM OPOR T0

INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry

LEFT JOIN PDN1 T2
    ON T2.BaseType  = 22
   AND T2.BaseEntry = T1.DocEntry
   AND T2.BaseLine  = T1.LineNum

LEFT JOIN OPDN T3
    ON T3.DocEntry = T2.DocEntry

LEFT JOIN RPD1 T4
    ON T4.BaseType  = 20
   AND T4.BaseEntry = T2.DocEntry
   AND T4.BaseLine  = T2.LineNum

LEFT JOIN ORPD T5
    ON T5.DocEntry = T4.DocEntry

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

  -- 排除取消的收貨單，但保留完全沒有收貨單的採購項目
  AND (T3.CANCELED = 'N' OR T2.DocEntry IS NULL)

  -- 排除取消的退貨單，但保留完全沒有退貨單的收貨項目
  AND (T5.CANCELED = 'N' OR T4.DocEntry IS NULL)

ORDER BY
    T0.DocNum,
    T1.LineNum,
    T3.DocDate,
    T3.DocNum,
    T5.DocDate,
    T5.DocNum
```

這個模式可能出現：

```text
PO001 第1項 → 收貨單 GR001 → 退貨單 RT001
PO001 第1項 → 收貨單 GR002 → 無退貨
```

## 2. 有加總：每個採購項次一列

這個版本分開計算收貨量與退貨量，避免同一張收貨單有多張退貨單時，把收貨數量重複加總。

```sql
SELECT
    T0.DocNum                    AS '採購單號',
    T0.DocDate                   AS '採購日期',
    T0.DocDueDate                AS '採購到期日',
    T0.CardCode                  AS '供應商代碼',
    T0.CardName                  AS '供應商名稱',

    T1.LineNum + 1               AS '採購項次',
    T1.ItemCode                  AS '品號',
    T1.Dscription                AS '品名',
    T1.Quantity                  AS '採購數量',
    T1.OpenQty                   AS '目前未結數量',
    T1.WhsCode                   AS '倉庫',

    ISNULL((
        SELECT SUM(PDN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0) AS '累計收貨數量',

    ISNULL((
        SELECT SUM(RTN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        INNER JOIN RPD1 RTN
            ON RTN.BaseType  = 20
           AND RTN.BaseEntry = PDN.DocEntry
           AND RTN.BaseLine  = PDN.LineNum
        INNER JOIN ORPD GR_RETURN
            ON GR_RETURN.DocEntry = RTN.DocEntry
           AND GR_RETURN.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0) AS '累計退回數量',

    ISNULL((
        SELECT SUM(PDN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0)
    -
    ISNULL((
        SELECT SUM(RTN.Quantity)
        FROM PDN1 PDN
        INNER JOIN OPDN GR
            ON GR.DocEntry = PDN.DocEntry
           AND GR.CANCELED = 'N'
        INNER JOIN RPD1 RTN
            ON RTN.BaseType  = 20
           AND RTN.BaseEntry = PDN.DocEntry
           AND RTN.BaseLine  = PDN.LineNum
        INNER JOIN ORPD GR_RETURN
            ON GR_RETURN.DocEntry = RTN.DocEntry
           AND GR_RETURN.CANCELED = 'N'
        WHERE PDN.BaseType  = 22
          AND PDN.BaseEntry = T1.DocEntry
          AND PDN.BaseLine  = T1.LineNum
    ), 0) AS '收貨淨額數量'

FROM OPOR T0

INNER JOIN POR1 T1
    ON T1.DocEntry = T0.DocEntry

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

ORDER BY
    T0.DocNum,
    T1.LineNum
```

欄位意義：

```text
累計收貨數量 = 所有未取消的收貨採購單數量
累計退回數量 = 所有未取消的採購退貨數量
收貨淨額數量 = 累計收貨數量 − 累計退回數量
目前未結數量 = SAP POR1.OpenQty
```

`目前未結數量` 建議直接採用 SAP 的 `POR1.OpenQty`；不要自行用「採購量－收貨＋退貨」取代，因為手動關閉與「退貨後是否重新開啟基礎文件」設定都可能影響 SAP 的未結數量。

## S068-Q014｜為甚麼會有這麼多小數位後的數字

日期：2026-08-12

**你的提問**

# Files mentioned by the user:

## codex-clipboard-39987e9b-80cc-4813-b00e-f97d3705bf58.png: C:/Users/nick_yeh/AppData/Local/Temp/codex-clipboard-39987e9b-80cc-4813-b00e-f97d3705bf58.png

## My request:
為甚麼會有這麼多小數位後的數字

[原對話含圖片，本文未嵌入圖片]

**當時回答**

因為 SAP B1 的數量、價格欄位通常是 `DECIMAL(19,6)`，查詢結果會依資料庫精度顯示 6 位小數，例如：

```text
2000.000000
1.890000
```

這不是計算錯誤，只是顯示格式。可以在 `SELECT` 使用 `CAST` 控制小數位數。

建議格式：

- 數量：2 位小數
- 單價：4 位小數
- 金額：2 位小數

```sql
CAST(T1.Quantity AS DECIMAL(19,2)) AS [採購數量],

CAST(ISNULL(T2.已交數量, 0)
     AS DECIMAL(19,2))             AS [已交數量],

CAST(ISNULL(T3.已退數量, 0)
     AS DECIMAL(19,2))             AS [已退數量],

CAST(
    ISNULL(T2.已交數量, 0)
    - ISNULL(T3.已退數量, 0)
    AS DECIMAL(19,2)
)                                  AS [實收數量],

CAST(T1.OpenQty AS DECIMAL(19,2))  AS [未交數量],

CAST(T1.Price AS DECIMAL(19,4))    AS [採購單價],

CAST(
    T1.OpenQty * T1.Price
    AS DECIMAL(19,2)
)                                  AS [未交金額]
```

結果會變成：

```text
採購數量：2,000.00
採購單價：1.8900
未交金額：3,780.00
```

如果數量確定只能是整數，例如全部都是 `PCS`，可以改為零位小數：

```sql
CAST(T1.Quantity AS DECIMAL(19,0)) AS [採購數量]
```

不過若還有公斤、米等可能出現小數的單位，建議數量保留兩位：

```sql
DECIMAL(19,2)
```

不要使用 `FORMAT()`，因為它會把數字轉成文字，之後在 Excel 排序、加總可能不方便；`CAST(... AS DECIMAL)` 能維持數值格式。

        ISNULL(T2.DeliveredQty, 0)
        AS DECIMAL(19,2)
    )                                            AS [已交數量],

    CAST(
        ISNULL(T3.ReturnedQty, 0)

    CAST(
        T1.OpenQty * T1.Price
        AS DECIMAL(19,2)
    )                                            AS [未交金額]

    ON T1.DocEntry = T0.DocEntry

/* 已交數量：未取消的收貨採購單 */

        A.BaseEntry,
        A.BaseLine,
        SUM(A.Quantity) AS DeliveredQty

        A.BaseEntry,

    INNER JOIN OPDN B
        ON B.DocEntry = A.DocEntry
       AND B.CANCELED = 'N'

    INNER JOIN RPD1 C
        ON C.BaseType  = 20
       AND C.BaseEntry = A.DocEntry
       AND C.BaseLine  = A.LineNum

    INNER JOIN ORPD D
        ON D.DocEntry = C.DocEntry

    WHERE A.BaseType = 22

    GROUP BY
        A.BaseEntry,
        A.BaseLine
) T3
    ON T3.BaseEntry = T1.DocEntry
   AND T3.BaseLine  = T1.LineNum

WHERE T0.CANCELED = 'N'
  AND T1.LineStatus = 'O'
  AND T1.OpenQty > 0

ORDER BY
    T1.ShipDate,
    T0.DocNum,
    T1.LineNum

## S068-Q017｜還是一樣

日期：2026-08-12

**你的提問**

還是一樣

**當時回答**

對，因為 SAP B1 查詢結果視窗會依「查詢中的小數位數」顯示，可能忽略 SQL 的 `DECIMAL(19,2)` 顯示精度。前面的 `CAST` 只能限制資料精度，不能保證 SAP B1 畫面只顯示兩位。

有兩種處理方式。

### 方法一：修改 SAP B1 顯示設定（建議）

進入：

```text
管理
→ 系統初始化
→ 一般設定
→ 顯示
→ 小數位數
→ 查詢中的小數位數（Decimals in Query）
```

建議設定：

```text
數量：2
價格：4
金額：2
查詢中的小數位數：2
```

修改後重新登入 SAP B1。如果仍然沒變，檢查該使用者是否套用了獨立的「使用者預設值」，因為它可能覆蓋公司的一般設定。SAP 官方確認查詢計算欄位的顯示位數受這項設定控制：[General Settings: Display Tab](https://help.sap.com/docs/SAP_BUSINESS_ONE/68a2e87fb29941b5bf959a184d9c6727/4506b85a7d720487e10000000a155369.html)。

### 方法二：SQL 強制顯示位數

如果不能修改 SAP 設定，就用 `FORMAT()` 強制轉成文字：

```sql
FORMAT(T1.Quantity, 'N2')                       AS [採購數量],
FORMAT(ISNULL(T2.DeliveredQty, 0), 'N2')        AS [已交數量],
FORMAT(ISNULL(T3.ReturnedQty, 0), 'N2')         AS [已退數量],

FORMAT(
    ISNULL(T2.DeliveredQty, 0)
    - ISNULL(T3.ReturnedQty, 0),
    'N2'
)                                                AS [實收數量],

FORMAT(T1.OpenQty, 'N2')                         AS [未交數量],
FORMAT(T1.Price, 'N4')                           AS [採購單價],
FORMAT(T1.OpenQty * T1.Price, 'N2')              AS [未交金額]
```

結果會顯示成：

```text
採購數量    1,698.00
已交數量      180.00
採購單價       35.0000
未交金額   59,430.00
```

但 `FORMAT()` 會把結果轉成文字，匯出 Excel 後可能需要再轉回數字。因此，能調整 SAP B1 的「查詢中的小數位數」時，優先使用方法一。

## S068-Q020｜為甚麼匯出EXCEL 小數點會不一致

日期：2026-08-12

**你的提問**

為甚麼匯出EXCEL 小數點會不一致

**當時回答**

因為 Excel 的「數值」與「顯示格式」是兩件事。

例如下面三個值在 Excel 裡其實相同：

```text
180
180.00
180.000000
```

SQL 的 `CAST(... AS DECIMAL(19,2))` 可以控制計算精度，但 SAP B1 匯出到 Excel 後，Excel 可能套用：

- 一般格式：`180`
- SAP B1 數量格式：`180.000000`
- 原有 Excel 欄位格式：`180.00`
- 使用過 `FORMAT()` 的欄位：變成文字 `"180.00"`

因此畫面可能不一致。

建議統一使用 `CAST`，不要混用 `FORMAT`：

```sql
CAST(ROUND(T1.Quantity, 2) AS DECIMAL(19,2))
    AS [採購數量],

CAST(ROUND(ISNULL(T2.DeliveredQty, 0), 2) AS DECIMAL(19,2))
    AS [已交數量],

CAST(ROUND(ISNULL(T3.ReturnedQty, 0), 2) AS DECIMAL(19,2))
    AS [已退數量],

CAST(
    ROUND(
        ISNULL(T2.DeliveredQty, 0)
        - ISNULL(T3.ReturnedQty, 0),
        2
    )
    AS DECIMAL(19,2)
) AS [實收數量],

CAST(ROUND(T1.OpenQty, 2) AS DECIMAL(19,2))
    AS [未交數量],

CAST(ROUND(T1.Price, 4) AS DECIMAL(19,4))
    AS [採購單價],

CAST(
    ROUND(T1.OpenQty * T1.Price, 2)
    AS DECIMAL(19,2)
) AS [未交金額]
```

但要讓 Excel「畫面」完全一致，匯出後還是要設定 Excel 欄位格式：

- 採購數量～未交數量：數值、小數位數 `2`
- 採購單價：數值、小數位數 `4`
- 未交金額：數值、小數位數 `2`

另外，請重新匯出成一個新的 Excel 檔案，不要覆蓋舊檔。舊檔欄位可能保留先前 `FORMAT()` 產生的文字格式。

核心原則是：

```text
CAST／ROUND：確保資料仍是數字，可以計算
Excel 欄位格式：控制實際顯示幾位小數
FORMAT：強制顯示，但會變成文字
```
